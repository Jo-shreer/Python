# 14. ThreadPoolExecutor

`ThreadPoolExecutor` is a higher-level API for managing worker threads.

```python
from concurrent.futures import ThreadPoolExecutor
def task(number):
    return number * 2

with ThreadPoolExecutor(max_workers=3) as executor:
    futures = [
        executor.submit(task, number)
        for number in range(5)
    ]
    results = [
        future.result()
        for future in futures
    ]

print(results)
```
The executor handles:
* creating worker threads
* assigning tasks
* managing the worker pool
* waiting for workers
* shutting down the pool

You don't manually call `start()` or `join()` for each worker.

---

## 15. `max_workers`
```python
ThreadPoolExecutor(max_workers=5)
```
controls how many worker threads can execute concurrently.
Example:

```python
from concurrent.futures import ThreadPoolExecutor
def task(number):
    return number * 2
with ThreadPoolExecutor(max_workers=5) as executor:
    results = list(
        executor.map(task, range(10))
    )
print(results)
```
There can be up to 5 worker threads processing tasks at the same time.
For I/O-bound ETL work, the correct value depends on:
* API limits
* database capacity
* network capacity
* task duration
* memory usage
More threads do not automatically mean better performance.

# 16. `submit()`
`submit()` schedules one function call and returns a `Future`.

```python
from concurrent.futures import ThreadPoolExecutor
def task(number):
    return number * 2
with ThreadPoolExecutor(max_workers=3) as executor:
    future = executor.submit(task, 10)
    print(future.result())
```
---

# 17. Future
A `Future` represents the result of an asynchronous operation.
Important methods:
```python
future.result()
future.done()
future.exception()
future.cancel()
future.cancelled()
```
Example:

```python
from concurrent.futures import ThreadPoolExecutor
import time

def task():
    time.sleep(2)
    return 100

with ThreadPoolExecutor(max_workers=1) as executor:
    future = executor.submit(task)
    print("Done:", future.done())
    result = future.result()
    print("Result:", result)
    print("Done:", future.done())
    print("Exception:", future.exception())
```

### `result()`
```python
future.result()
```
returns the function result.
If the task has not finished, `result()` waits.

### `done()`
```python
future.done()
```
returns:
```text
True
```
if the task has completed.

### `exception()`
```python
future.exception()
```
returns the exception raised by the task, or `None`.

### `cancel()`
```python
future.cancel()
```
attempts to cancel the task.
A task that is already running generally cannot be cancelled.

# 18. Exception Handling with `Future`
One major advantage of `Future` is that exceptions can be caught when calling `result()`.
```python
from concurrent.futures import ThreadPoolExecutor

def task(number):
    if number == 3:
        raise ValueError("Invalid number")

    return number * 2

with ThreadPoolExecutor(max_workers=3) as executor:
    futures = [
        executor.submit(task, number)
        for number in range(5)
    ]
    for future in futures:
        try:
            result = future.result()
            print("Result:", result)

        except Exception as e:
            print("Task failed:", e)
```

# 19. `executor.map()`
`map()` is useful when the same function needs to be applied to many inputs.

```python
from concurrent.futures import ThreadPoolExecutor

def transform(number):
    return number * 2

with ThreadPoolExecutor(max_workers=3) as executor:
    results = executor.map(
        transform,
        [1, 2, 3, 4, 5]
    )
print(list(results))
```
Output:

```text
[2, 4, 6, 8, 10]
```
An important property is that results are returned in **input order**.

# 20. `submit()` vs `map()`
### `map()`

Use when:
```text
same function
+
many inputs
+
simple result collection
```

### `submit()`
Use when you need:
* individual `Future` objects
* exception handling per task
* `done()`
* `cancel()`
* `exception()`
* custom tracking
* processing tasks as they finish

# 21. `as_completed()`
`as_completed()` allows you to process results as soon as individual tasks finish.
```python
from concurrent.futures import ThreadPoolExecutor, as_completed
import time
import random

def task(number):
    time.sleep(random.randint(1, 3))
    return number * 2

with ThreadPoolExecutor(max_workers=3) as executor:
    futures = [
        executor.submit(task, number)
        for number in range(5)
    ]
    for future in as_completed(futures):
        try:
            result = future.result()
            print("Completed:", result)

        except Exception as e:
            print("Failed:", e)
```

The completion order may differ from input order.
This is very useful in ETL when you want to process successful API responses immediately rather than waiting for every API call.
