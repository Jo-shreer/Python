# 1. ASYNCHRONOUS PROGRAMMING IN PYTHON

## 1.1 What is asynchronous programming?

Asynchronous programming allows an application to handle multiple operations concurrently without blocking execution while waiting for I/O operations to complete.

For example, a Django application may need to:
1. Fetch user information from a database.
2. Call an external payment API.
3. Send an email.
4. Fetch product information.

In synchronous programming, these operations may execute one after another.

In asynchronous programming, independent I/O operations can overlap, reducing overall waiting time.

### Synchronous example

```python
import time

def fetch_user():
    time.sleep(2)
    return "User data"

def fetch_products():
    time.sleep(3)
    return "Product data"

def main():
    user = fetch_user()
    products = fetch_products()

    print(user, products)

main()
```

Total execution time: approximately 5 seconds.

### Asynchronous example

```python
import asyncio

async def fetch_user():
    await asyncio.sleep(2)
    return "User data"

async def fetch_products():
    await asyncio.sleep(3)
    return "Product data"

async def main():

    results = await asyncio.gather(
        fetch_user(),
        fetch_products()
    )

    print(results)

asyncio.run(main())
```

Total execution time: approximately 3 seconds.

The operations execute concurrently because they are waiting for I/O.

## 1.2 Important Python async keywords

### async

Defines an asynchronous function.

```python
async def get_user():
    return "John"
```

### await

Waits for an asynchronous operation without blocking the event loop.

```python
async def get_user():
    await asyncio.sleep(2)
    return "John"
```

### asyncio.gather()

Runs multiple asynchronous operations concurrently and collects their results.

```python
results = await asyncio.gather(
    fetch_user(),
    fetch_products()
)
```

### asyncio.create_task()

Schedules a coroutine to run as a task.

```python
async def main():

    task1 = asyncio.create_task(fetch_user())
    task2 = asyncio.create_task(fetch_products())

    user = await task1
    products = await task2

    print(user, products)
```

### asyncio.wait_for()

Adds a timeout to an asynchronous operation.

```python
result = await asyncio.wait_for(
    fetch_user(),
    timeout=5
)
```

### asyncio.Semaphore()

Limits the number of concurrent operations.

```python
import asyncio

semaphore = asyncio.Semaphore(5)

async def fetch_data():

    async with semaphore:
        await asyncio.sleep(2)
        return "Data fetched"
```

Useful when calling external APIs with concurrency limits.

# 2. ASYNCHRONOUS PROGRAMMING IN DJANGO

Django supports asynchronous views and asynchronous ORM operations.

## 2.1 Async Django view

```python
from django.http import JsonResponse
import httpx

async def get_users(request):

    async with httpx.AsyncClient() as client:

        response = await client.get(
            "https://api.example.com/users"
        )

    return JsonResponse(response.json(), safe=False)
```

This allows Django to perform asynchronous HTTP requests without blocking the event loop while waiting for the response.

## 2.2 Django asynchronous ORM

Modern Django supports asynchronous ORM methods.

### Fetch one record

```python
employee = await Employee.objects.aget(id=1)
```

### Create a record

```python
employee = await Employee.objects.acreate(
    name="John",
    email="john@example.com"
)
```

### Filter records

```python
employees = [
    employee
    async for employee in Employee.objects.filter(
        department="IT"
    )
]
```

### Check whether records exist

```python
exists = await Employee.objects.filter(
    department="IT"
).aexists()
```

### Count records

```python
count = await Employee.objects.acount()
```

Important: Django's async ORM support varies by operation and version. Some database operations still require synchronous execution. Transactions should generally be placed inside synchronous functions using `transaction.atomic()` and called through `sync_to_async()` when needed.

## 2.3 sync_to_async()

Used to call synchronous functions from asynchronous code.

```python
from asgiref.sync import sync_to_async
from django.db import transaction

@sync_to_async
def get_employee():

    with transaction.atomic():

        employee = Employee.objects.select_for_update().get(id=1)

        employee.status = "active"
        employee.save()

        return employee.name
```

Usage:

```python
async def employee_view(request):

    name = await get_employee()

    return JsonResponse({"name": name})
```

## 2.4 async_to_sync()

Used to call asynchronous functions from synchronous code.

```python
from asgiref.sync import async_to_sync

async def fetch_data():
    return "Data fetched"

result = async_to_sync(fetch_data)()
```

# 3. ASYNC VS THREADING VS MULTIPROCESSING

| Feature | Asyncio | Multithreading | Multiprocessing |
|---|---|---|---|
| Best for | I/O-bound operations | I/O-bound operations | CPU-bound operations |
| Execution | Event loop | Multiple threads | Multiple processes |
| Memory usage | Usually lower | Shared process memory | Separate process memory |
| GIL | Does not bypass GIL | Affects Python CPU work | Separate processes |
| Example | API requests | File/network operations | Image processing |

### When to use each?

Asyncio:
- External API requests.
- Multiple HTTP calls.
- WebSockets.
- Network operations.

Multithreading:
- Blocking I/O operations.
- Legacy synchronous libraries.
- Concurrent file or network operations.

Multiprocessing:
- Image processing.
- Video processing.
- Large mathematical calculations.
- CPU-intensive operations.

# 4. CELERY AND BACKGROUND TASK PROCESSING

## 4.1 What is Celery?

Celery is a distributed task queue used to execute background tasks outside the main Django request-response cycle.

For example:
- Sending emails.
- Generating PDF reports.
- Processing uploaded files.
- Sending notifications.
- Running scheduled jobs.

## 4.2 Why use Celery?

Suppose a user registers on your website.

The application needs to:
1. Save user information.
2. Send a welcome email.
3. Generate a welcome PDF.
4. Send a notification.

Sending the email and generating the PDF synchronously can make the registration API slow.

Instead, use Celery to execute those operations in the background.

## 4.3 Celery example

tasks.py:

```python
from celery import shared_task

@shared_task
def send_welcome_email(email):

    print(f"Sending email to {email}")

    return "Email sent"
```

views.py:

```python
from django.http import JsonResponse
from .tasks import send_welcome_email

def register_user(request):

    email = "john@example.com"

    send_welcome_email.delay(email)

    return JsonResponse({
        "message": "Registration successful"
    })
```

The `.delay()` method sends the task to the Celery broker.

## 4.4 Celery architecture

Django Application → Message Broker → Celery Worker → Task Execution.

Common message brokers:
- Redis.
- RabbitMQ.

Celery Beat is used for scheduled tasks.

Example:

```python
from celery.schedules import crontab

CELERY_BEAT_SCHEDULE = {
    "daily-report": {
        "task": "reports.tasks.generate_report",
        "schedule": crontab(hour=8, minute=0),
    }
}
```

# 5. MANAGING HIGH-LOAD DATABASE QUERIES

## 5.1 What is high-load database management?

High-load database management means optimizing database performance when many users or applications access the database simultaneously.

Example:

An e-commerce application receives 50,000 requests per minute.

Possible problems:
- Slow SQL queries.
- Too many database connections.
- High CPU usage.
- Database locks.
- Deadlocks.
- Connection timeouts.
- High memory consumption.

The objective is to reduce database load and maintain good response times.

## 5.2 Django ORM query optimization

### N+1 query problem

Bad approach:

```python
employees = Employee.objects.all()

for employee in employees:
    print(employee.department.name)
```

This can execute one query for employees and additional queries for each department.

Optimized approach:

```python
employees = Employee.objects.select_related(
    "department"
)

for employee in employees:
    print(employee.department.name)
```

### select_related()

Used for:
- ForeignKey.
- OneToOneField.

Uses SQL JOIN to retrieve related data.

### prefetch_related()

Used for:
- ManyToManyField.
- Reverse ForeignKey relationships.

Uses separate queries and joins the results in Python.

Example:

```python
courses = Course.objects.prefetch_related(
    "students"
)
```

### only()

Fetches only selected model fields initially.

```python
employees = Employee.objects.only(
    "id",
    "name"
)
```

### defer()

Avoids loading selected fields initially.

```python
employees = Employee.objects.defer(
    "description"
)
```

### values()

Returns dictionaries instead of model objects.

```python
employees = Employee.objects.values(
    "id",
    "name"
)
```

### values_list()

Returns tuples or flat values.

```python
names = Employee.objects.values_list(
    "name",
    flat=True
)
```

### exists()

Efficiently checks whether records exist.

```python
exists = Employee.objects.filter(
    department="IT"
).exists()
```

### count()

Counts records efficiently.

```python
total = Employee.objects.count()
```

### bulk_create()

Inserts multiple records efficiently.

```python
employees = [
    Employee(name="John"),
    Employee(name="David"),
    Employee(name="Mike")
]

Employee.objects.bulk_create(employees)
```

### bulk_update()

Updates multiple records efficiently.

```python
employees = Employee.objects.filter(
    department="IT"
)

for employee in employees:
    employee.status = "active"

Employee.objects.bulk_update(
    employees,
    ["status"]
)
```

Note: Bulk operations bypass normal per-instance save behavior and model save signals. Validate data and handle business logic accordingly.

# 6. DATABASE INDEXING

## What is database indexing?

An index is a data structure that helps a database locate records faster without scanning the entire table.

Example:

```python
class Employee(models.Model):

    name = models.CharField(max_length=100)

    email = models.EmailField(
        db_index=True
    )
```

Query:

```python
Employee.objects.filter(
    email="john@example.com"
)
```

The index can improve lookup performance.

## Types of database indexes

1. Single-column index.
2. Composite index.
3. Unique index.
4. Partial index.
5. Functional index.
6. Full-text index.
7. B-tree index.
8. Hash index.
9. GIN index.
10. GiST index.

### Composite index example

```python
class Order(models.Model):

    customer_id = models.IntegerField()

    status = models.CharField(max_length=50)

    class Meta:
        indexes = [
            models.Index(
                fields=["customer_id", "status"]
            )
        ]
```

Useful for queries filtering by both customer_id and status.

Important: Indexes improve some reads but consume storage and can slow down INSERT, UPDATE, and DELETE operations.

# 7. DATABASE CONNECTION POOLING

## What is connection pooling?

Connection pooling maintains reusable database connections rather than establishing a new database connection for every request.

Benefits:
- Reduces connection establishment overhead.
- Controls database connection usage.
- Improves scalability.
- Reduces connection churn.

## Django persistent connections

```python
DATABASES = {
    "default": {
        "ENGINE": "django.db.backends.postgresql",
        "NAME": "mydb",
        "USER": "postgres",
        "PASSWORD": "password",
        "HOST": "localhost",
        "PORT": "5432",
        "CONN_MAX_AGE": 60,
    }
}
```

`CONN_MAX_AGE` controls how long Django can reuse a persistent connection, subject to its connection lifecycle.

Persistent connections are not the same as a centralized connection pool.

## PgBouncer

PgBouncer is a PostgreSQL connection pooling tool.

Architecture:

Django → PgBouncer → PostgreSQL.

### PgBouncer pooling modes

1. Session pooling: Connection is assigned for the entire client session.
2. Transaction pooling: Connection is assigned for the duration of a transaction.
3. Statement pooling: Connection is released after each statement.

Transaction pooling is useful for high-concurrency workloads but requires care with session-level state and certain PostgreSQL features.

# 8. REDIS CACHING

## What is Redis?

Redis is an in-memory data store used for:
- Caching.
- Session management.
- Message brokering.
- Distributed locks.
- Temporary data storage.

## Django caching example

```python
from django.core.cache import cache

def get_products():

    products = cache.get("products")

    if products is None:

        products = list(
            Product.objects.values(
                "id",
                "name",
                "price"
            )
        )

        cache.set(
            "products",
            products,
            timeout=300
        )

    return products
```

The cache stores the products for 300 seconds.

## Types of caching

4. Per-view caching.

# 9. DATABASE TRANSACTIONS AND CONCURRENCY

## What is a database transaction?

A transaction is a group of database operations that should succeed or fail together.

Django provides `transaction.atomic()`.

Example:

```python
from django.db import transaction

def transfer_money(sender, receiver, amount):

    with transaction.atomic():

        sender.balance -= amount
        sender.save()

        receiver.balance += amount
        receiver.save()
```

If an exception occurs inside the transaction, the transaction is rolled back.

## ACID properties

1. Atomicity: All operations succeed or none do.
2. Consistency: Database rules remain valid.
3. Isolation: Concurrent transactions are controlled.
4. Durability: Committed changes persist.

## select_for_update()

Used to lock selected rows during a transaction.

```python
from django.db import transaction

def update_balance(account_id, amount):

    with transaction.atomic():

        account = Account.objects.select_for_update().get(
            id=account_id
        )

        account.balance += amount

        account.save()
```

This helps prevent conflicting concurrent modifications.

## Optimistic locking

Optimistic locking uses a version number to detect concurrent updates.

Example concept:

```python
from django.db.models import F

updated = Account.objects.filter(
    id=account_id,
    version=current_version
).update(
    balance=F("balance") + amount,
    version=F("version") + 1
)

if updated == 0:
    raise Exception("Concurrent update detected")
```

This is useful when conflicts are relatively uncommon.

# 10. DATABASE DEADLOCKS

## What is a deadlock?

A deadlock occurs when two or more transactions wait for each other to release locked resources.

Example:

Transaction A locks Account 1 and waits for Account 2.

Transaction B locks Account 2 and waits for Account 1.

Neither transaction can continue.

### How to prevent deadlocks

1. Acquire locks in a consistent order.
2. Keep transactions short.
3. Avoid unnecessary row locking.
4. Use appropriate transaction isolation.
5. Handle deadlock errors and retry safely.
6. Avoid external API calls while holding database locks.

# 11. DATABASE READ REPLICAS

## What is database replication?

Replication means copying database data from a primary database to one or more replica databases.

Architecture:

Django Application
    |
    |-- Read Queries → Replica Database
    |
    |-- Write Queries → Primary Database

Benefits:
- Distributes read traffic.
- Reduces primary database workload.
- Improves read scalability.
- Supports reporting workloads.

Django database router:

```python
class DatabaseRouter:

    def db_for_read(self, model, **hints):
        return "replica"

    def db_for_write(self, model, **hints):
        return "default"
```

Settings:

```python
DATABASE_ROUTERS = [
    "myapp.routers.DatabaseRouter"
]
```

Important: Replication lag means a recent write may not immediately be available on a replica. Use the primary database when read-after-write consistency is required.

# 12. PAGINATION

Pagination prevents an application from retrieving huge amounts of data in one request.

Bad approach:

```python
employees = Employee.objects.all()
```

Better:

```python
employees = Employee.objects.all()[:20]
```

Django REST Framework pagination:

```python
from rest_framework.pagination import PageNumberPagination

class EmployeePagination(PageNumberPagination):

    page_size = 20

    page_size_query_param = "page_size"

    max_page_size = 100
```

### Types of pagination

1. Page-number pagination.
2. Limit-offset pagination.
3. Cursor pagination.

Cursor pagination is often preferable for large, frequently changing datasets when records have a suitable stable ordering.

# 15. IMPORTANT INTERVIEW QUESTIONS AND ANSWERS

## ASYNCHRONOUS PROGRAMMING

### Q1. What is asynchronous programming?

Asynchronous programming allows an application to execute multiple I/O-bound operations concurrently without blocking the event loop while waiting for operations to complete.

### Q2. What is the difference between synchronous and asynchronous programming?

Synchronous programming executes operations sequentially.

Asynchronous programming allows other tasks to execute while an I/O operation is waiting.

### Q3. What are async and await?

`async` defines a coroutine function.

`await` pauses the current coroutine until an awaitable operation completes, allowing other tasks to run.

### Q4. What is asyncio?

Asyncio is Python's library for writing concurrent code using coroutines, tasks, and event loops.

### Q5. What is asyncio.gather()?

It schedules multiple awaitables concurrently and collects their results.

### Q6. What is asyncio.create_task()?

It schedules a coroutine to run as a task and returns a task object.

### Q7. What is the GIL?

The Global Interpreter Lock is a mechanism in standard CPython builds that generally allows only one thread to execute Python bytecode at a time within a process.

### Q8. What is ASGI?

ASGI stands for Asynchronous Server Gateway Interface. It supports asynchronous Python applications, including Django async views and WebSockets.

### Q9. What is WSGI?

WSGI stands for Web Server Gateway Interface. It is the traditional synchronous Python web application interface.

### Q10. What is the difference between Celery and asyncio?

Asyncio handles concurrent operations within an application process.

Celery distributes background tasks across workers and can process tasks independently of the request-response cycle.

### Q11. Can Django ORM work asynchronously?

Yes. Modern Django supports asynchronous ORM operations such as `aget()`, `acreate()`, `aexists()`, and asynchronous QuerySet iteration.

Some operations, particularly transaction workflows, still require synchronous execution.
