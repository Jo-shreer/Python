# Django & Django REST Framework – Complete Cheat Sheet

# PART 1: DJANGO FUNDAMENTALS

## 1. What is Django?

Django is a Python web framework used to build web applications and backend APIs.

It provides:
- ORM (database interaction)
- Authentication
- Admin panel
- URL routing
- Middleware
- Security features
- Forms and templates

## 2. Django MVT Architecture

MVT stands for:

- Model – Handles database structure and data.
- View – Handles business logic and requests.
- Template – Handles the presentation/UI.

Example flow:

1. User sends a request.
2. URL routes the request to a View.
3. View interacts with Model if required.
4. View returns a response or renders a Template.

## 3. Create a Django Project

```bash
pip install django
django-admin startproject myproject
cd myproject
python manage.py startapp myapp
python manage.py runserver
```

Important files:

- `settings.py` – Project configuration.
- `urls.py` – URL routing.
- `models.py` – Database models.
- `views.py` – Business logic.
- `admin.py` – Admin registration.
- `apps.py` – App configuration.
- `tests.py` – Tests.

Register your app in `INSTALLED_APPS` in settings.py.

# PART 2: DJANGO MODELS

## 4. What are Models?

Models define the database tables and their columns.

Example:

```python
from django.db import models

class Employee(models.Model):
    name = models.CharField(max_length=100)
    age = models.IntegerField()
    email = models.EmailField()
    salary = models.FloatField()
    is_active = models.BooleanField(default=True)
```

Django automatically creates the database table based on the model.

## 5. Important Model Fields

```python
models.CharField(max_length=100)
models.TextField()
models.IntegerField()
models.FloatField()
models.DecimalField(max_digits=10, decimal_places=2)
models.BooleanField(default=True)
models.DateField()
models.DateTimeField(auto_now_add=True)
models.DateTimeField(auto_now=True)
models.EmailField()
models.URLField()
models.FileField()
models.ImageField()
```

Important differences:

- `auto_now_add=True` – Sets the date/time when the record is first created.
- `auto_now=True` – Updates the date/time whenever the record is saved.
- `null=True` – Allows NULL in the database.
- `blank=True` – Allows an empty value during validation.
- `default` – Provides a default value.

## 6. Primary Key

A primary key uniquely identifies each database record.

```python
class Employee(models.Model):
    name = models.CharField(max_length=100)
```

Django automatically creates an `id` primary key if you don't define one.

## 7. ForeignKey (Many-to-One)

Multiple products can belong to one category.

```python
class Category(models.Model):
    name = models.CharField(max_length=100)

class Product(models.Model):
    name = models.CharField(max_length=100)
    category = models.ForeignKey(
        Category,
        on_delete=models.CASCADE
    )
```

Important:

- `ForeignKey` defines a relationship.
- Django automatically uses the related model's primary key.
- The database column is normally called `category_id`.

`on_delete` options:

- `CASCADE` – Delete related records when the referenced record is deleted.
- `PROTECT` – Prevent deletion if related records exist.
- `SET_NULL` – Set the foreign key to NULL.
- `SET_DEFAULT` – Set a default value.
- `DO_NOTHING` – Do nothing automatically.

## 8. OneToOneField

One record relates to exactly one record in another model.

Example: One employee has one profile.

```python
class Employee(models.Model):
    name = models.CharField(max_length=100)

class EmployeeProfile(models.Model):
    employee = models.OneToOneField(
        Employee,
        on_delete=models.CASCADE,
        related_name="profile"
    )
    address = models.CharField(max_length=200)
```

Access:

```python
profile.employee       # Forward relationship
employee.profile       # Reverse relationship
```

`related_name` defines the reverse relationship's accessor name.

Without it, Django creates a default reverse accessor.

## 9. ManyToManyField

Multiple students can enroll in multiple courses.

```python
class Course(models.Model):
    name = models.CharField(max_length=100)

class Student(models.Model):
    name = models.CharField(max_length=100)
    courses = models.ManyToManyField(Course)
```

Usage:

```python
student.courses.add(course)
student.courses.remove(course)
student.courses.all()
student.courses.clear()
```

Django creates an intermediate table automatically.

## 10. Model Migrations

Migrations apply model changes to the database.

```bash

```

- `makemigrations` – Creates migration files.
- `migrate` – Applies migrations to the database.
- `showmigrations` – Shows applied and unapplied migrations.

## 12. ORM Lookup Operations

```python
Employee.objects.filter(age__gt=25)
Employee.objects.filter(age__gte=25)
Employee.objects.filter(age__lt=25)
Employee.objects.filter(age__lte=25)
Employee.objects.filter(name__exact="John")
Employee.objects.filter(name__icontains="jo")
Employee.objects.filter(name__startswith="J")
Employee.objects.filter(age__in=[20, 25, 30])
Employee.objects.filter(age__range=(20, 30))
```

Meaning:

- `gt` – Greater than.
- `gte` – Greater than or equal.
- `lt` – Less than.
- `lte` – Less than or equal.
- `icontains` – Case-insensitive contains.
- `in` – Matches any value in a list.
- `range` – Between two values.

## 13. select_related vs prefetch_related

These improve database query performance.

### select_related

Used for ForeignKey and OneToOne relationships.

```python
products = Product.objects.select_related("category").all()
```

It uses SQL JOIN to fetch related objects together.

### prefetch_related

Used for ManyToMany and reverse relationships.

```python
students = Student.objects.prefetch_related("courses").all()
```

It performs separate queries and combines the results in Python.

Remember:

- `select_related` – ForeignKey and OneToOne.
- `prefetch_related` – ManyToMany and reverse relationships.

## 14. Q Objects

Used for complex OR and AND queries.

```python
from django.db.models import Q

Employee.objects.filter(
    Q(age__gt=30) | Q(salary__gt=50000)
)
```

OR: `|`

AND: `&`

NOT: `~`

## 15. F Expressions

Used to compare or update database fields without retrieving their values into Python first.

```python
from django.db.models import F

Employee.objects.filter(
    salary__gt=F("bonus")
)
```

Increment salary:

```python
Employee.objects.filter(id=1).update(
    salary=F("salary") + 1000
)
```

## 16. Aggregate and Annotate

### Aggregate

Returns a summary value for a queryset.

```python
from django.db.models import Avg, Sum, Count

Employee.objects.aggregate(
    average_salary=Avg("salary")
)
```

### Annotate

Adds calculated values to individual records.

```python
from django.db.models import Count

categories = Category.objects.annotate(
    product_count=Count("product")
)
```

# PART 4: DJANGO REST FRAMEWORK

## 20. What is DRF?

Django REST Framework is a toolkit used to build REST APIs using Django.

Install:

```bash
pip install djangorestframework
```

Add `rest_framework` to `INSTALLED_APPS`.

## 21. What is a Serializer?

A serializer converts:

- Model objects into JSON-ready Python data.
- Incoming JSON data into validated Python data that can be saved.

Example model:

```python
class Student(models.Model):
    name = models.CharField(max_length=100)
    age = models.IntegerField()
```

Serializer:

```python
from rest_framework import serializers

class StudentSerializer(serializers.ModelSerializer):
    class Meta:
        model = Student
        fields = "__all__"
```

### Serialization

```python
student = Student.objects.get(id=1)

serializer = StudentSerializer(student)

print(serializer.data)
```

Converts a model object into JSON-ready data.

### Deserialization

```python
serializer = StudentSerializer(data=request.data)

if serializer.is_valid():
    serializer.save()
```

Accepts input and validates it before saving.

## 22. fields = "__all__"

Includes all model fields in the serializer.

```python
class Meta:
    model = Student
    fields = "__all__"
```

You can also specify particular fields:

```python
fields = ["id", "name", "age"]
```

## 23. Serializer Validation

### Field-level validation

Used to validate an individual field.

```python
def validate_age(self, value):
    if value < 18:
        raise serializers.ValidationError(
            "Age must be at least 18"
        )
    return value
```

DRF calls this method automatically for the `age` field.

### Object-level validation

Used when validation depends on multiple fields.

```python
def validate(self, data):
    if data["age"] < 18 and data["marks"] > 90:
        raise serializers.ValidationError(
            "Invalid student details"
        )

    return data
```

### Validation flow

```python
serializer = StudentSerializer(data=request.data)

if serializer.is_valid():
    serializer.save()
    return Response(serializer.data)

return Response(serializer.errors, status=400)
```

- `is_valid()` – Runs validation.
- `raise ValidationError()` – Reports a validation failure.
- `serializer.errors` – Contains validation errors.
- `serializer.save()` – Creates or updates an object.

## 24. read_only and write_only

### read_only

Client can receive the field but cannot modify it through the serializer.

```python
class StudentSerializer(serializers.ModelSerializer):
    class Meta:
        model = Student
        fields = "__all__"
        read_only_fields = ["id"]
```

### write_only

Client can send the field, but it won't appear in the response.

```python
password = serializers.CharField(write_only=True)
```

Commonly used for passwords.

## 25. partial=True

Used when updating only some fields.

```python
def update_student(request, pk):
    student = Student.objects.get(id=pk)

    serializer = StudentSerializer(
        student,
        data=request.data,
        partial=True
    )

    if serializer.is_valid():
        serializer.save()
        return Response(serializer.data)

    return Response(serializer.errors, status=400)
```

`partial=True` allows missing required fields.

Commonly used for PATCH.

## 26. source in Serializers

Used to map a serializer field name to a different model field name.

Model:

```python
class Product(models.Model):
    name = models.CharField(max_length=100)
    price = models.IntegerField()
```

Serializer:

```python
class ProductSerializer(serializers.ModelSerializer):
    product_price = serializers.IntegerField(source="price")

    class Meta:
        model = Product
        fields = ["name", "product_price"]
```

Frontend request:

```json
{
    "name": "Laptop",
    "product_price": 50000
}
```

DRF maps `product_price` to the model's `price` field.

Response:

```json
{
    "name": "Laptop",
    "product_price": 50000
}
```

Important: `source` handles both input and output.

## 27. PrimaryKeyRelatedField

Used to accept a related object's primary key in an API request.

Models:

```python
class Category(models.Model):
    name = models.CharField(max_length=100)

class Product(models.Model):
    name = models.CharField(max_length=100)
    category = models.ForeignKey(
        Category,
        on_delete=models.CASCADE
    )
```

Serializer:

```python
class ProductSerializer(serializers.ModelSerializer):

    category_id = serializers.PrimaryKeyRelatedField(
        source="category",
        queryset=Category.objects.all(),
        write_only=True
    )

    class Meta:
        model = Product
        fields = ["name", "category_id"]
```

Frontend sends:

```json
{
    "name": "Laptop",
    "category_id": 1
}
```

DRF:

1. Receives category ID.
2. Searches the Category queryset.
3. Checks whether the category exists.
4. Gets the actual Category object.
5. Assigns it to Product's `category` field.

Without custom field naming, ModelSerializer can handle a ForeignKey automatically.

## 28. Nested Serializers

Used when you want to return related objects as nested data.

```python
class CategorySerializer(serializers.ModelSerializer):
    class Meta:
        model = Category
        fields = "__all__"


class ProductSerializer(serializers.ModelSerializer):
    category = CategorySerializer(read_only=True)

    class Meta:
        model = Product
        fields = "__all__"
```

Example response:

```json
{
    "id": 1,
    "name": "Laptop",
    "category": {
        "id": 2,
        "name": "Electronics"
    }
}
```

Note: Nested read-only serializers are straightforward for output. Creating or updating nested objects requires custom `create()` or `update()` logic.

## 29. APIView

APIView gives control over HTTP methods.

```python
from rest_framework.views import APIView
from rest_framework.response import Response
from rest_framework import status

class StudentAPIView(APIView):

    def get(self, request):
        students = Student.objects.all()
        serializer = StudentSerializer(students, many=True)
        return Response(serializer.data)

    def post(self, request):
        serializer = StudentSerializer(data=request.data)

        if serializer.is_valid():
            serializer.save()
            return Response(
                serializer.data,
                status=status.HTTP_201_CREATED
            )

        return Response(
            serializer.errors,
            status=status.HTTP_400_BAD_REQUEST
        )
```

Important:

- `many=True` – Used when serializing multiple objects.
- `request.data` – Contains parsed request body.
- `Response` – DRF response class.

# PART 5: AUTHENTICATION AND PERMISSIONS

## 34. Authentication vs Authorization

Authentication: Who are you?

Authorization: What are you allowed to do?

## 35. Basic Authentication

Sends username and password encoded in Base64.

```http
Authorization: Basic <credentials>
```

Base64 is encoding, not encryption. Use HTTPS.

## 36. Session Authentication

Django verifies the user's login and creates a session.

Browser stores a session cookie:

```http
Cookie: sessionid=abc123
```

For unsafe requests such as POST, PUT, PATCH and DELETE, CSRF protection is required.

Commonly used for browser-based applications.

## 37. Token Authentication

User logs in and receives a token.

```http
Authorization: Token abc123
```

The client sends the token on subsequent API requests.

DRF's built-in token authentication does not provide token expiry by default.

## 38. JWT Authentication

JWT means JSON Web Token.

Install:

```bash
pip install djangorestframework-simplejwt
```

Typical flow:

1. User sends username and password.
2. Backend returns access and refresh tokens.
3. Client sends access token with API requests.
4. When access token expires, client uses refresh token to obtain another access token.

Header:

```http
Authorization: Bearer <access_token>
```

JWT structure:

- Header
- Payload
- Signature

Important: JWT payload is encoded, not encrypted. Never store passwords or sensitive data in it.

## 39. Permissions

Permissions control who can access an API.

Example:

```python
from rest_framework.permissions import IsAuthenticated

class StudentAPIView(APIView):
    permission_classes = [IsAuthenticated]
```

Common permissions:

- `AllowAny` – Anyone can access.
- `IsAuthenticated` – Only logged-in users.
- `IsAdminUser` – Admin/staff users.
- `IsAuthenticatedOrReadOnly` – Anyone can read, authenticated users can perform unsafe operations.

## 40. Custom Permissions

```python
from rest_framework.permissions import BasePermission

class IsOwner(BasePermission):

    def has_object_permission(self, request, view, obj):
        return obj.user == request.user
```

This checks whether the logged-in user owns the object.

## 41. Middleware

Middleware processes requests and responses globally.

Flow:

Request → Middleware → View → Middleware → Response

Common middleware:

- SecurityMiddleware
- SessionMiddleware
- AuthenticationMiddleware
- CsrfViewMiddleware
- CommonMiddleware

Custom middleware:

```python
class MyMiddleware:

    def __init__(self, get_response):
        self.get_response = get_response

    def __call__(self, request):
        print("Before view")

        response = self.get_response(request)

        print("After view")
        return response
```

## 42. Django Signals

Signals allow one part of the application to respond to events in another part.

Example: Create a profile when a user is created.

```python
from django.db.models.signals import post_save
from django.dispatch import receiver

@receiver(post_save, sender=Employee)
def create_profile(sender, instance, created, **kwargs):
    if created:
        EmployeeProfile.objects.create(employee=instance)
```

Important signals:

- `pre_save`
- `post_save`
- `pre_delete`
- `post_delete`
- `m2m_changed`

Avoid using signals for complex business logic when an explicit service function would be clearer.

## 43. Transactions


If an exception causes the transaction to fail, changes within the transaction are rolled back.

## 50. Async Views

Async views allow asynchronous I/O operations.

```python

from django.http import JsonResponse

async def external_api(request):

    async with httpx.AsyncClient() as client:
        response = await client.get(
            "https://api.example.com/users"
```

Important:

- `await` waits for an asynchronous operation without blocking the event loop.
- Useful for I/O-heavy operations.

# PART 7: SECURITY

## 53. Important Django Security Concepts

### CSRF

Cross-Site Request Forgery.

Django uses CSRF tokens to protect browser-based requests.

### XSS

Cross-Site Scripting.

Avoid inserting untrusted HTML into pages. Django templates escape variables by default.

### SQL Injection

Avoid constructing SQL queries using string concatenation.

Use Django ORM or parameterized SQL.

### Password Security

Use Django's built-in password hashing:

```python
from django.contrib.auth.hashers import make_password

hashed = make_password("mypassword")
```

Never store plain-text passwords.

### HTTPS

Use HTTPS in production to protect data in transit.

### Secret Management

Store database passwords, API keys and Django SECRET_KEY outside source code.

# PART 9: INTERVIEW QUESTIONS AND ANSWERS

## Django Fundamentals

**Q1. What is Django?**

Django is a high-level Python web framework used to build secure and scalable web applications and APIs.

**Q2. What is MVT architecture?**

MVT stands for Model, View and Template. Model handles data, View handles business logic, and Template handles presentation.

**Q3. What is the difference between Django and DRF?**

Django is a web framework. Django REST Framework is an additional toolkit used to build REST APIs with Django.

**Q4. What is manage.py?**

It is a command-line utility used to manage Django projects, including running servers, migrations and creating superusers.

**Q5. What is the difference between a project and an app?**

A project is the complete Django application. An app is a module that handles a specific functionality.

## Models and ORM

**Q6. What is ORM?**

ORM allows us to interact with a relational database using Python objects instead of writing SQL manually.

**Q7. What is the difference between ForeignKey, OneToOneField and ManyToManyField?**

- ForeignKey: Many records can reference one record.
- OneToOneField: Each side has at most one related record.
- ManyToManyField: Multiple records can relate to multiple records.

**Q8. What is related_name?**

It defines the name used to access a related object in the reverse direction.

**Q9. What is on_delete=models.CASCADE?**

When the referenced object is deleted, its dependent objects are deleted too.

**Q10. What is the difference between null=True and blank=True?**

- null=True: Allows NULL in the database.
- blank=True: Allows an empty value during validation.

**Q11. What is the difference between get() and filter()?**

- `get()` returns one object and raises an exception if it doesn't find exactly one.
- `filter()` returns a QuerySet, even if no records match.

**Q12. What is select_related?**

It fetches related ForeignKey or OneToOne objects using SQL JOINs.

**Q13. What is prefetch_related?**

It fetches related records using separate queries and combines them in Python.

**Q14. What is the N+1 query problem?**

It happens when one query fetches a list of records and additional queries are executed for each record's related data.

Use `select_related()` or `prefetch_related()` to reduce unnecessary queries.

**Q15. What are Q objects?**

Q objects allow complex database queries using OR, AND and NOT conditions.

**Q16. What are F expressions?**

F expressions reference database fields directly in queries, allowing comparisons and updates without first retrieving values into Python.

**Q17. What is the difference between annotate and aggregate?**

- Aggregate returns summary values for a queryset.
- Annotate adds calculated values to individual records.

**Q18. What are migrations?**

Migrations track model changes and apply those changes to the database schema.

**Q19. What is transaction.atomic()?**

It groups database operations into one transaction. If the transaction fails, changes are rolled back.

## Views and APIs

**Q20. What is the difference between FBV and CBV?**

- FBV uses functions.
- CBV uses classes and supports reusable behavior through inheritance and mixins.

**Q21. What is APIView?**

APIView is a DRF class that provides HTTP method handlers such as GET, POST, PUT and DELETE.

**Q22. What is a ViewSet?**

A ViewSet groups related API actions, such as listing, creating, updating and deleting records.

**Q23. What is a Router?**

A router automatically generates URLs for registered ViewSets.

**Q24. What is the difference between PUT and PATCH?**

- PUT generally replaces the resource and expects required fields.
- PATCH updates only specified fields.

**Q25. What is Response in DRF?**

Response is a DRF class that returns API data and supports content negotiation.

## Serializers

**Q26. What is a serializer?**

A serializer converts model objects into JSON-ready data and validates incoming data before saving it.

**Q27. What is ModelSerializer?**

ModelSerializer automatically creates serializer fields based on a Django model.

**Q28. What is fields="__all__"?**

It includes all model fields in the serializer.

**Q29. What is many=True?**

It tells the serializer that we are serializing multiple objects.

**Q30. What is is_valid()?**

It validates incoming data against serializer field and custom validation rules.

**Q31. What is serializer.save()?**

It creates a new object or updates an existing object, depending on whether an instance was passed to the serializer.

**Q32. What is validate_<field_name>()?**

It is field-level validation.

Example:

```python
def validate_age(self, value):
    if value < 18:
        raise serializers.ValidationError("Invalid age")
    return value
```

**Q33. What is validate()?**

It is object-level validation used when validation depends on multiple fields.

**Q34. What is read_only?**

A field is included in API output but is not accepted as writable input.

**Q35. What is write_only?**

A field accepts input but is excluded from serialized output.

**Q36. What is partial=True?**

It allows partial updates without requiring every required field.

**Q37. What is source in serializers?**

It maps a serializer field to a model field with a different name. It works for both serialization and deserialization.

**Q38. What is PrimaryKeyRelatedField?**

It accepts a related object's primary key and resolves it to the actual related model object using a queryset.

**Q39. What is a nested serializer?**

It represents related model data as nested JSON instead of only returning a related object's ID.

**Q40. What is the difference between Serializer and ModelSerializer?**

- Serializer: Fields and create/update logic are generally defined manually.
- ModelSerializer: Automatically generates fields and basic create/update logic from a model.

## Authentication and Security

**Q41. What is the difference between authentication and authorization?**

Authentication identifies the user. Authorization checks what the user is allowed to do.

**Q42. What is SessionAuthentication?**

It authenticates requests using Django's session cookie. Unsafe browser requests require CSRF protection.

**Q43. What is TokenAuthentication?**

It authenticates API requests using a token sent in the Authorization header.

**Q44. What is JWT?**

JWT is a signed token format commonly used for stateless authentication. It can contain claims and expiry information.

**Q45. What is the difference between JWT and DRF TokenAuthentication?**

DRF TokenAuthentication typically uses a database-backed token. JWT uses signed tokens containing claims and can be validated without looking up a token record on every request.

**Q46. What is permission_classes?**

It specifies which users are allowed to access an API.

**Q47. What is CSRF?**

Cross-Site Request Forgery is an attack where a malicious site attempts to make a user's browser perform an unwanted authenticated request.

**Q48. What is XSS?**

Cross-Site Scripting is an attack where malicious scripts are injected into web pages.

**Q49. How do you protect API credentials?**

Use HTTPS, environment variables or a secrets manager, proper authentication, and never expose secrets in frontend code.

## Advanced Django

**Q50. What is middleware?**

Middleware processes incoming requests and outgoing responses globally.

**Q51. What are Django signals?**

Signals allow functions to respond to events such as model creation, saving and deletion.

**Q52. What is caching?**

Caching stores frequently accessed data temporarily to reduce database queries and improve performance.

**Q53. What is pagination?**

Pagination divides large result sets into smaller pages.

**Q54. What is Celery?**

Celery is a distributed task queue used to run background jobs asynchronously.

**Q55. What is Redis?**

Redis is an in-memory data store commonly used for caching, Celery brokers and temporary application data.

**Q56. What is the difference between async and sync views?**

Synchronous views execute normally and can block while waiting for I/O. Async views support awaitable operations and are useful for concurrent I/O workloads.

**Q57. What is logging?**

Logging records application events, warnings and errors to help with monitoring and debugging.

**Q58. How do you handle exceptions in DRF?**

Use validation errors, appropriate HTTP status codes, try/except where needed, and DRF's exception handling system.

**Q59. How do you improve Django API performance?**

- Use select_related and prefetch_related.
- Add database indexes where useful.
- Use pagination.
- Avoid unnecessary database queries.
- Use caching.
- Optimize SQL queries.
- Move long-running tasks to background workers.

**Q60. How do you manage database transactions?**

Use `transaction.atomic()` to ensure related database operations succeed or roll back together.
