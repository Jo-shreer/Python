============================================================
TERRAFORM AWS RESOURCES – CHEAT SHEET
============================================================

BASIC TERRAFORM RESOURCE SYNTAX
------------------------------------------------------------

resource "RESOURCE_TYPE" "RESOURCE_NAME" {
  argument = value
}


Example:

resource "aws_s3_bucket" "my_bucket" {
  bucket = "my-app-bucket"
}


FORMAT:

resource
   ↓
AWS resource type
   ↓
Terraform local name
   ↓
Configuration

29. TERRAFORM RESOURCE REFERENCE
============================================================

Resources can reference other resources.

Example:

resource "aws_vpc" "main" {
  cidr_block = "10.0.0.0/16"
}

resource "aws_subnet" "public" {
  vpc_id = aws_vpc.main.id

  cidr_block = "10.0.1.0/24"
}


Here:

aws_vpc.main.id

means:

RESOURCE TYPE = aws_vpc
RESOURCE NAME = main
ATTRIBUTE     = id

============================================================
IMPORTANT NOTE
============================================================

You do NOT need to memorize every AWS Terraform resource.

The important pattern is:

resource "aws_<service>_<resource>" "name" {
    configuration
}

Examples:

aws_instance
aws_s3_bucket
aws_lambda_function
aws_vpc
aws_subnet
aws_iam_role
aws_dynamodb_table
aws_ecs_cluster
aws_sqs_queue
aws_sns_topic
aws_db_instance

Terraform has many more AWS resources, and the exact arguments
depend on the resource.

For real projects, engineers normally refer to the Terraform
AWS Provider documentation for the exact resource syntax.
