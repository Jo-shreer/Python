# FastAPI — Complete Notes

## 1. What is FastAPI?
**FastAPI** is a modern Python web framework used to build APIs.

It is built around:
* Python type hints
* Pydantic for data validation
* ASGI for asynchronous applications
* Automatic OpenAPI documentation

Typical use cases:

```text
REST APIs
Backend services
Microservices
ETL APIs
Internal services
Data processing APIs
```

---

## 2. Basic FastAPI Application

```python
from fastapi import FastAPI

app = FastAPI()


@app.get("/")
def home():
    return {"message": "API is running"}
```

Run it with:

```bash
uvicorn main:app --reload
```

If the file is called `main.py`:

```text
main → Python file
app  → FastAPI object
```

FastAPI automatically provides:

```text
/docs    → Swagger UI
/redoc   → ReDoc
/openapi.json → OpenAPI schema
```

---

## 3. HTTP Methods

The main HTTP methods used in REST APIs are:

```text
GET
POST
PUT
PATCH
DELETE
```

Example:

```python
from fastapi import FastAPI

app = FastAPI()


@app.get("/customers")
def get_customers():
    return {"customers": []}


@app.post("/customers")
def create_customer():
    return {"message": "Customer created"}


@app.put("/customers/{customer_id}")
def replace_customer(customer_id: int):
    return {"message": "Customer replaced"}


@app.patch("/customers/{customer_id}")
def update_customer(customer_id: int):
    return {"message": "Customer updated"}


@app.delete("/customers/{customer_id}")
def delete_customer(customer_id: int):
    return {"message": "Customer deleted"}
```

Meaning:

```text
GET     → Read
POST    → Create
PUT     → Replace
PATCH   → Partial update
DELETE  → Delete
```

## 4. Path Parameters

Path parameters identify a specific resource.

```python
from fastapi import FastAPI

app = FastAPI()


@app.get("/customers/{customer_id}")
def get_customer(customer_id: int):
    return {
        "customer_id": customer_id
    }
```

Request:

```text
GET /customers/101
```

FastAPI converts:

```text
"101"
```

into:

```python
101
```

because of:

```python
customer_id: int
```

If the client sends an invalid value:

```text
GET /customers/abc
```

FastAPI returns a validation error.

## 5. Query Parameters

Query parameters appear after `?`.

```python
from fastapi import FastAPI

app = FastAPI()


@app.get("/customers")
def get_customers(
    country: str = "Ireland",
    limit: int = 10
):
    return {
        "country": country,
        "limit": limit
    }
```

Request:

```text
GET /customers?country=Ireland&limit=20
```

FastAPI gives:

```python
country = "Ireland"
limit = 20
```

Common uses:

```text
Filtering
Searching
Sorting
Pagination
Optional parameters
```

## 6. Optional Query Parameters

Use `None` when a parameter is optional.

```python
from fastapi import FastAPI

app = FastAPI()


@app.get("/customers")
def get_customers(
    country: str | None = None,
    age: int | None = None
):
    return {
        "country": country,
        "age": age
    }
```

Possible request:

```text
/customers
```

or:

```text
/customers?country=Ireland
```

or:

```text
/customers?country=Ireland&age=30
```

## 7. Request Body

For POST/PUT/PATCH requests, data is commonly sent in the request body.

FastAPI commonly uses **Pydantic models** to define and validate the body.

```python
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()


class Customer(BaseModel):
    name: str
    email: str
    age: int


@app.post("/customers")
def create_customer(customer: Customer):
    return {
        "name": customer.name,
        "email": customer.email,
        "age": customer.age
    }
```

Client sends:

```json
{
    "name": "John",
    "email": "john@example.com",
    "age": 30
}
```

FastAPI/Pydantic:

```text
JSON
 ↓
Pydantic model
 ↓
Validation
 ↓
Python object
 ↓
Endpoint function
```

## 8. Pydantic `BaseModel`

`BaseModel` comes from Pydantic.

```python
from pydantic import BaseModel


class Customer(BaseModel):
    name: str
    email: str
    age: int
```

It defines the expected data structure.

It is used for:

```text
Validation
Parsing
Serialization
API schemas
```

It does **not** automatically represent a database table.

## 9. Validation

Suppose:

```python
class Customer(BaseModel):
    name: str
    email: str
    age: int
```

Valid:

```json
{
    "name": "John",
    "email": "john@example.com",
    "age": 30
}
```

Invalid because `age` is missing:

```json
{
    "name": "John",
    "email": "john@example.com"
}
```

Invalid:

```json
{
    "name": "John",
    "email": "john@example.com",
    "age": "hello"
}
```

FastAPI returns a validation error and the endpoint function does not execute.

## 10. Response Models

A response model defines what the API should return.

```python
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()


class CustomerResponse(BaseModel):
    id: int
    name: str
    email: str


@app.get(
    "/customers/{customer_id}",
    response_model=CustomerResponse
)
def get_customer(customer_id: int):

    return {
        "id": customer_id,
        "name": "John",
        "email": "john@example.com",
        "password": "secret123"
    }
```

The response model only exposes:

```text
id
name
email
```

The password is not included.

`response_model` is useful for:

* Response validation
* Consistent API contracts
* Filtering unwanted fields
* Documentation

## 11. Separate Create and Response Models

A good API commonly uses different models for input and output.

```python
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()


class CustomerCreate(BaseModel):
    name: str
    email: str
    age: int


class CustomerResponse(BaseModel):
    id: int
    name: str
    email: str
    age: int


@app.post(
    "/customers",
    response_model=CustomerResponse
)
def create_customer(customer: CustomerCreate):

    return {
        "id": 1,
        "name": customer.name,
        "email": customer.email,
        "age": customer.age
    }
```

This prevents internal/database fields from automatically becoming part of the public API contract.

## 13. HTTPException

```python
def get_customer(customer_id: int):

    customer = None

    if customer is None:
        raise HTTPException(
            status_code=404,
            detail="Customer not found"
        )

    return customer
```

```json
{
```

## 14. CRUD

CRUD means:

```text
Create
Read
Update
Delete
```

Typical REST API:

```text
POST   /customers
GET    /customers
GET    /customers/{id}
PUT    /customers/{id}
PATCH  /customers/{id}
DELETE /customers/{id}
```

Example:

```python
from fastapi import FastAPI, HTTPException

app = FastAPI()

customers = {}


@app.post("/customers")
def create_customer(name: str):
    customer_id = len(customers) + 1

    customers[customer_id] = {
        "id": customer_id,
        "name": name
    }

    return customers[customer_id]


@app.get("/customers/{customer_id}")
def get_customer(customer_id: int):

    customer = customers.get(customer_id)

    if customer is None:
        raise HTTPException(
            status_code=404,
            detail="Customer not found"
        )

    return customer


@app.delete("/customers/{customer_id}")
def delete_customer(customer_id: int):

    if customer_id not in customers:
        raise HTTPException(
            status_code=404,
            detail="Customer not found"
        )

    del customers[customer_id]

    return {"message": "Customer deleted"}
```

## 15. PUT vs PATCH

### PUT

Usually represents replacing the resource.

```text
PUT /customers/101
```

The client generally sends the complete representation.

### PATCH

Usually represents a partial update.

```text
PATCH /customers/101
```

The client can send only the fields that need to change.

Example:

```json
{
    "email": "new@example.com"
}
```

## 16. Pagination

Never return millions of records from an API in one response.

A simple pagination approach:

```python
from fastapi import FastAPI

app = FastAPI()


@app.get("/customers")
def get_customers(
    page: int = 1,
    page_size: int = 100
):

    offset = (page - 1) * page_size

    return fetch_customers(
        offset=offset,
        limit=page_size
    )
```

Formula:

```text
offset = (page - 1) × page_size
```

For very large datasets, cursor/keyset pagination can be more efficient than large offsets.

## 18. Async and Await

FastAPI supports asynchronous endpoints.

```python
from fastapi import FastAPI

app = FastAPI()


@app.get("/customers")
async def get_customers():

    result = await fetch_from_database()

    return result
```

Use async when the underlying operations are asynchronous.

For example:

```text
async database driver
async HTTP client
async network operations
```

Making a function `async` does not automatically make blocking code asynchronous.

---

## 19. Synchronous vs Asynchronous Endpoint

Synchronous:

```python
@app.get("/customers")
def get_customers():
    return fetch_data()
```

Asynchronous:

```python
@app.get("/customers")
async def get_customers():
    return await fetch_data_async()
```

The important rule is:

```text
Async endpoint
      ↓
Use async-compatible I/O
```

Do not assume:

```python
async def
```

automatically makes every operation non-blocking.

## 20. Dependency Injection

FastAPI provides dependency injection through `Depends`.

```python
from fastapi import FastAPI, Depends

app = FastAPI()


def get_current_user():
    return {
        "id": 101,
        "name": "John"
    }


@app.get("/profile")
def profile(
    user=Depends(get_current_user)
):
    return user
```

FastAPI calls:

```text
get_current_user()
       ↓
Depends(...)
       ↓
profile()
```

Dependencies are useful for:

```text
Authentication
Authorization
Database sessions
Common parameters
Reusable business logic
Permissions
```

## 21. Database Dependency

A common pattern is creating a database session per request.

```python
from fastapi import FastAPI, Depends

app = FastAPI()


def get_db():

    db = create_database_session()

    try:
        yield db

    finally:
        db.close()


@app.get("/customers")
def get_customers(
    db=Depends(get_db)
):

    return db.query(Customer).all()
```

The important lifecycle is:

```text
Request
 ↓
Create DB session
 ↓
Endpoint uses session
 ↓
Request completes
 ↓
Close session
```

## 22. Authentication

Authentication answers:

> Who are you?

Authorization answers:

> What are you allowed to do?

A common API authentication approach is:

```text
Login
 ↓
Username/password
 ↓
Validate credentials
 ↓
Create access token
 ↓
Client sends token
 ↓
API validates token
```

FastAPI provides security utilities such as OAuth2 helpers.

Example:

```python
from fastapi import FastAPI, Depends
from fastapi.security import OAuth2PasswordBearer

app = FastAPI()

oauth2_scheme = OAuth2PasswordBearer(
    tokenUrl="token"
)


@app.get("/profile")
def profile(
    token: str = Depends(oauth2_scheme)
):

    return {
        "token": token
    }
```

In a real application, the token must be properly validated.

## 23. JWT

JWT stands for **JSON Web Token**.

A common flow:

```text
Client
  ↓
Login
  ↓
Server validates credentials
  ↓
Server creates JWT
  ↓
Client stores token
  ↓
Client sends:
Authorization: Bearer <token>
  ↓
Server validates token
  ↓
Request allowed
```

JWT commonly contains claims such as:

```text
sub
exp
iat
```

Never put sensitive secrets/passwords inside a JWT payload simply because it is encoded.

## 24. Middleware

Middleware runs around requests.

```python
from fastapi import FastAPI, Request

app = FastAPI()


@app.middleware("http")
async def log_requests(
    request: Request,
    call_next
):

    print(
        "Request:",
        request.method,
        request.url
    )

    response = await call_next(request)

    print(
        "Status:",
        response.status_code
    )

    return response
```

Flow:

```text
Request
   ↓
Middleware
   ↓
Endpoint
   ↓
Middleware
   ↓
Response
```

Common uses:

```text
Logging
Request timing
Request IDs
CORS
Security-related processing
```

## 25. CORS

CORS means **Cross-Origin Resource Sharing**.

It controls which browser origins can make requests to your API.

Example:

```python
from fastapi import FastAPI
from fastapi.middleware.cors import CORSMiddleware

app = FastAPI()


app.add_middleware(
    CORSMiddleware,
    allow_origins=[
        "https://example.com"
    ],
    allow_methods=["*"],
    allow_headers=["*"]
)
```

In production, avoid blindly allowing every origin.

## 26. Routers

As the application grows, don't put every endpoint in `main.py`.

Project structure:

```text
project/
│
├── main.py
│
├── routers/
│   ├── customers.py
│   └── orders.py
│
├── services/
│   ├── customer_service.py
│   └── order_service.py
│
├── repositories/
│   └── customer_repository.py
│
└── models/
    └── customer.py
```

Router:

```python
from fastapi import APIRouter

router = APIRouter()


@router.get("/customers")
def get_customers():
    return {"customers": []}
```

Main application:

```python
from fastapi import FastAPI
from routers.customers import router as customer_router

app = FastAPI()

app.include_router(customer_router)
```

Routers help organize large applications.

## 27. Service Layer

The service layer contains business logic.

Instead of:

```text
Router
 ↓
Database
```

use:

```text
Router
 ↓
Service
 ↓
Repository
 ↓
Database
```

Example:

```python
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()


class CustomerCreate(BaseModel):
    name: str
    email: str


class CustomerService:

    def create(self, customer):
        return {
            "id": 1,
            "name": customer.name,
            "email": customer.email
        }


customer_service = CustomerService()


@app.post("/customers")
def create_customer(
    customer: CustomerCreate
):

    return customer_service.create(customer)
```

The endpoint should ideally remain thin.

## 28. Repository Layer

The repository handles database access.

Architecture:

```text
HTTP Request
     ↓
Router
     ↓
Service
     ↓
Repository
     ↓
Database
```

Example:

```python
class CustomerRepository:

    def save(self, customer):
        # database operation
        return customer

    def find_by_id(self, customer_id):
        # database query
        return None
```

The service can then use the repository:

```python
class CustomerService:

    def __init__(self, repository):
        self.repository = repository

    def create(self, customer):
        return self.repository.save(customer)
```

## 29. Error Handling

You can handle specific application exceptions globally.

```python
from fastapi import FastAPI, Request
from fastapi.responses import JSONResponse

app = FastAPI()


@app.exception_handler(ValueError)
async def value_error_handler(
    request: Request,
    exc: ValueError
):

    return JSONResponse(
        status_code=400,
        content={
            "detail": str(exc)
        }
    )
```

Then:

```python
raise ValueError("Invalid customer")
```

can be converted into a controlled HTTP response.

## 31. BackgroundTasks

FastAPI provides lightweight background tasks.

```python
from fastapi import FastAPI, BackgroundTasks

app = FastAPI()


def write_log(message):
    print(message)


@app.post("/customers")
def create_customer(
    background_tasks: BackgroundTasks
):

    background_tasks.add_task(
        write_log,
        "Customer created"
    )

    return {
        "message": "Created"
    }
```

The response can be returned without waiting for the background task.

For serious durable workloads such as large ETL jobs, use a proper task queue/orchestration system rather than relying only on FastAPI `BackgroundTasks`.

## 38. FastAPI + ETL

A common mistake is putting a huge ETL job directly inside a normal HTTP request.

Instead of:

```text
POST /run-etl
      ↓
HTTP request waits
      ↓
2-hour ETL
      ↓
response
```

a better design is:

```text
POST /etl/jobs
      ↓
Create job
      ↓
Return job_id
      ↓
Background worker / queue / orchestrator
      ↓
ETL runs
      ↓
GET /etl/jobs/{job_id}
      ↓
Check status
```

Example:

```python
from fastapi import FastAPI

app = FastAPI()


@app.post("/etl/jobs")
def start_etl_job():

    job_id = "12345"

    # Submit job to a worker/queue/orchestrator.

    return {
        "job_id": job_id,
        "status": "started"
    }


@app.get("/etl/jobs/{job_id}")
def get_job_status(job_id: str):

    return {
        "job_id": job_id,
        "status": "running"
    }
```

This separates the API layer from the long-running ETL workload.

## 39. FastAPI + Async vs Threads

For async-compatible I/O:

```python
@app.get("/customer")
async def customer():

    result = await async_api_call()

    return result
```

For blocking synchronous I/O, threads can sometimes be appropriate.

The important distinction is:

```text
Async I/O
→ async/await

Blocking I/O
→ threads can help

CPU-heavy Python work
→ multiprocessing / separate workers
```

Don't blindly create a new thread for every request.

## 40. Complete FastAPI Example

This combines several important concepts:

```python
from fastapi import FastAPI, HTTPException, status
from pydantic import BaseModel


app = FastAPI()


class CustomerCreate(BaseModel):
    name: str
    email: str
    age: int


class CustomerResponse(BaseModel):
    id: int
    name: str
    email: str
    age: int


customers = {}


@app.post(
    "/customers",
    response_model=CustomerResponse,
    status_code=status.HTTP_201_CREATED
)
def create_customer(
    customer: CustomerCreate
):

    customer_id = len(customers) + 1

    new_customer = {
        "id": customer_id,
        "name": customer.name,
        "email": customer.email,
        "age": customer.age
    }

    customers[customer_id] = new_customer

    return new_customer


@app.get(
    "/customers/{customer_id}",
    response_model=CustomerResponse
)
def get_customer(
    customer_id: int
):

    customer = customers.get(customer_id)

    if customer is None:

        raise HTTPException(
            status_code=404,
            detail="Customer not found"
        )

    return customer


@app.patch(
    "/customers/{customer_id}",
    response_model=CustomerResponse
)
def update_customer(
    customer_id: int,
    customer: CustomerCreate
):

    if customer_id not in customers:

        raise HTTPException(
            status_code=404,
            detail="Customer not found"
        )

    updated_customer = {
        "id": customer_id,
        "name": customer.name,
        "email": customer.email,
        "age": customer.age
    }

    customers[customer_id] = updated_customer

    return updated_customer


@app.delete(
    "/customers/{customer_id}",
    status_code=status.HTTP_204_NO_CONTENT
)
def delete_customer(
    customer_id: int
):

    if customer_id not in customers:

        raise HTTPException(
            status_code=404,
            detail="Customer not found"
        )

    del customers[customer_id]
```

## 8. Rate limiter

**File: `app/rate_limiter.py`**

```python
import time

from collections import defaultdict, deque
from threading import Lock

from fastapi import HTTPException, status

from app.config import RATE_LIMIT, RATE_LIMIT_WINDOW


request_history = defaultdict(deque)
rate_limit_lock = Lock()


def check_rate_limit(client_ip: str):
    current_time = time.time()
    window_start = current_time - RATE_LIMIT_WINDOW

    with rate_limit_lock:
        requests = request_history[client_ip]

        while requests and requests[0] <= window_start:
            requests.popleft()

        if len(requests) >= RATE_LIMIT:
            retry_after = max(
                1,
                int(
                    RATE_LIMIT_WINDOW -
                    (current_time - requests[0])
                )
            )

            raise HTTPException(
                status_code=status.HTTP_429_TOO_MANY_REQUESTS,
                detail="Rate limit exceeded. Try again later.",
                headers={
                    "Retry-After": str(retry_after)
                }
            )

        requests.append(current_time)

        return RATE_LIMIT - len(requests)
```

**Explanation:**

Rate limiting controls how many requests a client can make within a specific time period.

Our configuration allows:

- 100 requests
- Within 60 seconds
- Per client IP address

We use:

- `defaultdict`: Stores request history for each IP.
- `deque`: Stores request timestamps efficiently.
- `Lock`: Prevents concurrent requests from modifying the same tracking structure at the same time.
- `time.time()`: Records request timestamps.

When the request limit is exceeded, the API returns:

```http
429 Too Many Requests
```

The `Retry-After` header tells the client how many seconds to wait before retrying.

**Important:** This is an in-memory, single-process implementation for learning and small deployments. For multiple workers or servers, use a shared rate-limit store such as Redis. Also configure trusted proxy handling before relying on client IP addresses behind a reverse proxy.

## 9. Middleware

**File: `app/middleware.py`**

```python
import logging
import time
import uuid

from fastapi import Request
from fastapi.responses import JSONResponse

from app.config import RATE_LIMIT
from app.rate_limiter import check_rate_limit


logger = logging.getLogger(__name__)


async def request_middleware(request: Request, call_next):
    request_id = str(uuid.uuid4())
    start_time = time.perf_counter()

    client_ip = (
        request.client.host
        if request.client
        else "unknown"
    )

    try:
        remaining_requests = check_rate_limit(client_ip)

    except Exception as exc:
        from fastapi import HTTPException

        if isinstance(exc, HTTPException):
            logger.warning(
                "Request rejected | ID: %s | IP: %s",
                request_id,
                client_ip
            )

            response = JSONResponse(
                status_code=exc.status_code,
                content={"detail": exc.detail},
                headers=exc.headers
            )

            response.headers["X-Request-ID"] = request_id
            response.headers["X-RateLimit-Limit"] = str(RATE_LIMIT)
            response.headers["X-RateLimit-Remaining"] = "0"

            return response

        raise

    try:
        response = await call_next(request)

        process_time = time.perf_counter() - start_time

        response.headers["X-Request-ID"] = request_id
        response.headers["X-Process-Time"] = str(
            round(process_time, 4)
        )

        response.headers["X-RateLimit-Limit"] = str(RATE_LIMIT)
        response.headers["X-RateLimit-Remaining"] = str(
            remaining_requests
        )

        response.headers["X-Content-Type-Options"] = "nosniff"
        response.headers["X-Frame-Options"] = "DENY"
        response.headers["Referrer-Policy"] = (
            "strict-origin-when-cross-origin"
        )

        logger.info(
            "Request completed | ID: %s | Method: %s | "
            "Path: %s | Status: %s | Time: %.4fs",
            request_id,
            request.method,
            request.url.path,
            response.status_code,
            process_time
        )

        return response

    except Exception:
        logger.exception(
            "Request failed | ID: %s | Method: %s | Path: %s",
            request_id,
            request.method,
            request.url.path
        )
        raise
```

**Explanation:**

Middleware executes automatically for incoming HTTP requests.

Our middleware performs several tasks:

1. Generates a unique request ID.
2. Records the request start time.
3. Checks the rate limit.
4. Passes allowed requests to the endpoint using `call_next()`.
5. Calculates request processing time.
6. Adds security and performance headers.
7. Logs request information.

If the rate limit is exceeded, middleware returns HTTP 429 directly.

We do not need to call middleware manually inside an endpoint.

## 10. External API service

**File: `app/services/external_api.py`**

```python
import logging
import httpx

from fastapi import HTTPException, status

from app.config import BASE_URL, API_TOKEN


logger = logging.getLogger(__name__)


def make_api_request(endpoint: str, client: httpx.Client):
    url = f"{BASE_URL}/{endpoint.lstrip('/')}"

    headers = {
        "Authorization": f"Bearer {API_TOKEN}",
        "Accept": "application/json"
    }

    try:
        logger.info(
            "Making GET request to %s",
            url
        )

        response = client.get(
            url,
            headers=headers
        )

        response.raise_for_status()

        logger.info(
            "External API request successful. Status: %s",
            response.status_code
        )

        return response.json()

    except httpx.TimeoutException:
        logger.exception(
            "External API request timed out"
        )

        raise HTTPException(
            status_code=status.HTTP_504_GATEWAY_TIMEOUT,
            detail="External API request timed out"
        )

    except httpx.ConnectError:
        logger.exception(
            "Unable to connect to external API"
        )

        raise HTTPException(
            status_code=status.HTTP_502_BAD_GATEWAY,
            detail="Unable to connect to external API"
        )

    except httpx.HTTPStatusError:
        logger.exception(
            "External API returned an HTTP error"
        )

        raise HTTPException(
            status_code=status.HTTP_502_BAD_GATEWAY,
            detail="External API returned an error"
        )

    except httpx.RequestError:
        logger.exception(
            "External API request failed"
        )

        raise HTTPException(
            status_code=status.HTTP_502_BAD_GATEWAY,
            detail="External API request failed"
        )

    except ValueError:
        logger.exception(
            "External API returned invalid JSON"
        )

        raise HTTPException(
            status_code=status.HTTP_502_BAD_GATEWAY,
            detail="External API returned invalid JSON"
        )
```

**Explanation:**

This file handles communication with the external API.

The `make_api_request()` function:

- Builds the external URL.
- Adds the external API Bearer token.
- Sends the GET request.
- Checks the HTTP response.
- Converts the response into JSON.
- Handles timeout, connection, HTTP, and JSON errors.

Keeping external API logic separate makes it easier to reuse and maintain.

```python
from fastapi import (

from sqlalchemy.orm import Session

from app.schemas import (
    PostResponse,

from app.services.external_api import make_api_request


router = APIRouter()


@router.get(
    "/posts/{post_id}",
    response_model=PostResponse,
    status_code=status.HTTP_200_OK
)
def get_posts(
    request: Request,
    post_id: int = Path(
        ...,
        gt=0,
        description="Post ID must be greater than zero",
        examples=[1]
    )
):
    client = request.app.state.http_client

    return make_api_request(
        f"/posts/{post_id}",
        client
    )


@router.get(
    "/db-check",
    response_model=DBCheckResponse,
    status_code=status.HTTP_200_OK
)
def db_check(
    db: Session = Depends(get_db)
):
    result = check_database_connection(db)

    return {
        "database_connected": result
    }


@router.get(
    "/get-request",
    response_model=GetRequestResponse,
    status_code=status.HTTP_200_OK
)
def get_request(
    request: Request,
    authenticated: str = Depends(verify_authentication),
    query: str | None = Query(
        default=None,
        description="Search posts by title or body"
    ),
    page: int = Query(
        default=1,
        ge=1
    ),
    limit: int = Query(
        default=10,
        ge=1,
        le=100
    )
):
    client = request.app.state.http_client

    posts = make_api_request(
        "/posts",
        client
    )

    if query:
        search_query = query.lower()

        posts = [
            post for post in posts
            if search_query in post["title"].lower()
            or search_query in post["body"].lower()
        ]

    total = len(posts)

    skip = (page - 1) * limit

    paginated_posts = posts[
        skip:skip + limit
    ]

    return {
        "total": total,
        "skip": skip,
        "limit": limit,
        "data": paginated_posts
    }
```

**Explanation:**

The router contains the application's API endpoints.


Checks whether the database connection works.

### Endpoint 3: Get requests

```http

```

**Query parameter:**

A query parameter passes optional information through the URL.

Example:

**Pagination:**

Pagination divides a large result set into smaller pages.

```python
import logging

import httpx

from contextlib import asynccontextmanager

from fastapi import FastAPI
from fastapi.middleware.cors import CORSMiddleware

from app.config import ALLOWED_ORIGINS
from app.middleware import request_middleware
from app.routers.posts import router

    level=logging.INFO,
    format=(
        "%(asctime)s - %(name)s - "
        "%(levelname)s - %(message)s"
    )
)


@asynccontextmanager
async def lifespan(app: FastAPI):
    with httpx.Client(
        timeout=10,
        limits=httpx.Limits(
            max_connections=100,
            max_keepalive_connections=20
        )
    ) as client:
        app.state.http_client = client
        yield


app = FastAPI(
    lifespan=lifespan
)


app.add_middleware(
    CORSMiddleware,
    allow_origins=ALLOWED_ORIGINS,
    allow_credentials=False,
    allow_methods=["GET"],
    allow_headers=[
        "Authorization",
        "Content-Type",
        "Accept"
    ],
    expose_headers=[
        "X-Request-ID",
        "X-Process-Time",
        "X-RateLimit-Limit",
        "X-RateLimit-Remaining"
    ]
)


app.middleware("http")(request_middleware)


app.include_router(router)
```

**Explanation:**

This is the entry point of the application.

It connects all the separate components.

- Creates the FastAPI application.
- Configures the HTTPX client.
- Configures CORS.
- Registers middleware.
- Includes the API router.

### What is lifespan?

Lifespan manages resources when the application starts and stops.

We create one reusable HTTPX client when FastAPI starts.

The client is closed automatically when the application shuts down.

This avoids creating a new HTTP client for every external API request.

### What is CORS?

CORS stands for Cross-Origin Resource Sharing.

It controls which frontend origins can access the API from a browser.

Our configuration currently allows the two localhost frontend origins listed in `config.py`.

# 43. Interview Questions

### Q1. What is FastAPI?

> FastAPI is a modern Python web framework for building APIs. It uses Python type hints, Pydantic validation, ASGI, and automatically generates OpenAPI documentation.

### Q2. What is Pydantic `BaseModel`?

> `BaseModel` is used to define structured data models and validate/parse request and response data.

### Q3. What is dependency injection in FastAPI?

> FastAPI's dependency injection system allows reusable components such as authentication, database sessions, and common logic to be provided to endpoints using `Depends`.

### Q4. What is middleware?

> Middleware runs around the request/response lifecycle and is useful for concerns such as logging, request IDs, timing, and CORS.

### Q5. Difference between PUT and PATCH?

> PUT generally represents replacing a resource, while PATCH is used for partial updates.

### Q6. Difference between 401 and 403?

> 401 means the request has not been properly authenticated. 403 means the client is authenticated but does not have permission to perform the operation.

### Q7. How does FastAPI validate requests?

> FastAPI uses type hints and Pydantic models to parse and validate path parameters, query parameters, and request bodies before calling the endpoint.

### Q8. Why use `response_model`?

> It defines the expected response schema, validates the response, improves API documentation, and can prevent unwanted fields from being exposed.

### Q9. Why use routers?

> Routers allow a large FastAPI application to be split into modular groups of endpoints instead of putting everything in one file.

### Q10. How would you structure a production FastAPI application?

> I would separate routers, schemas/models, services, repositories, configuration, authentication, and database access. The router handles HTTP concerns, the service contains business logic, and the repository handles data access.

### Q11. When would you use async in FastAPI?

> I would use async endpoints when the underlying operations are asynchronous, particularly for high-concurrency I/O such as asynchronous database or HTTP calls.

### Q12. Would you run a 2-hour ETL job directly inside a FastAPI request?

> No. I would normally submit the ETL job to a background worker, queue, or orchestration system, return a job ID, and provide another endpoint for checking job status.

### Q13. How would you handle a large file upload?

> I would avoid loading the entire file into memory. I would process or stream the file incrementally and apply appropriate size limits and validation.

### Q14. How do you secure API credentials?

> I would not hardcode secrets. I would use environment variables or a dedicated secret-management system and restrict access appropriately.

### Q15. How do you test a FastAPI API?

> I would use FastAPI's `TestClient` with pytest to test status codes, response bodies, validation errors, authentication, and important business scenarios.
