# Python Requests – Complete Guide from Beginner to Production

## 1. What is the Python Requests Library?

The `requests` library is a third-party Python package used to send HTTP requests to servers and receive HTTP responses.

For example, imagine you have a Django application that needs to communicate with an external payment gateway.

Your Django application sends a request:

```python
import requests

response = requests.get(
    "https://api.example.com/users"
)

print(response.status_code)
print(response.text)
```

The external server processes the request and returns a response.

Requests makes this communication simple without requiring you to manually manage low-level HTTP details.

### Common use cases

- Calling third-party REST APIs.
- Communicating between microservices.
- Integrating payment gateways.
- Sending notifications through external services.
- Downloading files and images.
- Uploading documents.
- Integrating authentication providers.
- Fetching data from external systems.
- Automating HTTP-based workflows.

## 3. Understanding HTTP Methods

HTTP methods define what operation your application wants to perform on a server.

The most commonly used methods are:

| Method | Purpose |
|---|---|
| GET | Retrieve information |
| POST | Create a resource or submit data |
| PUT | Replace an existing resource |
| PATCH | Partially update a resource |
| DELETE | Delete a resource |
| HEAD | Retrieve response headers |
| OPTIONS | Discover supported operations |

### GET request

Used to retrieve information.

```python
import requests

url = "https://jsonplaceholder.typicode.com/users"

response = requests.get(url)

print(response.status_code)
print(response.json())
```

### POST request

Used to submit data or create a resource.

```python
import requests

url = "https://jsonplaceholder.typicode.com/posts"

payload = {
    "title": "Django Tutorial",
    "body": "Learning Python Requests",
    "userId": 1
}

response = requests.post(
    url,
    json=payload
)

print(response.status_code)
print(response.json())
```

### PUT request

Used to replace an existing resource.

```python
import requests

url = "https://jsonplaceholder.typicode.com/posts/1"

payload = {
    "id": 1,
    "title": "Updated Title",
    "body": "Updated content",
    "userId": 1
}

response = requests.put(
    url,
    json=payload
)

print(response.status_code)
print(response.json())
```

### PATCH request

Used to update only selected fields.

```python
import requests

url = "https://jsonplaceholder.typicode.com/posts/1"

payload = {
    "title": "Partially Updated Title"
}

response = requests.patch(
    url,
    json=payload
)

print(response.status_code)
print(response.json())
```

### DELETE request

Used to delete a resource.

```python
import requests

url = "https://jsonplaceholder.typicode.com/posts/1"

response = requests.delete(url)

print(response.status_code)
```

Important: PUT generally replaces a resource, whereas PATCH modifies selected fields. Actual API behavior depends on the API implementation.

## 4. Understanding HTTP Status Codes

An HTTP response contains a status code indicating the result of the request.

### Successful responses

| Status | Meaning |
|---|---|
| 200 | OK |
| 201 | Created |
| 202 | Accepted |
| 204 | No Content |

### Client errors

| Status | Meaning |
|---|---|
| 400 | Bad Request |
| 401 | Unauthorized |
| 403 | Forbidden |
| 404 | Not Found |
| 405 | Method Not Allowed |
| 409 | Conflict |
| 422 | Unprocessable Content |
| 429 | Too Many Requests |

### Server errors

| Status | Meaning |
|---|---|
| 500 | Internal Server Error |
| 502 | Bad Gateway |
| 503 | Service Unavailable |
| 504 | Gateway Timeout |

Example:

```python
import requests

response = requests.get(
    "https://jsonplaceholder.typicode.com/users"
)

if response.status_code == 200:
    print("Request successful")

elif response.status_code == 404:
    print("Resource not found")

elif response.status_code >= 500:
    print("Server error")

else:
    print("Unexpected response")
```

A successful HTTP response does not necessarily mean the business operation succeeded. Always understand the API's response contract.

## 5. Understanding Response Object

When you make a request using `requests`, it returns a Response object.

```python
response = requests.get(
    "https://jsonplaceholder.typicode.com/users"
)
```

Important response properties:

### status_code

Returns the HTTP status code.

```python
print(response.status_code)
```

### text

Returns the response body as text.

```python
print(response.text)
```

### json()

Converts a JSON response into Python objects.

```python
data = response.json()

print(data)
```

For example, JSON:

```json
{
    "id": 1,
    "name": "John",
    "email": "john@example.com"
}
```

Becomes a Python dictionary:

```python
{
    "id": 1,
    "name": "John",
    "email": "john@example.com"
}
```

### headers

Returns response headers.

```python
print(response.headers)

print(response.headers.get("Content-Type"))
```

### url

Returns the final URL.

```python
print(response.url)
```

### encoding

Returns the detected response encoding.

```python
print(response.encoding)
```

### elapsed

Returns the time taken for the request.

```python
print(response.elapsed.total_seconds())
```

### cookies

Returns cookies received from the server.

```python
print(response.cookies)
```

## 6. Query Parameters

Query parameters are values passed through the URL to filter or retrieve specific information.

Example URL:

```text
https://api.example.com/users?page=2&limit=10
```

Using Requests:

```python
import requests

url = "https://api.example.com/users"

params = {
    "page": 2,
    "limit": 10
}

response = requests.get(
    url,
    params=params
)

print(response.url)
```

Requests automatically constructs the query string.

### Practical example

Retrieve users based on a search term:

```python
params = {
    "search": "john",
    "status": "active"
}

response = requests.get(
    "https://api.example.com/users",
    params=params
)
```

This is useful for pagination, filtering, searching, and sorting.

## 7. Sending JSON Data

Most modern REST APIs communicate using JSON.

Use the `json` parameter when sending JSON data.

```python
import requests

url = "https://api.example.com/users"

payload = {
    "name": "John",
    "email": "john@example.com"
}

response = requests.post(
    url,
    json=payload
)

print(response.status_code)
print(response.json())
```

Requests automatically serializes the Python dictionary into JSON and sets an appropriate content type.

### Difference between json and data

Using `json`:

```python
requests.post(
    url,
    json={"name": "John"}
)
```

Sends JSON.

Using `data`:

```python
requests.post(
    url,
    data={"name": "John"}
)
```

Typically sends form-encoded data.

You can also send a manually serialized JSON string:

```python
import json

requests.post(
    url,
    data=json.dumps({"name": "John"}),
    headers={
        "Content-Type": "application/json"
    }
)
```

Prefer `json=` for normal JSON APIs.

## 9. Authentication

Requests supports several authentication mechanisms.

### Basic Authentication

Basic authentication sends a username and password using HTTP authentication.

```python
import requests
from requests.auth import HTTPBasicAuth

response = requests.get(
    "https://api.example.com/profile",
    auth=HTTPBasicAuth(
        "username",
        "password"
    )
)
```

Shortcut:

```python
response = requests.get(
    "https://api.example.com/profile",
    auth=("username", "password")
)
```

Use HTTPS because Basic Authentication is not encryption by itself.

### Bearer Token Authentication

Commonly used with OAuth2 and JWT-based APIs.

```python
token = "YOUR_ACCESS_TOKEN"

headers = {
    "Authorization": f"Bearer {token}"
}

response = requests.get(
    "https://api.example.com/profile",
    headers=headers
)
```

### API Key Authentication

Some APIs expect an API key in the headers.

```python
headers = {
    "X-API-Key": "YOUR_API_KEY"
}

response = requests.get(
    "https://api.example.com/data",
    headers=headers
)
```

Others expect the API key in a query parameter:

```python
params = {
    "api_key": "YOUR_API_KEY"
}

response = requests.get(
    "https://api.example.com/data",
    params=params
)
```

Use the authentication method documented by the external API.

## 10. Error Handling and Exceptions

In real-world applications, API requests can fail for many reasons:

- Network connection problems.
- Connection timeouts.
- Invalid URLs.
- Authentication failures.
- Server errors.
- Invalid JSON responses.

Requests provides exception classes for handling these problems.

### Common exceptions

| Exception | Meaning |
|---|---|
| RequestException | Base exception |
| ConnectionError | Connection failed |
| Timeout | Request timed out |
| HTTPError | HTTP error response |
| TooManyRedirects | Too many redirects |
| InvalidURL | Invalid URL |

### Using try-except

```python
import requests

try:
    response = requests.get(
        "https://api.example.com/users",
        timeout=10
    )

    response.raise_for_status()

    data = response.json()

    print(data)

except requests.exceptions.Timeout:
    print("Request timed out")

except requests.exceptions.ConnectionError:
    print("Connection failed")

except requests.exceptions.HTTPError as error:
    print("HTTP error:", error)

except requests.exceptions.RequestException as error:
    print("Request failed:", error)
```

### Understanding raise_for_status()

This method raises an HTTPError if the server returns a 4xx or 5xx response.

Without it:

```python
response = requests.get(url)

print(response.status_code)
```

The code continues even if the server returns HTTP 500.

With it:

```python
response = requests.get(url)

response.raise_for_status()
```

An HTTPError is raised for unsuccessful HTTP status codes.

Important: `raise_for_status()` does not treat every non-2xx response as an error. For example, a 3xx response that is returned rather than followed is not automatically an HTTPError.

## 11. Timeout Handling

Timeouts are extremely important in production applications.

Consider a Django API calling an external payment service.

If the external service becomes slow, your Django worker could remain occupied while waiting for the response.

Without a timeout:

```python
response = requests.get(url)
```

The request can wait indefinitely from the application's perspective.

With a timeout:

```python
response = requests.get(
    url,
    timeout=10
)
```

The request has a timeout limit.

### Connect timeout and read timeout

You can specify them separately:

```python
response = requests.get(
    url,
    timeout=(3, 10)
)
```

Meaning:

- 3 seconds for connection establishment.
- 10 seconds for waiting for response data.

A Requests timeout is not necessarily a strict total deadline for the entire operation. The read timeout generally limits the wait between incoming bytes.

Production applications should always define suitable timeouts.

## 12. Session Management

A Session object allows multiple requests to share configuration and persist cookies.

Without a session:

```python
import requests

response1 = requests.get(url1)
response2 = requests.get(url2)
```

With a session:

```python
import requests

session = requests.Session()

session.headers.update({
    "Authorization": "Bearer YOUR_TOKEN",
    "Accept": "application/json"
})

response1 = session.get(url1)
response2 = session.get(url2)
```

### Advantages of Sessions

1. Reuses underlying connections through connection pooling.
2. Maintains cookies across requests.
3. Shares common headers.
4. Shares authentication configuration.
5. Reduces repeated configuration.

### Session with context manager

Recommended pattern:

```python
import requests

with requests.Session() as session:

    session.headers.update({
        "Accept": "application/json"
    })

    response = session.get(
        "https://api.example.com/users",
        timeout=10
    )

    response.raise_for_status()

    print(response.json())
```

A session is useful when making multiple requests to the same service.

Do not blindly share a mutable Session object across unrelated concurrent tasks or threads.

## 13. Uploading Files

Requests supports file uploads using the `files` parameter.

Example:

```python
import requests

url = "https://api.example.com/upload"

with open("document.pdf", "rb") as file:

    response = requests.post(
        url,
        files={
            "file": file
        },
        timeout=30
    )

    response.raise_for_status()

    print(response.json())
```

### Upload file with additional data

```python
with open("document.pdf", "rb") as file:

    response = requests.post(
        url,
        files={
            "document": (
                "document.pdf",
                file,
                "application/pdf"
            )
        },
        data={
            "category": "invoice"
        },
        timeout=30
    )
```

Requests automatically generates the multipart form-data boundary.

Do not manually set the multipart Content-Type header when using `files=`.

## 14. Downloading Files

Requests can download files from external services.

Basic example:

```python
import requests

url = "https://example.com/report.pdf"

response = requests.get(
    url,
    timeout=30
)

response.raise_for_status()

with open("report.pdf", "wb") as file:
    file.write(response.content)
```

### Streaming large files

For large files, avoid loading the entire file into memory.

```python
import requests

url = "https://example.com/large-file.zip"

with requests.get(
    url,
    stream=True,
    timeout=(5, 30)
) as response:

    response.raise_for_status()

    with open("large-file.zip", "wb") as file:

        for chunk in response.iter_content(
            chunk_size=8192
        ):

            if chunk:
                file.write(chunk)
```

Streaming is especially useful when downloading large reports, backups, videos, or documents.

For production systems, also consider download-size limits, disk space, and cleanup of partially downloaded files.

## 17. SSL Certificate Verification

HTTPS uses TLS to secure communication.

Requests verifies SSL certificates by default.

Normal usage:

```python
response = requests.get(
    "https://api.example.com",
    timeout=10
)
```

For an internal service using a trusted private certificate authority:

```python
response = requests.get(
    "https://internal-api.example.com",
    verify="/path/to/ca-bundle.pem",
    timeout=10
)
```

Avoid this:

```python
requests.get(
    "https://api.example.com",
    verify=False
)
```

Disabling certificate verification makes the connection vulnerable to man-in-the-middle attacks.

It should not be used as a production workaround for certificate problems.

## 19. Retry Mechanism

External APIs can temporarily fail.

For example:

- HTTP 429: Rate limit exceeded.
- HTTP 500: Internal server error.
- HTTP 502: Bad gateway.
- HTTP 503: Service unavailable.
- HTTP 504: Gateway timeout.

Instead of immediately failing, some applications retry the request.

Requests can use urllib3 retry configuration through an HTTPAdapter.

```python
import requests

from requests.adapters import HTTPAdapter
from urllib3.util.retry import Retry

retry_strategy = Retry(
    total=3,
    backoff_factor=1,
    status_forcelist=[429, 500, 502, 503, 504],
    allowed_methods=["GET", "HEAD", "OPTIONS"],
    respect_retry_after_header=True
)

adapter = HTTPAdapter(
    max_retries=retry_strategy
)

session = requests.Session()

session.mount(
    "https://",
    adapter
)

session.mount(
    "http://",
    adapter
)

response = session.get(
    "https://api.example.com/users",
    timeout=(3, 10)
)

response.raise_for_status()

print(response.json())
```

### How does backoff work?

Retries should not happen immediately one after another.

A backoff strategy introduces increasing delays.

For example:

- First retry: approximately 1 second.
- Second retry: approximately 2 seconds.
- Third retry: approximately 4 seconds.

The exact behavior depends on the retry configuration and library version.

### Important production consideration

Do not blindly retry POST, PUT, PATCH, or DELETE requests.

A POST request might create a payment or order. Retrying it could create duplicate operations.

For retrying non-idempotent operations, use an API-supported idempotency key or another deduplication mechanism.

## 20. Pagination

Many APIs return large datasets in multiple pages.

Example API response:

```json
{
    "results": [
        {"id": 1, "name": "John"},
        {"id": 2, "name": "David"}
    ],
    "next": "https://api.example.com/users?page=2"
}
```

You can retrieve all pages by following the next URL.

```python
import requests

url = "https://api.example.com/users"

all_users = []

with requests.Session() as session:

    while url:

        response = session.get(
            url,
            timeout=10
        )

        response.raise_for_status()

        data = response.json()

        all_users.extend(data["results"])

        url = data.get("next")

print(all_users)
```

The pagination format depends on the external API.

Common approaches include:

- Page number pagination.
- Limit and offset pagination.
- Cursor-based pagination.
- Next URL pagination.

## 21. Working with Requests in Django

This is particularly important for Django developers.

Imagine you have a Django application that needs to retrieve customer information from an external CRM API.

### Example project structure

```text
myproject/
│
├── manage.py
│
├── myapp/
│   ├── views.py
│   ├── services.py
│   ├── urls.py
│   └── models.py
│
└── requirements.txt
```

A good practice is to separate external API communication from Django views.

### Step 1: Create a service file

`myapp/services.py`

```python
import requests

from django.conf import settings


class CRMService:

    BASE_URL = settings.CRM_API_URL

    @classmethod
    def get_customer(cls, customer_id):

        url = f"{cls.BASE_URL}/customers/{customer_id}"

        headers = {
            "Authorization": (
                f"Bearer {settings.CRM_API_TOKEN}"
            ),
            "Accept": "application/json"
        }

        try:

            response = requests.get(
                url,
                headers=headers,
                timeout=(3, 10)
            )

            response.raise_for_status()

            return response.json()

        except requests.exceptions.Timeout:

            raise Exception("CRM API timed out")

        except requests.exceptions.RequestException:

            raise Exception("Unable to communicate with CRM API")
```

### Step 2: Configure environment variables

`.env`

```text
CRM_API_URL=https://crm.example.com/api
CRM_API_TOKEN=your-secret-token
```

Django settings:

```python
import os

CRM_API_URL = os.environ["CRM_API_URL"]

CRM_API_TOKEN = os.environ["CRM_API_TOKEN"]
```

Use an appropriate environment-variable loader or deployment secrets manager.

Do not commit actual secrets to Git.

### Step 3: Call the service from a Django view

`myapp/views.py`

```python
from django.http import JsonResponse

from .services import CRMService


def customer_detail(request, customer_id):

    try:

        customer = CRMService.get_customer(
            customer_id
        )

        return JsonResponse(customer)

    except Exception:

        return JsonResponse(
            {
                "error": "Unable to fetch customer"
            },
            status=502
        )
```

### Why separate services from views?

A service layer provides:

1. Reusable API communication.
2. Cleaner Django views.
3. Easier unit testing.
4. Centralized authentication.
5. Centralized timeout and retry configuration.
6. Easier integration with multiple external APIs.

In production, use specific custom exceptions instead of catching every exception generically. Also avoid returning raw upstream errors or sensitive details to clients.

## 22. Complete Production-Style API Client

Below is an example of a reusable API client.

```python
import requests

from requests.adapters import HTTPAdapter
from urllib3.util.retry import Retry


class ExternalAPIClient:

    def __init__(self, base_url, token):

        self.base_url = base_url.rstrip("/")

        self.session = requests.Session()

        self.session.headers.update({
            "Authorization": f"Bearer {token}",
            "Accept": "application/json"
        })

        retry_strategy = Retry(
            total=3,
            backoff_factor=1,
            status_forcelist=[
                429,
                500,
                502,
                503,
                504
            ],
            allowed_methods=[
                "GET",
                "HEAD",
                "OPTIONS"
            ],
            respect_retry_after_header=True
        )

        adapter = HTTPAdapter(
            max_retries=retry_strategy
        )

        self.session.mount(
            "https://",
            adapter
        )

    def get(self, endpoint, params=None):

        url = f"{self.base_url}/{endpoint.lstrip('/')}"

        response = self.session.get(
            url,
            params=params,
            timeout=(3, 10)
        )

        response.raise_for_status()

        return response.json()

    def post(self, endpoint, payload):

        url = f"{self.base_url}/{endpoint.lstrip('/')}"

        response = self.session.post(
            url,
            json=payload,
            timeout=(3, 10)
        )

        response.raise_for_status()

        return response.json()

    def close(self):

        self.session.close()


# Usage

client = ExternalAPIClient(
    base_url="https://api.example.com",
    token="YOUR_TOKEN"
)

try:

    users = client.get("users")

    print(users)

finally:

    client.close()
```

This is a useful starting point. Production implementations should also include:

- Custom exception classes.
- Structured logging.
- Request correlation IDs.
- Response validation.
- Retry policies appropriate to each endpoint.
- Token refresh when required.
- Rate-limit handling.
- A clearly defined overall request deadline.
- Metrics and tracing.

Do not assume every POST response contains JSON. Some APIs return an empty response with status 204.

## 23. Requests vs Httpx vs Aiohttp

Python has several libraries for making HTTP requests.

| Feature | Requests | HTTPX | Aiohttp |
|---|---|---|---|
| Synchronous requests | Yes | Yes | Yes |
| Asynchronous requests | No | Yes | Yes |
| HTTP/2 support | No | Yes | Yes |
| Connection pooling | Yes | Yes | Yes |
| Session management | Yes | Yes | Yes |
| Common use | Synchronous APIs | Sync and async APIs | Async networking |

### Requests

Best suited for:

- Traditional Django applications.
- Management commands.
- Background workers.
- Scripts.
- Synchronous integrations.

### HTTPX

Best suited for:

- Async Django views.
- Applications requiring async and sync clients.
- HTTP/2 use cases.

Example:

```python
import httpx

response = httpx.get(
    "https://api.example.com/users",
    timeout=10
)

print(response.json())
```

### Async HTTPX example

```python
import asyncio
import httpx


async def get_users():

    async with httpx.AsyncClient() as client:

        response = await client.get(
            "https://api.example.com/users",
            timeout=10
        )

        response.raise_for_status()

        return response.json()


users = asyncio.run(get_users())
```

### Important Django consideration

Django supports both synchronous and asynchronous views.

Calling synchronous Requests directly inside an async view blocks the event loop while the request runs.

For genuinely asynchronous HTTP communication, consider HTTPX AsyncClient or aiohttp.

## 24. Requests in Microservices Architecture

Consider an e-commerce application with multiple services:

```text
                Django Application
                       |
             ---------------------
             |         |         |
          User API  Order API  Payment API
             |         |         |
             ---------------------
                       |
                 External APIs
```

A Django application can use Requests to communicate with other services.

Example:

```python
import requests


def get_order(order_id):

    response = requests.get(
        f"http://order-service:8000/orders/{order_id}",
        timeout=(2, 5)
    )

    response.raise_for_status()

    return response.json()
```

In a Docker Compose environment, `order-service` could be the service hostname.

### Production considerations

- Configure connection and read timeouts.
- Implement appropriate retry policies.
- Avoid retrying non-idempotent operations blindly.
- Use service authentication.
- Log correlation IDs.
- Monitor upstream latency and errors.
- Consider circuit breakers for repeatedly failing services.
- Avoid synchronous chains of many dependent service calls.

## 25. Logging API Requests

Logging helps diagnose failures in production.

Example:

```python
import logging
import requests

logger = logging.getLogger(__name__)


def fetch_users():

    try:

        response = requests.get(
            "https://api.example.com/users",
            timeout=10
        )

        logger.info(
            "External API status: %s",
            response.status_code
        )

        response.raise_for_status()

        return response.json()

    except requests.exceptions.RequestException:

        logger.exception(
            "External API request failed"
        )

        raise
```

### What should be logged?

- API service name.
- HTTP method.
- HTTP status code.
- Request duration.
- Correlation ID.
- Retry count.
- Error category.

### What should not be logged?

- Passwords.
- Access tokens.
- API keys.
- Authorization headers.
- Sensitive personal information.
- Full payment details.

Be careful when logging URLs because query parameters can contain credentials or personal information.

## 26. Testing Requests with Mocking

When testing Django applications, you generally should not call real external APIs.

Instead, mock the HTTP request.

Install pytest and pytest-mock if you use that testing stack:

```bash
pip install pytest pytest-mock
```

Example using `unittest.mock`:

```python
from unittest.mock import patch, Mock

from myapp.services import CRMService


@patch("myapp.services.requests.get")
def test_get_customer(mock_get):

    mock_response = Mock()

    mock_response.status_code = 200

    mock_response.json.return_value = {
        "id": 1,
        "name": "John"
    }

    mock_response.raise_for_status.return_value = None

    mock_get.return_value = mock_response

    customer = CRMService.get_customer(1)

    assert customer["id"] == 1

    assert customer["name"] == "John"
```

Mock the function where it is used, not necessarily where it was originally defined.

Other useful testing tools include:

- `requests-mock`
- `responses`
- `pytest`
- `unittest.mock`

Test both successful responses and failure scenarios such as timeouts, HTTP 404, HTTP 500, and invalid JSON.

## 27. Common Mistakes in Production

### Mistake 1: Not using timeouts

Bad:

```python
requests.get(url)
```

Better:

```python
requests.get(
    url,
    timeout=(3, 10)
)
```

### Mistake 2: Not checking HTTP errors

Bad:

```python
response = requests.get(url)

data = response.json()
```

Better:

```python
response = requests.get(url)

response.raise_for_status()

data = response.json()
```

### Mistake 3: Hardcoding API tokens

Bad:

```python
headers = {
    "Authorization": "Bearer real-token"
}
```

Better:

```python
import os

token = os.environ["API_TOKEN"]

headers = {
    "Authorization": f"Bearer {token}"
}
```

### Mistake 4: Disabling SSL verification

Bad:

```python
requests.get(
    url,
    verify=False
)
```

Better: Configure the correct trusted certificate authority.

### Mistake 5: Downloading large files into memory

Bad:

```python
response = requests.get(url)

file.write(response.content)
```

Better: Use `stream=True` and `iter_content()`.

### Mistake 6: Blindly retrying POST requests

This can create duplicate orders, payments, or transactions.

Use API-supported idempotency keys and carefully designed retry behavior.

### Mistake 7: Calling synchronous Requests in async views

This blocks the event loop.

Use an asynchronous HTTP client when you need non-blocking HTTP operations.

## 28. End-to-End Example: Django Order Integration

Imagine a Django e-commerce application needs to create an order through an external order-management API.

### Step 1: Create an API service

```python
import requests

from django.conf import settings


class OrderAPIService:

    @staticmethod
    def create_order(order_data):

        url = (
            f"{settings.ORDER_API_URL}/orders"
        )

        headers = {
            "Authorization": (
                f"Bearer {settings.ORDER_API_TOKEN}"
            ),
            "Accept": "application/json"
        }

        try:

            response = requests.post(
                url,
                json=order_data,
                headers=headers,
                timeout=(3, 10)
            )

            response.raise_for_status()

            if response.status_code == 204:
                return None

            return response.json()

        except requests.exceptions.Timeout:

            raise Exception("Order API timeout")

        except requests.exceptions.RequestException:

            raise Exception("Order API request failed")
```

### Step 2: Call the service

```python
order_data = {
    "customer_id": 1001,
    "product_id": 501,
    "quantity": 2
}

result = OrderAPIService.create_order(
    order_data
)

print(result)
```

### Step 3: Understand the flow

```text
Customer
   |
   v
Django View
   |
   v
OrderAPIService
   |
   v
Requests Library
   |
   v
External Order API
   |
   v
HTTP Response
   |
   v
Django Application
```

In a real application, the order API should support an idempotency mechanism to prevent duplicate orders if the client retries after a timeout.

The application should also distinguish between an upstream timeout and a confirmed rejection. A timeout does not always mean the external service failed to process the order.

# 29. Python Requests Interview Questions and Answers

### Q1. What is the Requests library?

Requests is a third-party Python library used to send HTTP requests and communicate with web services and REST APIs.

### Q2. Is Requests built into Python?

No. It is a third-party package and must be installed separately.

### Q3. What are the different HTTP methods supported by Requests?

GET, POST, PUT, PATCH, DELETE, HEAD, and OPTIONS.

### Q4. What is the difference between GET and POST?

GET retrieves information from a server, whereas POST submits data and commonly creates a resource or initiates an operation.

### Q5. What is the difference between PUT and PATCH?

PUT generally replaces a resource, whereas PATCH updates selected fields.

### Q6. What is the difference between `response.text` and `response.json()`?

`response.text` returns the response body as text. `response.json()` parses JSON content into Python objects.

### Q7. What is `response.status_code`?

It returns the HTTP status code received from the server.

### Q8. What does `raise_for_status()` do?

It raises an HTTPError when the response has an unsuccessful 4xx or 5xx status code.

### Q9. What is a timeout in Requests?

A timeout specifies how long Requests waits for connection establishment or incoming response data before raising a timeout exception.

### Q10. What happens if we do not specify a timeout?

The application may wait for an extended period without a configured timeout limit.

### Q11. What is a Session object?

A Session object persists configuration and cookies across requests and enables connection pooling.

### Q12. What is connection pooling?

Connection pooling allows connections to be reused instead of establishing a new connection for every request.

### Q13. What is the difference between `json` and `data`?

`json` serializes a Python object as JSON. `data` is used for form-encoded data or a supplied request body.

### Q14. How do you pass query parameters?

Use the `params` argument.

```python
requests.get(
    url,
    params={"page": 1}
)
```

### Q15. How do you pass headers?

Use the `headers` argument.

```python
requests.get(
    url,
    headers={"Authorization": "Bearer token"}
)
```

### Q16. How do you handle exceptions?

Use try-except with Requests exceptions such as Timeout, ConnectionError, HTTPError, and RequestException.

### Q17. What is the difference between ConnectionError and Timeout?

ConnectionError represents a connection-related failure. Timeout indicates that the configured connection or read timeout was exceeded.

### Q18. How do you upload files?

Use the `files` argument with a file opened in binary mode.

### Q19. How do you download large files?

Use `stream=True` and process the response with `iter_content()`.

### Q20. How do you authenticate using a Bearer token?

Pass the token through the Authorization header.

```python
headers = {
    "Authorization": "Bearer YOUR_TOKEN"
}
```

### Q21. How does SSL verification work?

Requests verifies the server's TLS certificate by default. You can provide a trusted CA bundle through `verify`.

### Q22. What is the purpose of an HTTPAdapter?

An HTTPAdapter manages connection pooling and transport-level configuration, including retry behavior through urllib3.

### Q23. How do you implement retries?

Use `urllib3.util.retry.Retry` with a `requests.adapters.HTTPAdapter`.

### Q24. Why should we be careful when retrying POST requests?

A POST operation may create duplicate resources or trigger duplicate payments. Use idempotency keys or another deduplication mechanism.

### Q25. Can Requests be used asynchronously?

No. Requests is synchronous. For asynchronous HTTP communication, use HTTPX AsyncClient or aiohttp.

### Q26. What is the difference between Requests and HTTPX?

Requests is synchronous. HTTPX supports both synchronous and asynchronous communication and supports HTTP/2.

### Q27. How do you integrate Requests with Django?

Create a separate service module to handle API calls and invoke those service functions from Django views or background tasks.

### Q28. How do you store API credentials securely?

Use environment variables or a dedicated secrets manager. Never commit production credentials to Git.

### Q29. How do you test external API calls?

Mock the Requests calls using unittest.mock, responses, or requests-mock.

### Q30. What happens if an API returns HTTP 204?

HTTP 204 means the request succeeded but the response has no content. Do not attempt to parse it as JSON unless the API contract says otherwise.

### Q31. What is pagination?

Pagination divides a large dataset into smaller responses, allowing the client to retrieve data page by page.

### Q32. What is a proxy?

A proxy is an intermediary server through which HTTP requests are routed.

### Q33. What is the purpose of `allow_redirects`?

It controls whether Requests automatically follows HTTP redirects.

### Q34. What is the difference between response cookies and request cookies?

Response cookies are received from the server. Request cookies are sent by the client to the server.

### Q35. What are important production best practices for Requests?

- Always configure timeouts.
- Handle exceptions.
- Check HTTP status codes.
- Use Sessions for repeated calls.
- Secure API credentials.
- Keep SSL verification enabled.
- Implement safe retry policies.
- Avoid logging secrets.
- Monitor API latency and failures.
- Mock external calls during testing.
