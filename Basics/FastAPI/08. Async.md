# Part 8: Asynchronous Programming — Complete Python and FastAPI Guide

## 91. Synchronous vs Asynchronous Programming

### What is synchronous programming?

Synchronous programming means executing instructions one after another.

The next operation waits until the current operation finishes.

For example, imagine you need to call three external APIs.

Each API takes 2 seconds to respond.

With synchronous execution:

```text
API 1: 2 seconds
API 2: 2 seconds
API 3: 2 seconds

Total: 6 seconds
```

### Example 1: Synchronous Python

```python
import time

def task(name):
    print(f"{name} started")

    time.sleep(2)

    print(f"{name} completed")


start = time.time()

task("Task 1")
task("Task 2")
task("Task 3")

end = time.time()

print(f"Total time: {end - start:.2f} seconds")
```

**Expected output:**

```text
Task 1 started
Task 1 completed
Task 2 started
Task 2 completed
Task 3 started
Task 3 completed
Total time: 6.00 seconds
```

The exact timing can vary slightly.

### Explanation

1. Task 1 starts.
2. `time.sleep(2)` blocks execution for two seconds.
3. Task 1 completes.
4. Task 2 starts.
5. The same process repeats.
6. Task 3 completes.
7. The program finishes.

Each task must wait for the previous task.

### What is asynchronous programming?

Asynchronous programming allows a program to pause while waiting for an operation and work on other tasks in the meantime.

For example:

- Task 1 starts and waits for an API response.
- While Task 1 is waiting, Task 2 can execute.
- While Task 2 is waiting, Task 3 can execute.
- The program resumes each task when its awaited operation is ready.

### Example 2: Asynchronous Python

```python
import asyncio
import time


async def task(name):

    print(f"{name} started")

    await asyncio.sleep(2)

    print(f"{name} completed")


async def main():

    start = time.time()

    await asyncio.gather(
        task("Task 1"),
        task("Task 2"),
        task("Task 3")
    )

    end = time.time()

    print(f"Total time: {end - start:.2f} seconds")


asyncio.run(main())
```

**Expected output:**

```text
Task 1 started
Task 2 started
Task 3 started
Task 1 completed
Task 2 completed
Task 3 completed
Total time: 2.00 seconds
```

The exact completion order and timing can vary.

### Explanation

**`async def task()`**

Defines an asynchronous function.

**`await asyncio.sleep(2)`**

Pauses the current coroutine without blocking the event loop.

**`asyncio.gather()`**

Schedules multiple awaitable operations and waits for all of them to complete.

**`asyncio.run(main())`**

Creates an event loop, executes the main coroutine and closes the loop when finished.

### Comparison

| Synchronous | Asynchronous |
|---|---|
| Executes operations sequentially | Can coordinate multiple waiting operations |
| Blocking operations stop the current thread | Awaitable operations can yield control |
| Suitable for simple sequential work | Suitable for concurrent I/O-bound work |
| Often simpler to understand | Requires understanding `async` and `await` |
| May spend time waiting without doing other work | Can use waiting time to run other coroutines |

**Important:** Async programming does not automatically make CPU-intensive work faster. Its main benefit is improving concurrency when tasks spend time waiting for I/O.

## 92. Understanding async and await

### What is async?

The `async` keyword is used to define an asynchronous function.

Example:

```python
async def get_data():

    return "Hello from async function"


result = get_data()

print(result)
```

**Expected output:**

```text
<coroutine object get_data at ...>
```

Why?

Because calling an asynchronous function does not execute it immediately like a normal function. It creates a coroutine object.

To execute it, you need to await it inside an asynchronous context or run it through an event loop.

### What is await?

The `await` keyword waits for an awaitable operation to complete.

Example:

```python
import asyncio


async def get_data():

    await asyncio.sleep(2)

    return "Data received"


async def main():

    result = await get_data()

    print(result)


asyncio.run(main())
```

**Expected output:**

```text
Data received
```

### Understanding the execution

```python
result = await get_data()
```

This means:

1. Start or resume `get_data()`.
2. Wait for its awaited operations to complete.
3. Allow the event loop to run other coroutines while waiting.
4. Receive the returned value.
5. Store the value in `result`.

### Example: Multiple async functions

```python
import asyncio


async def get_user():

    await asyncio.sleep(1)

    return "Alice"


async def get_orders():

    await asyncio.sleep(1)

    return ["Order 1", "Order 2"]


async def main():

    user = await get_user()

    orders = await get_orders()

    print("User:", user)

    print("Orders:", orders)


asyncio.run(main())
```

**Expected output:**

```text
User: Alice
Orders: ['Order 1', 'Order 2']
```

Both operations take approximately one second each, so total time is approximately two seconds because they are awaited sequentially.

### Run both concurrently

```python
import asyncio


async def get_user():

    await asyncio.sleep(1)

    return "Alice"


async def get_orders():

    await asyncio.sleep(1)

    return ["Order 1", "Order 2"]


async def main():

    user, orders = await asyncio.gather(
        get_user(),
        get_orders()
    )

    print("User:", user)

    print("Orders:", orders)


asyncio.run(main())
```

**Expected output:**

```text
User: Alice
Orders: ['Order 1', 'Order 2']
```

Both operations now take approximately one second in total.

### Important rules

1. Use `async def` to define an asynchronous function.
2. Use `await` to wait for an awaitable.
3. You can use `await` inside an `async def` function.
4. Calling an async function creates a coroutine; it does not automatically execute it.
5. You cannot directly use `await` inside an ordinary synchronous function.

### Common mistake

Incorrect:

```python
async def get_data():
    return "Hello"


def main():
    result = get_data()

    print(result)


main()
```

**Expected output:**

```text
<coroutine object get_data at ...>
```

Correct:

```python
import asyncio


async def get_data():
    return "Hello"


async def main():

    result = await get_data()

    print(result)


asyncio.run(main())
```

**Expected output:**

```text
Hello
```

## 93. Event Loop Fundamentals

### What is an event loop?

The event loop is the mechanism that schedules and runs asynchronous tasks.

Think of it as a coordinator.

It manages multiple coroutines and decides which coroutine should run when another coroutine is waiting.

### Real-world example

Imagine a restaurant with one waiter.

The waiter:

1. Takes an order from Customer A.
2. Sends the order to the kitchen.
3. While the kitchen prepares it, takes an order from Customer B.
4. While Customer B's order is being prepared, serves Customer C.
5. Returns to the first customer when the food is ready.

The waiter does not need to stand idle while the kitchen works.

An event loop works similarly with asynchronous tasks.

### Example: Event loop with multiple tasks

```python
import asyncio


async def task(name, delay):

    print(f"{name} started")

    await asyncio.sleep(delay)

    print(f"{name} completed")


async def main():

    await asyncio.gather(
        task("Task A", 3),
        task("Task B", 2),
        task("Task C", 1)
    )


asyncio.run(main())
```

**Expected output:**

```text
Task A started
Task B started
Task C started
Task C completed
Task B completed
Task A completed
```

### Explanation

All three coroutines start.

- Task A waits for three seconds.
- Task B waits for two seconds.
- Task C waits for one second.

While one coroutine waits, the event loop can run another coroutine.

Therefore, Task C finishes first.

### Main event loop concepts

| Concept | Explanation |
|---|---|
| Event loop | Schedules and runs asynchronous tasks |
| Coroutine | An asynchronous function execution |
| Task | A scheduled coroutine |
| Awaitable | An object that can be awaited |
| Suspension | A coroutine pauses at an await point |
| Resumption | A suspended coroutine continues execution |

### Example: Create tasks manually

```python
import asyncio


async def say_hello():

    await asyncio.sleep(1)

    print("Hello")


async def main():

    task = asyncio.create_task(say_hello())

    print("Task created")

    await task

    print("Task completed")


asyncio.run(main())
```

**Expected output:**

```text
Task created
Hello
Task completed
```

### Explanation of create_task()

```python
task = asyncio.create_task(say_hello())
```

This schedules the coroutine to run on the current event loop.

It returns an `asyncio.Task` object.

You can later await the task to obtain its result or wait for its completion.

### Important distinction

- `asyncio.run()` starts and manages an event loop.
- `asyncio.create_task()` schedules a coroutine on an already running event loop.
- `await` waits for an awaitable operation.
- `asyncio.gather()` waits for multiple awaitables.

Do not call `asyncio.run()` inside an already running event loop. In FastAPI endpoints, use `await` or create tasks using the existing event loop instead.

## 94. Coroutines

### What is a coroutine?

A coroutine is an asynchronous unit of execution.

In Python, an `async def` function creates a coroutine object when called.

Example:

```python
async def get_message():

    return "Hello from coroutine"


result = get_message()

print(type(result))
```

**Expected output:**

```text
<class 'coroutine'>
```

The coroutine has not been executed yet.

### Execute the coroutine

```python
import asyncio


async def get_message():

    return "Hello from coroutine"


async def main():

    result = await get_message()

    print(result)


asyncio.run(main())
```

**Expected output:**

```text
Hello from coroutine
```

### Example: Two coroutines

```python
import asyncio


async def download_file():

    print("Downloading file")

    await asyncio.sleep(2)

    print("File downloaded")


async def process_file():

    print("Processing file")

    await asyncio.sleep(1)

    print("File processed")


async def main():

    await asyncio.gather(
        download_file(),
        process_file()
    )


asyncio.run(main())
```

**Expected output:**

```text
Downloading file
Processing file
File processed
File downloaded
```

### Coroutine versus Task

| Coroutine | Task |
|---|---|
| Represents asynchronous computation | Schedules a coroutine to run |
| Created by calling an async function | Created using `asyncio.create_task()` or similar |
| Can be awaited directly | Can be awaited |
| Does not necessarily run until awaited or scheduled | Is scheduled on an event loop |

### Example: Coroutine versus Task

```python
import asyncio


async def work():
    await asyncio.sleep(1)
    return "Work completed"


async def main():

    coroutine = work()

    print("Coroutine created")

    task = asyncio.create_task(work())

    print("Task created")

    result1 = await coroutine

    result2 = await task

    print(result1)

    print(result2)


asyncio.run(main())
```

**Expected output:**

```text
Coroutine created
Task created
Work completed
Work completed
```

The coroutine is awaited directly. The task is scheduled when created and can progress while the coroutine is awaited.

## 95. Async Endpoints

### What is an async endpoint in FastAPI?

An async endpoint is a route function defined using `async def`.

Example:

```python
from fastapi import FastAPI

app = FastAPI()


@app.get("/hello")
async def hello():

    return {
        "message": "Hello"
    }
```

**Expected API response:**

```json
{
  "message": "Hello"
}
```

### Why use async endpoints?

They are useful when your endpoint performs asynchronous I/O operations, such as:

- Calling external APIs.
- Querying an async database driver.
- Reading from an async network stream.
- Communicating with Redis asynchronously.

### Example: Async endpoint calling an external service

```python
import asyncio

from fastapi import FastAPI

app = FastAPI()


@app.get("/users")
async def get_users():

    await asyncio.sleep(2)

    return {
        "users": ["Alice", "Bob"]
    }
```

**Expected API response:**

```json
{
  "users": ["Alice", "Bob"]
}
```

The endpoint waits asynchronously for two seconds.

During this wait, the event loop can process other requests and coroutines.

### Sync versus async endpoints

Synchronous endpoint:

```python
@app.get("/sync")
def sync_endpoint():

    return {
        "message": "Synchronous endpoint"
    }
```

Asynchronous endpoint:

```python
@app.get("/async")
async def async_endpoint():

    return {
        "message": "Asynchronous endpoint"
    }
```

**Expected response from `/sync`:**

```json
{
  "message": "Synchronous endpoint"
}
```

**Expected response from `/async`:**

```json
{
  "message": "Asynchronous endpoint"
}
```

### Important FastAPI behaviour

FastAPI handles these differently:

**Normal `def` endpoint**

FastAPI runs synchronous endpoint functions in an external thread pool so that blocking synchronous code does not directly block the event loop.

**`async def` endpoint**

FastAPI calls the asynchronous endpoint on the event loop and awaits it.

This means:

- Use `async def` when using asynchronous libraries.
- Use `def` when using blocking synchronous libraries and the operation is reasonably suited to thread-pool execution.
- Do not put blocking operations directly inside an `async def` endpoint.

## 96. Blocking vs Non-Blocking Operations

### What is a blocking operation?

A blocking operation prevents the current thread from continuing until the operation finishes.

Example:

```python
import time


def blocking_task():

    print("Task started")

    time.sleep(3)

    print("Task completed")


blocking_task()
```

**Expected output:**

```text
Task started
Task completed
```

The thread waits for three seconds.

### What is a non-blocking asynchronous operation?

A non-blocking awaitable operation allows the event loop to run other tasks while the current coroutine waits.

Example:

```python
import asyncio


async def non_blocking_task():

    print("Task started")

    await asyncio.sleep(3)

    print("Task completed")


asyncio.run(non_blocking_task())
```

**Expected output:**

```text
Task started
Task completed
```

The visible output is similar, but the execution behaviour is different.

### Demonstrate the difference

Blocking version:

```python
import asyncio
import time


async def task_a():

    print("A started")

    time.sleep(3)

    print("A completed")


async def task_b():

    print("B started")

    await asyncio.sleep(1)

    print("B completed")


async def main():

    await asyncio.gather(
        task_a(),
        task_b()
    )


asyncio.run(main())
```

**Expected output:**

```text
A started
A completed
B started
B completed
```

Task A blocks the event loop for three seconds. Task B cannot start until Task A finishes.

### Correct non-blocking version

```python
import asyncio


async def task_a():

    print("A started")

    await asyncio.sleep(3)

    print("A completed")


async def task_b():

    print("B started")

    await asyncio.sleep(1)

    print("B completed")


async def main():

    await asyncio.gather(
        task_a(),
        task_b()
    )


asyncio.run(main())
```

**Expected output:**

```text
A started
B started
B completed
A completed
```

Task B completes while Task A is waiting.

### Common blocking operations

| Blocking operation | Async alternative |
|---|---|
| `time.sleep()` | `await asyncio.sleep()` |
| `requests.get()` | `await httpx.AsyncClient().get()` |
| Synchronous database driver | Async database driver |
| Blocking file operations | Async file library or thread offloading |
| Synchronous Redis client | `redis.asyncio` client |

### Important FastAPI example

Incorrect:

```python
import time

@app.get("/bad")
async def bad_endpoint():

    time.sleep(5)

    return {"message": "Done"}
```

This blocks the event loop.

Correct:

```python
import asyncio

@app.get("/good")
async def good_endpoint():

    await asyncio.sleep(5)

    return {"message": "Done"}
```

**Expected response from both:**

```json
{
  "message": "Done"
}
```

But the second implementation allows other coroutines to run during the wait.

## 97. Async Database Operations

### What are async database operations?

Async database operations allow your application to communicate with a database without blocking the event loop while waiting for database I/O.

They are useful when your API handles many concurrent requests.

Popular options include:

- SQLAlchemy AsyncIO.
- asyncpg for PostgreSQL.
- databases library.
- Async database drivers for supported databases.

### Install dependencies

```bash
pip install sqlalchemy asyncpg
```

### Example: Async SQLAlchemy setup

```python
from sqlalchemy.ext.asyncio import (
    create_async_engine,
    async_sessionmaker,
    AsyncSession
)

DATABASE_URL = (
    "postgresql+asyncpg://user:password@localhost/mydb"
)

engine = create_async_engine(
    DATABASE_URL,
    echo=True
)

AsyncSessionLocal = async_sessionmaker(
    engine,
    class_=AsyncSession,
    expire_on_commit=False
)
```

### Explanation

**`create_async_engine()`**

Creates an asynchronous database engine.

**`async_sessionmaker()`**

Creates a factory for asynchronous database sessions.

**`AsyncSession`**

Represents a database session that supports asynchronous operations.

**`expire_on_commit=False`**

Prevents ORM objects from being expired automatically after a commit. This can be convenient when accessing attributes after committing.

### Example: Create a database dependency

```python
from typing import AsyncGenerator
from sqlalchemy.ext.asyncio import AsyncSession


async def get_db() -> AsyncGenerator[AsyncSession, None]:

    async with AsyncSessionLocal() as session:

        yield session
```

The dependency creates a session for the request and closes it when the dependency scope ends.

### Example: Define a database model

```python
from sqlalchemy.orm import DeclarativeBase
from sqlalchemy.orm import Mapped, mapped_column
from sqlalchemy import String


class Base(DeclarativeBase):
    pass


class User(Base):

    __tablename__ = "users"

    id: Mapped[int] = mapped_column(
        primary_key=True
    )

    name: Mapped[str] = mapped_column(
        String(100)
    )

    email: Mapped[str] = mapped_column(
        String(200)
    )
```

### Example: Insert a user asynchronously

```python
from fastapi import Depends
from sqlalchemy.ext.asyncio import AsyncSession


@app.post("/users")
async def create_user(
    name: str,
    email: str,
    db: AsyncSession = Depends(get_db)
):

    user = User(
        name=name,
        email=email
    )

    db.add(user)

    await db.commit()

    await db.refresh(user)

    return {
        "id": user.id,
        "name": user.name,
        "email": user.email
    }
```

**Example request:**

```http
POST /users?name=Alice&email=alice@example.com
```

**Expected response:**

```json
{
  "id": 1,
  "name": "Alice",
  "email": "alice@example.com"
}
```

The ID depends on the database sequence.

### Explanation

**`db.add(user)`**

Adds the object to the session.

**`await db.commit()`**

Commits the transaction asynchronously.

**`await db.refresh(user)`**

Refreshes the object with values from the database.

### Example: Read a user

```python
from sqlalchemy import select


@app.get("/users/{user_id}")
async def get_user(
    user_id: int,
    db: AsyncSession = Depends(get_db)
):

    result = await db.execute(
        select(User).where(User.id == user_id)
    )

    user = result.scalar_one_or_none()

    if user is None:
        return {"message": "User not found"}

    return {
        "id": user.id,
        "name": user.name,
        "email": user.email
    }
```

**Expected response if the user exists:**

```json
{
  "id": 1,
  "name": "Alice",
  "email": "alice@example.com"
}
```

**Expected response if the user does not exist:**

```json
{
  "message": "User not found"
}
```

### Important production considerations

- Use an async-compatible database driver.
- Manage sessions through dependencies.
- Use transactions for related database changes.
- Configure connection pooling.
- Avoid sharing one `AsyncSession` between concurrent tasks.
- Do not call synchronous database operations directly inside an async endpoint.

**Important:** Async database access improves concurrency while waiting for database operations. It does not automatically make an individual SQL query faster.

## 98. Async HTTP Requests Using httpx

### What is HTTPX?

HTTPX is a Python HTTP client library.

It supports both synchronous and asynchronous HTTP requests.

It can communicate with external services and APIs.

### Install HTTPX

```bash
pip install httpx
```

### Example 1: Synchronous HTTP request

```python
import httpx


response = httpx.get(
    "https://jsonplaceholder.typicode.com/users/1"
)

print(response.status_code)

print(response.json())
```

**Expected output:**

```text
200
{
  'id': 1,
  'name': 'Leanne Graham',
  ...
}
```

The exact remaining JSON fields are returned by the external service.

### Example 2: Asynchronous HTTP request

```python
import asyncio
import httpx


async def get_user():

    async with httpx.AsyncClient() as client:

        response = await client.get(
            "https://jsonplaceholder.typicode.com/users/1"
        )

        print(response.status_code)

        print(response.json())


asyncio.run(get_user())
```

**Expected output:**

```text
200
{
  'id': 1,
  'name': 'Leanne Graham',
  ...
}
```

### Explanation

**`httpx.AsyncClient()`**

Creates an asynchronous HTTP client.

**`await client.get()`**

Sends an asynchronous GET request.

**`response.status_code`**

Returns the HTTP status code.

**`response.json()`**

Parses the response body as JSON.

### Example 3: Multiple API requests concurrently

```python
import asyncio
import httpx


async def fetch_user(client, user_id):

    response = await client.get(
        f"https://jsonplaceholder.typicode.com/users/{user_id}"
    )

    response.raise_for_status()

    return response.json()


async def main():

    async with httpx.AsyncClient(
        timeout=10.0
    ) as client:

        users = await asyncio.gather(
            fetch_user(client, 1),
            fetch_user(client, 2),
            fetch_user(client, 3)
        )

        for user in users:
            print(user["name"])


asyncio.run(main())
```

**Expected output:**

```text
Leanne Graham
Ervin Howell
Clementine Bauch
```

### Explanation

1. One HTTP client is created.
2. Three requests are scheduled concurrently.
3. The event loop coordinates their execution.
4. Each response is parsed as JSON.
5. `asyncio.gather()` returns the results.
6. The user names are printed.

### Example 4: Use HTTPX inside FastAPI

```python
import httpx

from fastapi import FastAPI, Request
from contextlib import asynccontextmanager


@asynccontextmanager
async def lifespan(app: FastAPI):

    app.state.http_client = httpx.AsyncClient(
        timeout=10.0
    )

    try:
        yield
    finally:
        await app.state.http_client.aclose()


app = FastAPI(lifespan=lifespan)


@app.get("/external-user/{user_id}")
async def get_external_user(
    user_id: int,
    request: Request
):

    client = request.app.state.http_client

    response = await client.get(
        f"https://jsonplaceholder.typicode.com/users/{user_id}"
    )

    response.raise_for_status()

    return response.json()
```

**Expected API response for `/external-user/1`:**

```json
{
  "id": 1,
  "name": "Leanne Graham",
  "username": "Bret",
  "email": "Sincere@april.biz"
}
```

Other fields may also be included in the response.

### Why reuse an HTTP client?

Creating a new client for every request can repeatedly incur connection setup costs.

Reusing a client enables connection pooling and reduces unnecessary overhead.

## 99. BackgroundTasks

### What are BackgroundTasks?

FastAPI provides `BackgroundTasks` to execute small tasks after the response has been sent.

This is useful when the client does not need to wait for additional work.

Example:

A user registers on your website.

1. User submits registration.
2. API creates the account.
3. API returns a response.
4. A welcome email is sent in the background.

### Example 1: Simple background task

```python
from fastapi import FastAPI, BackgroundTasks

app = FastAPI()


def send_email(email: str):

    print(f"Sending email to {email}")


@app.post("/register")
def register_user(
    email: str,
    background_tasks: BackgroundTasks
):

    background_tasks.add_task(
        send_email,
        email
    )

    return {
        "message": "User registered successfully"
    }
```

**Example request:**

```http
POST /register?email=alice@example.com
```

**Expected API response:**

```json
{
  "message": "User registered successfully"
}
```

**Expected server console output after response handling:**

```text
Sending email to alice@example.com
```

### Explanation

**`BackgroundTasks`**

FastAPI injects an object that collects tasks to execute after the response is sent.

**`add_task()`**

Registers the function and arguments.

Syntax:

```python
background_tasks.add_task(
    function_name,
    argument1,
    argument2
)
```

### Example 2: Multiple background tasks

```python
def send_email(email: str):
    print(f"Email sent to {email}")


def create_audit_log(user_id: int):
    print(f"Audit log created for user {user_id}")


@app.post("/users")
def create_user(background_tasks: BackgroundTasks):

    background_tasks.add_task(
        send_email,
        "alice@example.com"
    )

    background_tasks.add_task(
        create_audit_log,
        101
    )

    return {
        "message": "User created"
    }
```

**Expected API response:**

```json
{
  "message": "User created"
}
```

## 100. Thread Pools and Process Pools

### Why do we need thread pools and process pools?

Sometimes your application needs to execute blocking or CPU-intensive work.

Async programming alone does not solve every problem.

Python provides:

1. Thread pools.
2. Process pools.

### A. Thread Pool

A thread pool executes functions using multiple threads within the same process.

It is useful for many blocking I/O operations.

Examples:

- Calling synchronous HTTP libraries.
- Reading files using blocking operations.
- Calling synchronous database libraries.
- Working with legacy blocking code.

### Example: ThreadPoolExecutor

```python
import time

from concurrent.futures import ThreadPoolExecutor


def download_file(name):

    print(f"Downloading {name}")

    time.sleep(2)

    print(f"Downloaded {name}")

    return name


start = time.time()

with ThreadPoolExecutor(max_workers=3) as executor:

    results = list(
        executor.map(
            download_file,
            ["file1", "file2", "file3"]
        )
    )

print(results)

print(f"Total time: {time.time() - start:.2f}")
```

**Expected output:**

```text
Downloading file1
Downloading file2
Downloading file3
Downloaded file1
Downloaded file2
Downloaded file3
['file1', 'file2', 'file3']
Total time: 2.00
```

The exact order and duration can vary.

### Explanation

**`ThreadPoolExecutor`**

Creates a pool of worker threads.

**`max_workers=3`**

Allows up to three tasks to execute at the same time.

**`executor.map()`**

Schedules the function for each item and returns results in input order.

### B. Process Pool

A process pool executes functions in separate processes.

It is useful for CPU-intensive work.

Examples:

- Image processing.
- Large mathematical calculations.
- Data transformations.
- CPU-intensive report generation.

### Example: ProcessPoolExecutor

```python
from concurrent.futures import ProcessPoolExecutor


def calculate_square(number):

    result = number * number

    return result


if __name__ == "__main__":

    with ProcessPoolExecutor(max_workers=3) as executor:

        results = list(
            executor.map(
                calculate_square,
                [2, 3, 4, 5]
            )
        )

    print(results)
```

**Expected output:**

```text
[4, 9, 16, 25]
```

### Explanation

**`ProcessPoolExecutor`**

Creates separate worker processes.

**`max_workers=3`**

Allows up to three processes to work concurrently.

**`executor.map()`**

Distributes the calculations among the workers.

The `if __name__ == "__main__"` guard is important for portable multiprocessing behaviour, especially on platforms that use process spawning.

### C. Run blocking code from an async endpoint

Python provides `asyncio.to_thread()`.

```python
import asyncio
import time

from fastapi import FastAPI

app = FastAPI()


def blocking_operation():

    time.sleep(3)

    return "Operation completed"


@app.get("/thread")
async def run_thread():

    result = await asyncio.to_thread(
        blocking_operation
    )

    return {
        "result": result
    }
```

**Expected API response after approximately three seconds:**

```json
{
  "result": "Operation completed"
}
```

The blocking function runs in a separate thread rather than blocking the event loop.

### D. Use a process pool from an async endpoint

```python
import asyncio

from concurrent.futures import ProcessPoolExecutor
from fastapi import FastAPI

app = FastAPI()

process_pool = ProcessPoolExecutor(max_workers=2)


def calculate_sum(number):

    return sum(range(number))


@app.get("/calculate")
async def calculate():

    loop = asyncio.get_running_loop()

    result = await loop.run_in_executor(
        process_pool,
        calculate_sum,
        1000000
    )

    return {
        "result": result
    }
```

**Expected API response:**

```json
{
  "result": 499999500000
}
```

### Thread Pool versus Process Pool

| Thread Pool | Process Pool |
|---|---|
| Uses multiple threads | Uses multiple processes |
| Shared process memory | Separate process memory |
| Good for blocking I/O | Good for CPU-intensive work |
| Lower process-management overhead | More process-management overhead |
| Subject to Python GIL limitations for CPU-bound Python code | Can use multiple CPU cores for Python CPU-bound work |

### Important production considerations

- Thread pools have limited worker capacity.
- Process pools use additional memory.
- Functions and arguments sent to process workers generally need to be picklable.
- Do not create a new process pool for every request.
- Manage executor shutdown correctly.
- For very long-running work, consider a dedicated worker system.

## 101. Concurrency vs Parallelism

These terms are related but different.

### What is concurrency?

Concurrency means managing multiple tasks during overlapping periods of time.

Tasks can make progress without necessarily executing at the exact same instant.

Example:

```text
Task A starts
Task A waits for network
Task B runs
Task B waits for database
Task A continues
Task B continues
```

This is common with asynchronous programming.

### What is parallelism?

Parallelism means executing multiple tasks at the same time.

For example, two CPU cores can execute two independent calculations simultaneously.

### Real-world example

Concurrency:

One chef prepares several dishes.

- Starts boiling water.
- While water boils, cuts vegetables.
- While vegetables cook, prepares another dish.

Parallelism:

Three chefs work on different dishes at the same time.

### Example 1: Concurrency using asyncio

```python
import asyncio


async def task(name):

    print(f"{name} started")

    await asyncio.sleep(2)

    print(f"{name} completed")


async def main():

    await asyncio.gather(
        task("A"),
        task("B"),
        task("C")
    )


asyncio.run(main())
```

**Expected output:**

```text
A started
B started
C started
A completed
B completed
C completed
```

The tasks overlap while waiting.

### Example 2: Parallelism using ProcessPoolExecutor

```python
from concurrent.futures import ProcessPoolExecutor


def calculate(number):

    return sum(
        i * i
        for i in range(number)
    )


if __name__ == "__main__":

    numbers = [
        1000000,
        1000000,
        1000000
    ]

    with ProcessPoolExecutor(max_workers=3) as executor:

        results = list(
            executor.map(calculate, numbers)
        )

    print(results)
```

**Expected output:**

```text
[333332833333500000, 333332833333500000, 333332833333500000]
```

The independent calculations can run in separate processes simultaneously.

### Concurrency versus parallelism

| Concurrency | Parallelism |
|---|---|
| Tasks make progress over overlapping periods | Tasks execute at the same time |
| Can run on one CPU core | Requires multiple execution resources for true simultaneous execution |
| Useful for I/O-bound workloads | Useful for CPU-bound workloads |
| Often implemented with async event loops | Often implemented with multiple processes or cores |
| Does not necessarily mean simultaneous execution | Means simultaneous execution |

### Important point

Asyncio provides concurrency, not automatic CPU parallelism.

A single event loop generally executes one coroutine at a time on its thread. It switches between coroutines when they yield control.

## 102. Handling Long-Running Tasks

### What is a long-running task?

A long-running task is an operation that takes significant time to complete.

Examples:

- Generating large reports.
- Processing uploaded videos.
- Sending thousands of emails.
- Machine learning processing.
- Exporting large datasets.
- Processing financial transactions in batches.

### Why should we avoid executing long-running tasks directly in an API request?

Imagine a report takes 60 seconds to generate.

If the client waits for the entire operation:

- The request stays open for a long time.
- The client may time out.
- Server resources remain occupied.
- Retries may create duplicate work.
- The user has no convenient way to check progress.

A better architecture is to submit the task and return a job ID.

### Recommended architecture

```text
Client
  |
  v
FastAPI API
  |
  v
Create Job
  |
  v
Message Queue
  |
  v
Background Worker
  |
  v
Process Task
  |
  v
Database / Object Storage
  |
  v
Client checks job status
```

### Example 1: Simple in-process background task

```python

    await asyncio.sleep(5)

    print("Report generation completed")


@app.post("/generate-report")
async def create_report(
    background_tasks: BackgroundTasks
):

    background_tasks.add_task(
        generate_report
    )

    return {
        "message": "Report generation started"
    }
```

```json
{
  "message": "Report generation started"
}
```

**Expected server console output after approximately five seconds:**

```text

```

### Example 2: Job ID and status tracking

For a demonstration, use an in-memory dictionary.

```python
import asyncio
import uuid

from fastapi import FastAPI, BackgroundTasks, HTTPException

app = FastAPI()

jobs = {}


async def process_job(job_id: str):

    jobs[job_id]["status"] = "processing"

    await asyncio.sleep(5)

    jobs[job_id]["status"] = "completed"

    jobs[job_id]["result"] = {
        "message": "Report generated"
    }


@app.post("/jobs")
async def create_job(
    background_tasks: BackgroundTasks
):

    job_id = str(uuid.uuid4())

    jobs[job_id] = {
        "status": "pending",
        "result": None
    }

    background_tasks.add_task(
        process_job,
        job_id
    )

    return {
        "job_id": job_id,
        "status": "pending"
    }


@app.get("/jobs/{job_id}")
async def get_job(job_id: str):

    job = jobs.get(job_id)

    if job is None:
        raise HTTPException(
            status_code=404,
            detail="Job not found"
        )

    return {
        "job_id": job_id,
        **job
    }
```

```python
from fastapi import FastAPI
from worker import generate_report

app = FastAPI()


@app.post("/reports/{user_id}")
def create_report(user_id: int):

    task = generate_report.delay(user_id)

    return {
        "task_id": task.id,

    task = generate_report.AsyncResult(task_id)

        "task_id": task_id,
        "status": task.status,
        "result": task.result if task.successful() else None
    }
```

# Important FastAPI Interview Questions

### 1. What is the difference between `async def` and `def` in FastAPI?

- `async def` executes as a coroutine on the event loop.
- `def` endpoints are run in a thread pool by FastAPI.
- Use async endpoints with async libraries.
- Use synchronous endpoints for suitable blocking synchronous code.

### 2. Does async mean parallel execution?

No. Async provides concurrency. Multiple coroutines can make progress while waiting, but a single event loop does not execute their Python code simultaneously on multiple CPU cores.

### 3. What happens if you call `time.sleep()` inside an async endpoint?

It blocks the event-loop thread and prevents other coroutines on that loop from progressing during the sleep.

Use `await asyncio.sleep()` instead.

### 4. What is an event loop?

It schedules asynchronous tasks and resumes coroutines when their awaited operations are ready.

### 5. What is the difference between a coroutine and a task?

A coroutine represents asynchronous computation. A task schedules a coroutine to run on an event loop.

### 6. What is the difference between asyncio.gather() and asyncio.create_task()?

- `create_task()` schedules a coroutine and returns a Task.
- `gather()` schedules or awaits multiple awaitables together and collects their results.

### 7. When should you use async database operations?

When your database driver supports asynchronous operations and your application benefits from handling multiple requests concurrently while waiting for database I/O.

### 8. What is the difference between HTTPX and Requests?

- Requests is a synchronous HTTP client.
- HTTPX supports both synchronous and asynchronous HTTP clients.

### 9. What is the difference between BackgroundTasks and Celery?

- BackgroundTasks runs small work within the application process.
- Celery uses separate workers and a broker for distributed task processing.

### 10. When should you use ThreadPoolExecutor?

When you need to execute blocking I/O operations or run synchronous functions without blocking the event loop.

### 11. When should you use ProcessPoolExecutor?

For CPU-intensive Python work that can benefit from execution in separate processes.

### 12. What is the difference between concurrency and parallelism?

Concurrency means multiple tasks make progress over overlapping periods. Parallelism means multiple tasks execute simultaneously.

### 13. How do you handle long-running tasks in FastAPI?

Submit a job to a task queue, return a job ID, process it in a worker, and expose an endpoint for checking job status.

# Final Revision: What You Must Remember

1. **Synchronous:** One operation waits for another to finish.
2. **Asynchronous:** Tasks can make progress while other tasks wait.
3. **async:** Defines an asynchronous function.
4. **await:** Waits for an awaitable operation without blocking the event loop.
5. **Event loop:** Coordinates asynchronous task execution.
6. **Coroutine:** An asynchronous computation.
7. **Async endpoint:** Useful for non-blocking I/O.
8. **Blocking operation:** Prevents the current thread from continuing.
9. **Async database:** Allows concurrent database I/O.
10. **HTTPX:** Supports asynchronous external API requests.
11. **BackgroundTasks:** Runs small tasks after response handling.
12. **Thread pool:** Useful for blocking I/O and synchronous functions.
13. **Process pool:** Useful for CPU-intensive tasks.
14. **Concurrency:** Overlapping progress of tasks.
15. **Parallelism:** Simultaneous execution.
16. **Long-running tasks:** Use dedicated workers and durable queues when reliability matters.

## Most important practical rule

Choose the execution model based on the type of work:

| Workload | Recommended approach |
|---|---|
| Normal API logic | `def` or `async def`, depending on dependencies |
| External API calls | HTTPX AsyncClient |
| Async database queries | SQLAlchemy AsyncSession or async driver |
| Small email notification | FastAPI BackgroundTasks |
| Blocking synchronous library | `asyncio.to_thread()` or thread pool |
| CPU-intensive calculation | Process pool or separate compute worker |
| Long-running durable job | Celery or another distributed task queue |

**Remember:** Async is most useful when your application spends time waiting for external resources. For CPU-intensive work, use parallel execution or dedicated workers rather than simply adding `async` to the function.
