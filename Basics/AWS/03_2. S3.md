# Amazon S3 — Complete Configuration Reference

## 1. Basic S3 Concepts

- Bucket — container that stores objects.
- Object — file plus its associated metadata.
- Key — unique object name within a bucket, such as `images/photo.jpg`.
- Prefix — beginning of an object key, commonly used to group objects logically, such as `images/`.
- Version ID — identifies a specific object version when versioning is enabled.
- Region — AWS Region where the bucket is created.
- Bucket ARN — bucket identifier, for example `arn:aws:s3:::my-app-bucket`.
- Object ARN — object identifier, for example `arn:aws:s3:::my-app-bucket/*`.
- Object metadata — system-defined and user-defined information associated with an object.
- ETag — identifier returned for an object; do not assume it is always an MD5 checksum.

S3 is object storage, not a traditional filesystem. Prefixes can resemble directories, but they are part of object keys.

## 2. Bucket Configuration

- Bucket name — globally unique within the applicable AWS partition for general purpose buckets.
- Region — choose near workloads, users, and dependent services, subject to compliance requirements.
- Bucket type — general purpose bucket for most workloads; directory buckets for supported S3 Express One Zone use cases; table and vector buckets for their specialized use cases.
- Bucket tags — key-value pairs for cost allocation, ownership, automation, and access-control strategies.
- Object Ownership — controls ownership and ACL behavior.
- Bucket policy — resource-based policy defining who can access the bucket and which actions are allowed.
- Block Public Access — controls public access through policies and ACLs.
- Versioning — preserves multiple versions of objects.
- Default encryption — applies server-side encryption to new objects.
- Lifecycle configuration — transitions or expires objects automatically.
- Replication configuration — copies eligible objects to destination buckets.
- CORS — allows browser applications from specified origins to make supported cross-origin requests.
- Event notifications — sends supported object events to configured destinations.
- Server access logging — records requests made to the bucket.
- Transfer Acceleration — can improve long-distance uploads and downloads.
- Object Lock — protects object versions from deletion or overwrite for a retention period or legal hold.
- Requester Pays — charges the requester for supported requests and data transfer.
- Static website hosting — serves static website content through the S3 website endpoint.
- Object Lock default retention — applies a default retention policy when configured.
- Ownership and access point settings — support controlled access patterns for applications and teams.

Reference: [S3 bucket properties](https://docs.aws.amazon.com/AmazonS3/latest/userguide/view-bucket-properties.html)

## 3. Object-Level Attributes

- Key — object name.
- Version ID — version identifier.
- Content-Length — object size in bytes.
- Content-Type — MIME type, such as `application/json`.
- Content-Encoding — encoding applied to the content, if any.
- Content-Disposition — controls download or browser presentation behavior.
- Cache-Control — browser and intermediary caching instructions.
- Last-Modified — time the object was last modified.
- ETag — object entity tag.
- Metadata — custom key-value information.
- Storage class — storage tier used by the object.
- Server-side encryption — encryption method used for the object.
- SSE-KMS key ID — KMS key identifier when applicable.
- Checksum — supported checksum algorithm and value for integrity verification.
- Object tags — up to 10 tags per object.
- Legal hold — protects an object version from deletion while the hold remains active.
- Retention mode — Governance or Compliance for Object Lock.
- Retain-until date — date until which a locked object version is protected.
- Replication status — status information for eligible replicated objects.
- Restore status — information about restoration of supported archived objects.
- Website redirect location — optional redirect metadata for supported website hosting behavior.

Example object key:

`reports/2026/october/report.pdf`

Example custom metadata:

`department=finance`

Metadata and tags serve different purposes. Use tags for lifecycle rules, access-control conditions, and classification where appropriate.

## 4. Storage Classes

- S3 Standard — frequently accessed general-purpose data.
- S3 Intelligent-Tiering — automatically moves eligible objects between access tiers based on access patterns.
- S3 Standard-IA — infrequently accessed data that needs rapid access.
- S3 One Zone-IA — infrequently accessed data stored in one Availability Zone.
- S3 Glacier Instant Retrieval — archive data requiring millisecond retrieval.
- S3 Glacier Flexible Retrieval — archive data with retrieval delays depending on the retrieval option.
- S3 Glacier Deep Archive — long-term archive with longer retrieval times.
- S3 Express One Zone — high-performance storage for supported latency-sensitive workloads.

Important:
- Storage classes have different retrieval charges, minimum storage durations, and minimum billable object sizes.
- One Zone-IA and S3 Express One Zone have different resilience characteristics from multi-AZ storage classes.
- Intelligent-Tiering has monitoring and automation charges for applicable objects.
- Archive classes may require a restore operation before an object can be read.
- Choose storage class based on access frequency, recovery requirements, durability needs, and total cost.

## 5. Security and Access Control

### IAM and Resource Policies

- IAM identity policy — grants permissions to users, roles, or groups.
- Bucket policy — grants or denies access at the bucket or object level.
- Access point policy — controls access through a particular S3 access point.
- VPC endpoint policy — restricts requests traversing the applicable endpoint.
- AWS Organizations SCP — sets maximum permissions for affected accounts; does not itself grant permissions.
- Permissions boundary — limits permissions available to an IAM principal.
- Explicit Deny — overrides an applicable Allow.
- Least privilege — grant only the required actions on the required resources.

### Object Ownership and ACLs

- Bucket owner enforced — recommended for most modern designs; disables ACLs and makes the bucket owner own objects.
- Bucket owner preferred — supports ACL-based ownership behavior.
- Object writer — legacy ownership behavior where the uploading account can own the object.
- ACLs — legacy access-control mechanism; avoid unless a specific integration requires them.

### Block Public Access

The four settings are:

- `BlockPublicAcls` — blocks new public ACLs.
- `IgnorePublicAcls` — ignores public ACLs.
- `BlockPublicPolicy` — blocks attempts to add public bucket policies.
- `RestrictPublicBuckets` — restricts access for buckets with public policies in applicable scenarios.

Production recommendation: enable all four unless a documented, reviewed requirement says otherwise.

### Other Security Controls

- S3 Access Points — separate access policies and network-origin controls for application access.
- Multi-Region Access Points — provide a global access endpoint across configured buckets and Regions.
- S3 Object Lambda — custom processing of data retrieved through supported access patterns; verify current service availability and feature requirements.
- CloudTrail data events — audit object-level API activity when configured.
- AWS Config — track supported resource configuration and compliance.
- Macie — discover and help protect sensitive data in S3.
- GuardDuty S3 Protection — detect supported suspicious S3 activity.
- TLS enforcement — use bucket policies to require secure transport.
- Encryption enforcement — use policies when a particular encryption configuration is required.
- Cross-account access — configure both the relevant resource and identity permissions as required.
- Presigned URLs — grant time-limited access using the permissions of the signing principal; anyone holding a valid URL may use it until it expires or becomes invalid.

## 6. Encryption Configuration

### Server-Side Encryption

- SSE-S3 — S3-managed encryption keys; default encryption for new S3 objects.
- SSE-KMS — encryption using AWS KMS keys.
- DSSE-KMS — dual-layer server-side encryption using AWS KMS.
- SSE-C — server-side encryption with a customer-provided key; the customer must securely manage and supply the key for supported operations.
- Client-side encryption — encrypt data before sending it to S3.

### KMS Configuration

- KMS key ARN or key ID — identifies the key used for SSE-KMS.
- Key policy — controls access to the KMS key.
- IAM permissions — authorize required KMS operations.
- Key rotation — use supported automatic or manual rotation approaches appropriate to the key.
- S3 Bucket Key — can reduce KMS request costs for supported SSE-KMS objects.
- DSSE-KMS — does not support S3 Bucket Keys.
- Cross-account KMS — requires correct key policy and caller permissions.
- Key deletion — scheduled key deletion can make encrypted data permanently unrecoverable once the key is deleted.

Important: S3 default encryption protects new objects, but it does not automatically re-encrypt every existing object after a configuration change.

## 7. Versioning and Data Protection

- Versioning Enabled — retains multiple versions of objects.
- Versioning Suspended — stops creating new normal version IDs, but existing versions remain.
- Delete marker — represents a delete operation in a versioned bucket; it does not immediately remove prior versions.
- Noncurrent versions — older versions retained after a newer version is written.
- MFA Delete — provides additional protection for certain versioning operations, subject to its setup requirements.
- Object Lock Governance mode — authorized principals with the necessary permission can bypass retention.
- Object Lock Compliance mode — protected versions cannot be overwritten or deleted during retention, including by the account root user.
- Legal hold — protects an object version until the hold is removed.
- Replication — copies eligible objects to a destination bucket.
- AWS Backup — provides supported backup management capabilities for S3.

Production recommendation:
- Enable versioning for important data.
- Define lifecycle rules for noncurrent versions.
- Use Object Lock where immutable retention is required.
- Use replication or backups when separate recovery copies are required.

## 8. Lifecycle Rules

Lifecycle rules automate object transitions and expiration.

Common configuration fields:

- `ID` — unique rule identifier within the lifecycle configuration.
- `Status` — Enabled or Disabled.
- `Filter` — identifies applicable objects by prefix, tags, object size, or supported combinations.
- `Prefix` — applies a rule to keys beginning with a specified string.
- `Tag` — selects objects with matching tags.
- `ObjectSizeGreaterThan` — filters by minimum size.
- `ObjectSizeLessThan` — filters by maximum size.
- `Transitions` — moves eligible objects to another storage class.
- `Days` — specifies an age-based action.
- `Date` — specifies a date-based action where supported.
- `StorageClass` — target storage class for a transition.
- `Expiration` — expires current objects.
- `NoncurrentVersionTransitions` — transitions older object versions.
- `NoncurrentVersionExpiration` — expires older versions.
- `NewerNoncurrentVersions` — can retain a specified number of newer noncurrent versions in supported rules.
- `AbortIncompleteMultipartUpload` — removes incomplete multipart uploads after a configured number of days.
- `ExpiredObjectDeleteMarker` — removes eligible expired delete markers.

Important:
- Lifecycle actions are asynchronous and do not execute at an exact guaranteed clock time.
- In versioned buckets, expiring a current object can create a delete marker while retaining old versions.
- Configure noncurrent-version expiration to prevent old versions from accumulating indefinitely.
- Object Lock retention can prevent expiration or deletion while protection remains active.
- Check minimum storage durations and transition charges before moving objects to archive classes.

## 9. Replication

- Same-Region Replication (SRR) — copies eligible objects to another bucket in the same Region.
- Cross-Region Replication (CRR) — copies eligible objects to another Region.
- Replication role — IAM role assumed by S3 to perform replication.
- Source bucket — bucket where eligible objects originate.
- Destination bucket — target bucket receiving replicas.
- Rule ID — identifier for a replication rule.
- Rule status — Enabled or Disabled.
- Filter — selects objects by prefix and/or tags.
- Destination storage class — optional destination storage class.
- Delete marker replication — controls replication of delete markers where supported.
- Existing object replication — use S3 Batch Replication for eligible existing objects.
- Replication Time Control (RTC) — optional service for supported time-bound replication objectives.
- Replication metrics — help track replication progress and failures.
- Destination encryption — configure the destination and KMS permissions appropriately for encrypted objects.
- Object ownership override — available for supported cross-account replication configurations.

Important:
- Versioning must be enabled on source and destination buckets for normal S3 live replication.
- Replication is asynchronous.
- Replication does not replace a backup strategy.
- Delete operations and replication behavior depend on the configured rules.
- Avoid assuming every object or every historical version is replicated automatically.

## 10. Event Notifications and Integrations

S3 can publish supported events when objects are created, removed, restored, or otherwise changed.

Destinations include:
- Amazon SQS — queues.
- Amazon SNS — notifications.
- AWS Lambda — invoke functions.
- Amazon EventBridge — route supported events to many AWS services.

Configuration concepts:
- Event types — select the operations to monitor.
- Prefix filter — process keys beginning with a specified prefix.
- Suffix filter — process keys ending with a specified suffix.
- Destination permissions — allow S3 to publish to or invoke the destination.
- EventBridge integration — enable S3 event delivery to EventBridge.
- Retry and failure handling — configure appropriate destination-side processing and recovery.
- Idempotency — ensure duplicate event processing does not corrupt application state.

Important:
- S3 event notifications are designed for at-least-once delivery and can arrive out of order.
- Do not assume exactly-once processing.
- Avoid creating a Lambda trigger that writes to the same triggering prefix without safeguards, as it can create a processing loop.
- Event notification filters cannot use overlapping prefix/suffix combinations for the same event type in all configurations.

## 11. CORS and Static Website Hosting

### CORS

- `AllowedOrigins` — browser origins permitted to access the bucket cross-origin.
- `AllowedMethods` — HTTP methods permitted.
- `AllowedHeaders` — request headers allowed.
- `ExposeHeaders` — response headers visible to browser JavaScript.
- `MaxAgeSeconds` — duration for which the browser may cache preflight results.

CORS is a browser-enforced cross-origin mechanism. It is not an authentication or authorization system.

### Static Website Hosting

- `IndexDocument` — default page, such as `index.html`.
- `ErrorDocument` — error page, such as `error.html`.
- `RoutingRules` — supported redirect and routing behavior.

Important:
- The S3 website endpoint does not itself provide HTTPS.
- For a production public website, CloudFront with HTTPS and an appropriately configured S3 origin is commonly preferred.
- A private S3 bucket can be used with CloudFront Origin Access Control (OAC).
- S3 website hosting and private bucket access have different requirements; do not make a bucket public just to serve content through CloudFront.

## 12. Networking and VPC Endpoints

### Gateway VPC Endpoint

- Commonly preferred for private S3 access from VPC workloads.
- Adds routes to selected route tables.
- Does not create endpoint ENIs in subnets.
- Does not require a NAT Gateway for traffic using the endpoint.
- Supports endpoint policies to restrict access through the endpoint.
- S3 bucket policies can restrict access to a specified VPC endpoint where appropriate.

### Interface VPC Endpoint

- Uses AWS PrivateLink and endpoint network interfaces.
- Supports private IP connectivity for supported S3 access patterns.
- Has endpoint-related charges.
- May be appropriate for specific on-premises or private connectivity requirements.

### Networking Checks

- Route table — confirm the appropriate S3 route for a gateway endpoint.
- DNS — confirm correct resolution for the chosen endpoint pattern.
- Security groups — relevant to interface endpoint network interfaces.
- Endpoint policy — restricts requests that use the endpoint.
- IAM role — grants required S3 actions.
- Bucket policy — must permit the intended access.
- KMS permissions — required when using SSE-KMS.
- Cross-Region access — confirm routing, endpoint behavior, and Region-specific requirements.

Important: A VPC endpoint does not place S3 inside your VPC. It provides a private network path to the AWS-managed service.

## 13. Performance and Upload Configuration

- Multipart upload — splits large objects into parts for parallel upload.
- Part size — select based on object size, concurrency, and retry behavior.
- Parallelism — can improve throughput when configured appropriately.
- Checksums — validate transfer integrity.
- Retry strategy — use appropriate SDK retries and backoff for transient failures.
- Transfer Acceleration — optional feature for supported long-distance transfers.
- Byte-range GET — retrieve selected ranges of an object.
- S3 Select — legacy/limited feature availability; verify current support before designing new systems around it.
- CloudFront — cache frequently requested content close to users.
- S3 Express One Zone — consider for supported workloads needing very low latency.
- Request distribution — avoid unnecessary bottlenecks in client concurrency and downstream processing.
- Connection pooling — reuse SDK connections when possible.

Important:
- Multipart upload is useful for large files and resilient transfers.
- Configure cleanup for incomplete multipart uploads.
- S3 provides strong read-after-write consistency for object PUTs and DELETEs, but application workflows still need idempotency and correct concurrency handling.
- ETag is not a universal integrity checksum, especially for multipart uploads and some encryption modes.

## 14. Monitoring, Logging and Inventory

- CloudTrail management events — audit supported bucket and configuration operations.
- CloudTrail data events — audit object-level API activity when enabled.
- S3 Server Access Logging — records request details in a target bucket.
- CloudWatch metrics — monitor supported S3 usage and request metrics.
- S3 Storage Lens — analyze usage and activity across buckets and accounts.
- S3 Inventory — scheduled reports of objects and selected metadata.
- AWS Config — track supported configuration changes and compliance.
- CloudWatch alarms — alert on relevant supported metrics.
- Event notifications — trigger workflows when supported object events occur.
- Replication metrics — monitor replication status and failures.

Important:
- CloudTrail object-level data events can incur additional charges.
- Server access logging is not enabled by default.
- S3 Inventory is a scheduled report, not a real-time listing.
- Ensure logs are protected from alteration and unauthorized access.

## 15. Cost Configuration

Main cost drivers:

- Storage volume — GB-months in each storage class.
- Requests — GET, PUT, LIST, and other API requests.
- Data retrieval — applies to relevant storage classes.
- Data transfer — costs depend on source, destination, and network path.
- Replication — destination storage, requests, and applicable transfer charges.
- KMS — applicable API request and key charges.
- Lifecycle transitions — applicable transition requests and minimum-duration considerations.
- Incomplete multipart uploads — can continue to incur storage charges.
- Versioning — old versions continue consuming storage.
- Inventory and Storage Lens — pricing depends on the selected features and configuration.
- S3 Transfer Acceleration — additional transfer charges.
- Interface endpoints — endpoint and data processing charges.
- NAT Gateway — hourly and data processing charges when traffic uses it.

Cost controls:
- Configure lifecycle transitions and expiration.
- Expire noncurrent versions where safe.
- Abort incomplete multipart uploads.
- Use storage classes appropriate to access patterns.
- Use S3 Bucket Keys where supported and appropriate for SSE-KMS.
- Use Cost Explorer and cost allocation tags.
- Review data transfer and endpoint architecture.
- Avoid retaining redundant versions and replicas indefinitely without a requirement.

## 16. Important Limits and Exceptions

- Object size — maximum supported object size is 50 TB minus 1 byte; verify the current AWS General Reference for the exact limit.
- Multipart upload — required for uploading objects beyond the supported single-operation upload limit.
- Multipart part size — generally 5 MiB minimum except the last part, and up to 5 GiB per part.
- Object tags — maximum 10 tags per object.
- Lifecycle rules — maximum 1,000 rules per lifecycle configuration.
- Bucket names — follow S3 naming rules; names must be unique within the applicable partition for general purpose buckets.
- Object keys — maximum 1,024 bytes.
- Versioning — versioning is disabled by default on a newly created general purpose bucket unless enabled or automatically enabled by a configuration such as Object Lock.
- Object Lock — requires versioning and cannot be disabled after being enabled on a bucket.
- Object Lock Compliance mode — cannot be bypassed to delete a protected version before retention expires.
- Bucket Region — bucket location is fixed after creation; moving data to another Region requires copying or replication.
- S3 consistency — strong consistency does not make a multi-step application workflow transactional.
- Public access — S3 objects are private by default; access depends on policies and applicable controls.
- Website hosting — S3 website endpoints do not provide HTTPS by themselves.
- Archive retrieval — some storage classes require restoration before reading an object.
- Replication — asynchronous and not a substitute for backup.
- Event delivery — can be duplicated or arrive out of order.
- IAM, bucket, endpoint, and KMS policies — must all align for the relevant request to succeed.

Check current quotas and service-specific exceptions:
https://docs.aws.amazon.com/general/latest/gr/s3.html

## 17. Production Baseline

For a typical private application bucket:

- Block all public access.
- Use Bucket owner enforced unless ACLs are specifically required.
- Enable versioning for important data.
- Keep default encryption enabled.
- Use SSE-KMS when customer-managed key control or audit requirements justify it; otherwise SSE-S3 may be sufficient.
- Enable an S3 Gateway VPC endpoint for private access from VPC workloads where appropriate.
- Use least-privilege IAM roles and bucket policies.
- Enforce TLS.
- Configure lifecycle rules for current and noncurrent versions.
- Abort incomplete multipart uploads.
- Enable CloudTrail data events where object-level auditing is required.
- Enable replication, backups, or Object Lock according to recovery and compliance requirements.
- Monitor cost, access patterns, replication failures, and security findings.
- Manage configuration through Terraform or another infrastructure-as-code tool.

## 18. Terraform Example — Private Production-Oriented Bucket

```hcl
resource "aws_s3_bucket" "app_data" {
  bucket = "replace-with-a-globally-unique-bucket-name"

  tags = {
    Environment = "production"
    ManagedBy   = "terraform"
    DataClass   = "application"
  }

  lifecycle {
    prevent_destroy = true
  }
}

resource "aws_s3_bucket_public_access_block" "app_data" {
  bucket = aws_s3_bucket.app_data.id

  block_public_acls       = true
  ignore_public_acls      = true
  block_public_policy     = true
  restrict_public_buckets = true
}

resource "aws_s3_bucket_ownership_controls" "app_data" {
  bucket = aws_s3_bucket.app_data.id

  rule {
    object_ownership = "BucketOwnerEnforced"
  }
}

resource "aws_s3_bucket_versioning" "app_data" {
  bucket = aws_s3_bucket.app_data.id

  versioning_configuration {
    status = "Enabled"
  }
}

resource "aws_s3_bucket_server_side_encryption_configuration" "app_data" {
  bucket = aws_s3_bucket.app_data.id

  rule {
    apply_server_side_encryption_by_default {
      sse_algorithm = "AES256"
    }
  }
}

resource "aws_s3_bucket_lifecycle_configuration" "app_data" {
  bucket = aws_s3_bucket.app_data.id

  rule {
    id     = "abort-incomplete-multipart-uploads"
    status = "Enabled"

    filter {}

    abort_incomplete_multipart_upload {
      days_after_initiation = 7
    }
  }
}
```

Terraform notes:
- Replace the bucket name with a globally unique name.
- `prevent_destroy` is a Terraform safeguard, not an S3 deletion lock; it does not protect against deletion outside Terraform.
- The example uses SSE-S3. Change the encryption configuration for SSE-KMS if required.
- Add lifecycle expiration or archival transitions only after defining retention requirements.
- Add bucket policies, endpoint policies, logging, CloudTrail data events, replication, and Object Lock according to your threat model and operational requirements.
- Pin Terraform and AWS provider versions in a real production repository.
- Test plans before applying changes to production.

## 19. Quick Decision Summary

- Need to store files or backups? Use S3.
- Need private access from a VPC? Usually use an S3 Gateway endpoint.
- Need recoverable object history? Enable Versioning.
- Need immutable retention? Use Object Lock with an appropriate retention mode.
- Need cross-Region copies? Configure CRR.
- Need cheaper long-term retention? Consider lifecycle transitions to archive storage classes.
- Need encryption-key control? Consider SSE-KMS.
- Need browser access from a web application? Configure CORS only when required; CORS does not grant S3 permissions.
- Need a public static website? Consider CloudFront with HTTPS and a private S3 origin.
- Need audit records? Configure CloudTrail data events and/or server access logging.
- Need to prevent accidental public exposure? Enable all S3 Block Public Access settings and review bucket policies.
- Need predictable costs? Manage versions, lifecycle, incomplete uploads, request patterns, and data transfer.
