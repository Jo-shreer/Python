# AWS Services: VPC vs Non-VPC

## 1. Services that reside in or attach to your VPC

- EC2 — instances run in VPC subnets.
- ECS on EC2 — container instances run in subnets.
- ECS Fargate — tasks use ENIs in your subnets.
- EKS — worker nodes and pods can run in your VPC; the control plane is AWS-managed.
- RDS — database instances use VPC subnets.
- Aurora — database instances use VPC subnets.
- ElastiCache — cache nodes run in your VPC.
- MemoryDB — nodes run in your VPC.
- Redshift — can be deployed in a VPC.
- OpenSearch Service — can be deployed in a VPC.
- Amazon MQ — brokers can be deployed in a VPC.
- MSK (Managed Kafka) — brokers run in your VPC.
- EFS — accessed through mount targets in your VPC.
- FSx — file systems can use network interfaces in your VPC.
- Application Load Balancer (ALB) — deployed in VPC subnets.
- Network Load Balancer (NLB) — deployed in VPC subnets.
- NAT Gateway — created in a public subnet.
- Internet Gateway — attached to a VPC.
- VPC endpoints — configured for private connectivity to supported services.
- Transit Gateway — connects VPCs and other networks.
- AWS Network Firewall — uses VPC subnets.
- AWS Client VPN — connects clients to VPC resources.

## 2. AWS-managed services that do not reside inside your VPC

These services run on AWS-managed infrastructure. Supported services can be accessed privately using VPC endpoints.

- DynamoDB — Gateway endpoint or interface endpoint.
- S3 — Gateway endpoint or interface endpoint.
- SQS — Interface endpoint.
- SNS — Interface endpoint.
- EventBridge — Interface endpoint.
- Lambda service API — Interface endpoint; Lambda functions can also attach to a VPC.
- Secrets Manager — Interface endpoint.
- Systems Manager (SSM) — Interface endpoints.
- CloudWatch — Interface endpoints for supported APIs.
- CloudWatch Logs — Interface endpoint.
- ECR API — Interface endpoint.
- ECR Docker registry — Interface endpoint.
- KMS — Interface endpoint.
- STS — Interface endpoint.
- Step Functions — Interface endpoint.
- API Gateway — Private APIs can be accessed through an interface endpoint.
- AWS Glue — Interface endpoints for supported APIs.
- Amazon Bedrock — Interface endpoint for supported APIs.
- CodeArtifact — Interface endpoint.
- AppConfig — Interface endpoint.
- AWS Backup — Interface endpoints for supported APIs.
- CloudFormation — Interface endpoint.
- Cognito — Endpoint options depend on the API and service configuration.
- AWS Organizations — AWS-managed control-plane service; endpoint options depend on the API.

## 3. VPC endpoint types

- Gateway endpoint — primarily S3 and DynamoDB.
- Interface endpoint (AWS PrivateLink) — SQS, SNS, EventBridge, Secrets Manager, KMS, CloudWatch, SSM, ECR, and other supported services.
- Gateway Load Balancer endpoint — connects VPC traffic to supported virtual network appliances.
- Other PrivateLink options — support access to specific services and resources, depending on configuration.

## 4. Important exceptions

- Lambda: The service is AWS-managed. Configure VPC subnets and security groups when a function needs access to private VPC resources.
- EKS: AWS manages the control plane; worker nodes and pods can run in your VPC.
- ECS: Tasks can use your VPC subnets and security groups.
- S3 and DynamoDB: They are not deployed in your VPC. Gateway endpoints provide private routing without requiring a NAT Gateway.
- API Gateway: The service is AWS-managed; a private API can be accessed through an interface endpoint.
- EFS: AWS manages the file system; mount targets are created in your VPC.

## 5. Example architecture

Private subnet:
- EC2
- ECS tasks
- VPC-attached Lambda
- RDS

Private connectivity through VPC endpoints to AWS-managed services:
- S3
- DynamoDB
- SQS
- SNS
- EventBridge
- Secrets Manager

## 6. Quick decision summary

- **Need to run compute in your network?** Use EC2, ECS, EKS worker nodes, or VPC-attached Lambda.
- **Need a relational database in your VPC?** Use RDS or Aurora.
- **Need managed cache or messaging brokers in your VPC?** Consider ElastiCache, MemoryDB, or MSK.
- **Need private access to S3 or DynamoDB?** Use a Gateway VPC endpoint in most cases.
- **Need private access to SQS, SNS, EventBridge, Secrets Manager, KMS, or CloudWatch?** Use an Interface VPC endpoint when supported.
- **Need outbound internet access from a private subnet?** Use a NAT Gateway, unless the required traffic can use private endpoints or another private network path.
- **Need inbound public HTTP/HTTPS traffic?** Use an internet-facing ALB/NLB in an appropriate public-subnet design, with application resources kept private where possible.
- **Need private connectivity from your office or data center?** Consider Site-to-Site VPN or Direct Connect.
- **Need to connect multiple VPCs?** Consider VPC peering or Transit Gateway, depending on scale and routing requirements.

**Rule of thumb:** Your workloads and many databases live in your VPC. AWS-managed services such as S3, DynamoDB, SQS, and SNS do not; use VPC endpoints when supported to access them privately.

## 7. Production notes

- A VPC endpoint does not move an AWS service into your VPC; it provides a private path to that service.
- Private subnets do not automatically have private access to every AWS service.
- Gateway endpoints do not require a NAT Gateway for supported S3 and DynamoDB traffic.
- Interface endpoints typically use endpoint network interfaces and security groups.
- Configure IAM permissions, endpoint policies where supported, DNS, routing, and security groups correctly.
- Check endpoint availability and regional support for each service before designing the architecture.
