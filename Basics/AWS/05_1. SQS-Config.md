# Amazon SQS — Production Configuration and Python Reference

## 1. Purpose

Use Terraform to provision and configure SQS. Use Python/Boto3 to send, receive, and process messages.

## 2. SQS Queue Configuration Attributes

### General queue settings

| Terraform argument | AWS queue attribute | Purpose |
|---|---|---|
| `name` | `QueueName` | Queue name |
| `fifo_queue` | `FifoQueue` | Standard or FIFO |
| `visibility_timeout_seconds` | `VisibilityTimeout` | Time a received message stays invisible |
| `message_retention_seconds` | `MessageRetentionPeriod` | Message retention, 60–1,209,600 seconds |
| `delay_seconds` | `DelaySeconds` | Default delivery delay, 0–900 seconds |
| `max_message_size` | `MaximumMessageSize` | Maximum message size, up to 1 MiB |
| `receive_wait_time_seconds` | `ReceiveMessageWaitTimeSeconds` | Long polling, 0–20 seconds |
| `redrive_policy` | `RedrivePolicy` | Configure the dead-letter queue |
| `redrive_allow_policy` | `RedriveAllowPolicy` | Control which source queues can use a DLQ |
| `policy` | `Policy` | Queue resource policy |
| `sqs_managed_sse_enabled` | `SqsManagedSseEnabled` | SQS-managed encryption at rest |
| `kms_master_key_id` | `KmsMasterKeyId` | Customer-managed or AWS KMS key |
| `kms_data_key_reuse_period_seconds` | `KmsDataKeyReusePeriodSeconds` | KMS data-key reuse interval |
| `tags` | Resource tags | Ownership, environment, cost allocation |

### FIFO-specific settings

| Terraform argument | AWS queue attribute | Purpose |
|---|---|---|
| `content_based_deduplication` | `ContentBasedDeduplication` | Deduplicate using message content |
| `deduplication_scope` | `DeduplicationScope` | Deduplicate by queue or message group |
| `fifo_throughput_limit` | `FifoThroughputLimit` | Configure FIFO throughput scope |

**Important:** FIFO queue names must end in `.fifo`. FIFO deduplication does not replace application-level idempotency.

### Additional AWS queue attributes

These can be inspected through `get_queue_attributes`:

- `QueueArn`
- `CreatedTimestamp`
- `LastModifiedTimestamp`
- `ApproximateNumberOfMessages`
- `ApproximateNumberOfMessagesNotVisible`
- `ApproximateNumberOfMessagesDelayed`

The last three are approximate queue counts. They are useful for monitoring, not precise transactional state.

Other attributes are listed above, including `Policy`, `RedrivePolicy`, encryption settings, and FIFO settings.

## 5. Production Terraform Example

Example `main.tf` for a Standard queue with a dead-letter queue, encryption, long polling, and tags.

```hcl
terraform {
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      # Pin a tested version or approved version range
    }
  }
}

provider "aws" {
  region = var.aws_region

  default_tags {
    tags = {
      Environment = var.environment
      ManagedBy   = "Terraform"
      Service     = "orders"
    }
  }
}

variable "aws_region" {
  type    = string
  default = "eu-west-1"
}

variable "environment" {
  type    = string
  default = "prod"
}

resource "aws_sqs_queue" "orders_dlq" {
  name                      = "${var.environment}-orders-dlq"
  message_retention_seconds = 1209600
  sqs_managed_sse_enabled   = true
}

resource "aws_sqs_queue" "orders" {
  name                       = "${var.environment}-orders"
  visibility_timeout_seconds = 60
  message_retention_seconds  = 345600
  receive_wait_time_seconds  = 20
  delay_seconds              = 0
  max_message_size           = 262144

  sqs_managed_sse_enabled = true

  redrive_policy = jsonencode({
    deadLetterTargetArn = aws_sqs_queue.orders_dlq.arn
    maxReceiveCount     = 5
  })

  tags = {
    Purpose = "Order processing"
  }
}

output "orders_queue_url" {
  value = aws_sqs_queue.orders.url
}

output "orders_queue_arn" {
  value = aws_sqs_queue.orders.arn
}
```

**Production notes**

- Pin the AWS provider to a tested version in your real configuration and commit `.terraform.lock.hcl`.
- Store the queue URL in deployment configuration, such as an environment variable.
- Grant the application's IAM role only the required SQS permissions.
- Add CloudWatch alarms, a documented DLQ recovery procedure, and a queue resource policy where needed.
- Consider a customer-managed KMS key if your compliance requirements demand it.
- Tune the visibility timeout to your processing duration. Ensure consumers handle duplicate deliveries safely.
- Set `maxReceiveCount` according to your retry strategy.

## 6. Python Producer Example

The queue is provisioned by Terraform. The application only sends messages.

```python
import json
import os

import boto3

sqs = boto3.client(
    "sqs",
    region_name=os.environ["AWS_REGION"],
)

QUEUE_URL = os.environ["SQS_QUEUE_URL"]


def send_order(order_id: str) -> str:
    response = sqs.send_message(
        QueueUrl=QUEUE_URL,
        MessageBody=json.dumps({
            "order_id": order_id,
            "event_type": "order_created",
        }),
    )
    return response["MessageId"]


if __name__ == "__main__":
    message_id = send_order("order-123")
    print(f"Sent message: {message_id}")
```

Configure `AWS_REGION` and `SQS_QUEUE_URL` in your runtime environment. Use an IAM role in AWS rather than hardcoded credentials.

## 7. Python Consumer Pattern

```python
import os
import boto3

sqs = boto3.client("sqs", region_name=os.environ["AWS_REGION"])
QUEUE_URL = os.environ["SQS_QUEUE_URL"]


def process_message(body: str) -> None:
    # Validate and process the message.
    print(body)


def consume_once() -> None:
    response = sqs.receive_message(
        QueueUrl=QUEUE_URL,
        MaxNumberOfMessages=10,
        WaitTimeSeconds=20,
        VisibilityTimeout=60,
    )

    for message in response.get("Messages", []):
        try:
            process_message(message["Body"])

            # Delete only after successful processing.
            sqs.delete_message(
                QueueUrl=QUEUE_URL,
                ReceiptHandle=message["ReceiptHandle"],
            )
        except Exception:
            # Do not delete failed messages.
            # They can become visible again after the timeout.
            raise
```

A real consumer should catch failures per message, log errors, use appropriate retry/backoff behavior, and avoid terminating the whole batch because one message fails. Ensure processing is idempotent.
