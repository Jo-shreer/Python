
# Enterprise Amazon Redshift RA3
## Production Terraform Implementation Guide

---

# 1. Introduction

This document explains how to provision an enterprise-grade Amazon Redshift RA3 provisioned cluster using Terraform.

The implementation covers infrastructure prerequisites, security, networking, IAM integration, encryption, monitoring, backup, deployment, and post-deployment verification.

The Terraform implementation is maintained in a single `main.tf` file. Logical sections are separated using comments such as VARIABLES.TF, IAM.TF, SECURITY.TF, and MONITORING.TF.

### Architecture

- Compute: Amazon Redshift RA3 provisioned cluster.
- Cluster type: Multi-node.
- Networking: Private VPC.
- Encryption: AWS KMS customer-managed key.
- Authentication: Redshift-managed master credentials.
- Secrets: AWS Secrets Manager.
- IAM: Dedicated Redshift IAM role.
- Storage integration: Amazon S3.
- Routing: Enhanced VPC routing.
- Monitoring: Amazon CloudWatch.
- Logging: Connection, user, and user activity logs.
- Backup: Automated and manual snapshots.
- Security: Private access, restricted security groups, and deletion protection.

# 2. Prerequisites

Before creating the Redshift cluster, the following AWS resources and configurations must be available.

## 2.1 AWS Account

You need:

- An active AWS account.
- Appropriate IAM permissions.
- Access to the target AWS region.
- An approved deployment identity.

For enterprise deployments, use AWS IAM Identity Center or an assumed IAM deployment role instead of long-lived access keys.

The deployment identity needs permissions to manage:

- Amazon Redshift.
- Amazon EC2 security groups.
- Redshift subnet groups.
- IAM roles and policies.
- AWS KMS.
- AWS CloudWatch.
- AWS Secrets Manager.

It also needs the necessary permissions to pass the Redshift IAM role.

## 2.2 Install Terraform

Install Terraform version 1.6 or later.

Verify installation:

```bash
terraform version
```

## 2.3 Install AWS CLI

Install AWS CLI and configure authentication.

Verify installation:

```bash
aws --version
```

For an AWS IAM Identity Center profile:

```bash
aws configure sso
aws sso login --profile production
export AWS_PROFILE=production
```

Verify AWS connectivity:

```bash
aws sts get-caller-identity
```

This confirms which AWS account and identity Terraform will use.

## 2.4 Create VPC

Redshift should be deployed inside a private VPC.

Before creating Redshift, ensure that:

- A VPC is available.
- Private subnets are configured.
- Route tables are configured.
- Network ACLs permit required traffic.
- The subnets have sufficient available IP addresses.

Example:

```text
VPC: 10.10.0.0/16

Private Subnet 1:
10.10.1.0/24
Availability Zone: eu-west-1a

Private Subnet 2:
10.10.2.0/24
Availability Zone: eu-west-1b
```

The example Terraform configuration uses existing VPC and subnet IDs. It does not create the VPC itself.

## 2.5 Create Private Subnets

Create at least two suitable private subnets.

Requirements:

- Subnets must belong to the same VPC.
- Subnets should span different Availability Zones.
- Subnets must satisfy Redshift subnet-group requirements.
- Subnets should have sufficient available IP addresses.
- Public internet exposure should not be required for Redshift clients.

## 2.6 Create Application Security Group

Identify the security group attached to the applications that need Redshift connectivity.

Examples:

- ETL applications.
- AWS Glue workloads.
- EC2 applications.
- Private application services.
- Approved analytics clients.

Redshift uses TCP port 5439 by default.

Only trusted application security groups should be allowed to connect.

Avoid:

```text
0.0.0.0/0
```

for Redshift inbound access.

## 2.7 Create AWS KMS Key

Create a customer-managed KMS key for Redshift encryption.

Recommended settings:

- Key type: Symmetric.
- Key usage: Encrypt and decrypt.
- Key rotation: Enabled where appropriate.
- Key administrators: Restricted.
- Key users: Restricted.
- Key policy: Allow required Redshift and deployment operations.

Redshift encryption protects data at rest.

The Terraform configuration accepts the existing KMS key ARN.

## 2.8 Create S3 Bucket

If Redshift needs to load or unload data, create an S3 bucket.

Example:

```text
enterprise-data-lake-prod
    |
    |-- warehouse/
    |
    |-- staging/
    |
    |-- archive/
```

Redshift can use S3 for:

- COPY operations.
- UNLOAD operations.
- Data ingestion.
- Data exports.
- Data lake integration.

Restrict IAM permissions to required bucket paths.

If S3 uses SSE-KMS encryption, configure the necessary KMS permissions as well.

## 2.9 Create SNS Topic

Create an SNS topic if CloudWatch alarms should send notifications.

Example:

```text
enterprise-redshift-alerts
```

Subscribe the operations team or monitoring platform to this topic.

The SNS topic ARN will be passed to Terraform.

## 2.10 Configure Terraform State Storage

For enterprise environments, Terraform state should be stored remotely.

Recommended:

- Amazon S3 backend.
- Encryption enabled.
- Bucket versioning enabled.
- Restricted bucket access.
- State locking enabled.
- Separate state access permissions.

Create the state bucket and locking configuration separately before initializing the Redshift Terraform stack.

Terraform state must be treated as sensitive infrastructure data.

# 3. Recommended Infrastructure Creation Sequence

Follow this sequence when deploying Redshift.

### Step 1: Prepare AWS Account

Confirm AWS account, deployment role, permissions, and region.

### Step 2: Prepare Networking

Create or identify:

- VPC.
- Private subnets.
- Route tables.
- Network ACLs.
- Application security groups.

### Step 3: Prepare Encryption

Create the KMS key and configure the required key policy.

### Step 4: Prepare S3

Create the data lake bucket and required prefixes.

### Step 5: Prepare Monitoring

Create the SNS topic and configure notification subscriptions.

### Step 6: Prepare Terraform

Install Terraform and AWS CLI.

Configure AWS authentication.

### Step 7: Create Terraform Configuration

Create a directory:

```bash
mkdir redshift-enterprise
cd redshift-enterprise
```

Create the main file:

```bash
touch main.tf
```

Paste the complete Terraform configuration into this file.

### Step 8: Create terraform.tfvars

Create the variables file:

```bash
touch terraform.tfvars
```

Provide actual AWS resource IDs and configuration values.

### Step 9: Initialize Terraform

```bash
terraform init
```

### Step 10: Format Terraform

```bash
terraform fmt -recursive
```

### Step 11: Validate Terraform

```bash
terraform validate
```

### Step 12: Review Terraform Plan

```bash
terraform plan -out=redshift.tfplan
```

Review every resource and configuration change.

### Step 13: Deploy Redshift

After approval:

```bash
terraform apply redshift.tfplan
```

### Step 14: Verify Deployment

Confirm the cluster status is Available.

Check networking, encryption, IAM, monitoring, and snapshots.

### Step 15: Test Database Connectivity

Connect from an approved private application or database client.

Verify SSL connectivity and database authentication.

```text
redshift-enterprise/
|
|-- main.tf
|
|-- terraform.tfvars
|
|-- .terraform.lock.hcl
|
|-- terraform.tfstate
|
|-- terraform.tfstate.backup
```

Logical sections inside main.tf:

```text
PROVIDER.TF
VARIABLES.TF
LOCALS.TF
SECURITY.TF
IAM.TF
PARAMETER-GROUP.TF
MAIN.TF
MONITORING.TF
OUTPUTS.TF
```

Note:

The logical sections are comments, not separate physical Terraform files.

The Terraform state files should not be committed to Git.

# 5. Complete Terraform Configuration

Create a file called main.tf.

The configuration below contains all Terraform resources in one file.

```hcl
# ============================================================
# ENTERPRISE AMAZON REDSHIFT RA3
# PRODUCTION CONFIGURATION
# SINGLE FILE: main.tf
# ============================================================


# ============================================================
# PROVIDER.TF
# ============================================================

terraform {
  required_version = ">= 1.6.0"

  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 6.0"
    }
  }
}

provider "aws" {
  region = var.aws_region

  default_tags {
    tags = {
      Environment = "production"
      Project     = "enterprise-data-warehouse"
      ManagedBy   = "terraform"
      Service     = "redshift"
    }
  }
}


# ============================================================
# VARIABLES.TF
# ============================================================

variable "aws_region" {
  description = "AWS deployment region"
  type        = string
  default     = "eu-west-1"
}

variable "cluster_identifier" {
  description = "Redshift cluster identifier"
  type        = string
  default     = "enterprise-prod-redshift"
}

variable "database_name" {
  description = "Initial database name"
  type        = string
  default     = "analytics"
}

variable "master_username" {
  description = "Redshift master username"
  type        = string
  default     = "redshiftadmin"
}

variable "node_type" {
  description = "Redshift RA3 node type"
  type        = string
  default     = "ra3.xlplus"
}

variable "number_of_nodes" {
  description = "Number of Redshift nodes"
  type        = number
  default     = 2

  validation {
    condition     = var.number_of_nodes >= 2
    error_message = "Production multi-node cluster requires at least two nodes."
  }
}

variable "vpc_id" {
  description = "Existing VPC ID"
  type        = string
}

variable "private_subnet_ids" {
  description = "Private subnet IDs"
  type        = list(string)
}

variable "application_security_group_ids" {
  description = "Approved application security group IDs"
  type        = list(string)
  default     = []
}

variable "kms_key_arn" {
  description = "Customer-managed KMS key ARN"
  type        = string
}

variable "snapshot_retention_days" {
  description = "Automated snapshot retention"
  type        = number
  default     = 14
}

variable "alarm_sns_topic_arn" {
  description = "SNS notification topic ARN"
  type        = string
  default     = null
}


# ============================================================
# LOCALS.TF
# ============================================================

locals {
  common_tags = {
    Environment = "production"
    Application = "enterprise-data-warehouse"
    Owner       = "data-platform-team"
  }
}


# ============================================================
# SECURITY.TF
# REDSHIFT SUBNET GROUP
# ============================================================

resource "aws_redshift_subnet_group" "redshift_subnet" {

  name = "enterprise-prod-redshift-subnet"

  description = "Private subnet group for production Redshift"

  subnet_ids = var.private_subnet_ids

  tags = local.common_tags

  lifecycle {
    precondition {
      condition = length(var.private_subnet_ids) >= 2

      error_message = "Provide at least two private subnets."
    }
  }
}


# ============================================================
# SECURITY.TF
# REDSHIFT SECURITY GROUP
# ============================================================

resource "aws_security_group" "redshift_sg" {

  name = "enterprise-prod-redshift-sg"

  description = "Restricted access to production Redshift"

  vpc_id = var.vpc_id

  tags = local.common_tags
}


# ============================================================
# SECURITY.TF
# REDSHIFT INGRESS RULE
# ============================================================

resource "aws_vpc_security_group_ingress_rule" "redshift_ingress" {

  for_each = toset(var.application_security_group_ids)

  security_group_id = aws_security_group.redshift_sg.id

  referenced_security_group_id = each.value

  ip_protocol = "tcp"

  from_port = 5439

  to_port = 5439

  description = "Approved application access"
}


# ============================================================
# SECURITY.TF
# REDSHIFT EGRESS RULE
# ============================================================

resource "aws_vpc_security_group_egress_rule" "redshift_https" {

  security_group_id = aws_security_group.redshift_sg.id

  ip_protocol = "tcp"

  from_port = 443

  to_port = 443

  cidr_ipv4 = "0.0.0.0/0"

  description = "HTTPS outbound access - review enterprise network policy"
}


# ============================================================
# IAM.TF
# REDSHIFT IAM ROLE
# ============================================================

resource "aws_iam_role" "redshift_role" {

  name = "enterprise-prod-redshift-role"

  assume_role_policy = jsonencode({

    Version = "2012-10-17"

    Statement = [{

      Effect = "Allow"

      Principal = {
        Service = "redshift.amazonaws.com"
      }

      Action = "sts:AssumeRole"
    }]
  })

  tags = local.common_tags
}


# ============================================================
# IAM.TF
# S3 ACCESS POLICY
# ============================================================

resource "aws_iam_policy" "redshift_s3_policy" {

  name = "enterprise-prod-redshift-s3-access"

  description = "Restricted S3 read access for Redshift"

  policy = jsonencode({

    Version = "2012-10-17"

    Statement = [

      {
        Effect = "Allow"

        Action = [
          "s3:GetObject"
        ]

        Resource = [
          "arn:aws:s3:::enterprise-data-lake-prod/warehouse/*"
        ]
      },

      {
        Effect = "Allow"

        Action = [
          "s3:ListBucket"
        ]

        Resource = [
          "arn:aws:s3:::enterprise-data-lake-prod"
        ]

        Condition = {
          StringLike = {
            "s3:prefix" = [
              "warehouse/*"
            ]
          }
        }
      }
    ]
  })

  tags = local.common_tags
}


# ============================================================
# IAM.TF
# ATTACH S3 POLICY TO REDSHIFT ROLE
# ============================================================

resource "aws_iam_role_policy_attachment" "redshift_s3_attachment" {

  role = aws_iam_role.redshift_role.name

  policy_arn = aws_iam_policy.redshift_s3_policy.arn
}


# ============================================================
# PARAMETER-GROUP.TF
# REDSHIFT PARAMETER GROUP
# ============================================================

resource "aws_redshift_parameter_group" "production" {

  name = "enterprise-prod-redshift-params"

  family = "redshift-1.0"

  description = "Enterprise production Redshift parameters"

  parameter {
    name = "require_ssl"
    value = "true"
  }

  parameter {
    name = "enable_user_activity_logging"
    value = "true"
  }

  tags = local.common_tags
}


# ============================================================
# MAIN.TF
# AMAZON REDSHIFT RA3 CLUSTER
# ============================================================

resource "aws_redshift_cluster" "production" {

  # Cluster identification

  cluster_identifier = var.cluster_identifier

  database_name = var.database_name

  master_username = var.master_username

  # AWS manages master password

  manage_master_password = true

  # Compute configuration

  node_type = var.node_type

  number_of_nodes = var.number_of_nodes

  cluster_type = "multi-node"

  # Encryption

  encrypted = true

  kms_key_id = var.kms_key_arn

  # Network security

  publicly_accessible = false

  cluster_subnet_group_name = (
    aws_redshift_subnet_group.redshift_subnet.name
  )

  vpc_security_group_ids = [
    aws_security_group.redshift_sg.id
  ]

  enhanced_vpc_routing = true

  # IAM integration

  iam_roles = [
    aws_iam_role.redshift_role.arn
  ]

  # Backup configuration

  automated_snapshot_retention_period = (
    var.snapshot_retention_days
  )

  manual_snapshot_retention_period = 90

  preferred_maintenance_window = "sun:03:00-sun:04:00"

  # Logging configuration

  logging {

    enable = true

    log_destination_type = "cloudwatch"

    log_exports = [
      "connectionlog",
      "userlog",
      "useractivitylog"
    ]
  }

  # Maintenance

  allow_version_upgrade = true

  maintenance_track_name = "current"

  # Production protection

  deletion_protection = true

  skip_final_snapshot = false

  final_snapshot_identifier = (
    "${var.cluster_identifier}-final-snapshot"
  )

  # Parameter group

  cluster_parameter_group_name = (
    aws_redshift_parameter_group.production.name
  )

  tags = local.common_tags

  depends_on = [
    aws_iam_role_policy_attachment.redshift_s3_attachment
  ]

  lifecycle {
    prevent_destroy = true
  }
}


# ============================================================
# MONITORING.TF
# CLOUDWATCH CPU ALARM
# ============================================================

resource "aws_cloudwatch_metric_alarm" "redshift_cpu" {

  alarm_name = "enterprise-prod-redshift-high-cpu"

  comparison_operator = "GreaterThanThreshold"

  evaluation_periods = 3

  metric_name = "CPUUtilization"

  namespace = "AWS/Redshift"

  period = 300

  statistic = "Average"

  threshold = 80

  alarm_description = "Redshift CPU utilization is above 80%"

  dimensions = {

    ClusterIdentifier = (
      aws_redshift_cluster.production.cluster_identifier
    )
  }

  alarm_actions = (
    var.alarm_sns_topic_arn == null
    ? []
    : [var.alarm_sns_topic_arn]
  )

  tags = local.common_tags
}


# ============================================================
# MONITORING.TF
# CLOUDWATCH STORAGE ALARM
# ============================================================

resource "aws_cloudwatch_metric_alarm" "redshift_storage" {

  alarm_name = "enterprise-prod-redshift-high-storage"

  comparison_operator = "GreaterThanThreshold"

  evaluation_periods = 2

  metric_name = "PercentageDiskSpaceUsed"

  namespace = "AWS/Redshift"

  period = 300

  statistic = "Average"

  threshold = 80

  alarm_description = "Redshift disk usage is above 80%"

  dimensions = {

    ClusterIdentifier = (
      aws_redshift_cluster.production.cluster_identifier
    )
  }

  alarm_actions = (
    var.alarm_sns_topic_arn == null
    ? []
    : [var.alarm_sns_topic_arn]
  )

  tags = local.common_tags
}


# ============================================================
# OUTPUTS.TF
# ============================================================

output "redshift_cluster_identifier" {

  value = aws_redshift_cluster.production.cluster_identifier
}

output "redshift_endpoint" {

  description = "Private Redshift endpoint"

  value = aws_redshift_cluster.production.endpoint
}

output "redshift_database_name" {

  value = aws_redshift_cluster.production.database_name
}

output "redshift_port" {

  value = aws_redshift_cluster.production.port
}

output "redshift_iam_role_arn" {

  value = aws_iam_role.redshift_role.arn
}

output "redshift_security_group_id" {

  value = aws_security_group.redshift_sg.id
}
```

- Formats Terraform configuration.
- Improves readability.
- Standardizes indentation.

## Step 3: Validate Configuration

```bash
terraform validate
```

Purpose:

- Checks Terraform syntax.
- Checks resource references.
- Validates configuration structure.

## Step 4: Review Deployment Plan

```bash
terraform plan -out=redshift.tfplan
```

Purpose:

- Shows resources Terraform intends to create.
- Identifies configuration changes.
- Helps detect unexpected modifications.

Review the plan carefully before deployment.

```bash
terraform apply redshift.tfplan
```

- Creates the Redshift subnet group.
- Creates security groups.
- Creates IAM role and policy.
- Creates the Redshift parameter group.
- Provisions the Redshift cluster.
- Configures CloudWatch alarms.

## Step 6: View Terraform Outputs

```bash
terraform output
```

Purpose:

- Displays Redshift endpoint.
- Displays cluster identifier.
- Displays database name.
- Displays port.
- Displays IAM role ARN.

## Step 7: Check Cluster Status

```bash
aws redshift describe-clusters \
  --cluster-identifier enterprise-prod-redshift \
  --region eu-west-1
```

Check that the cluster status is:

```text
available
```

# 9. Enterprise Security Best Practices

## 9.1 Network Security

- Deploy Redshift in private subnets.
- Disable public accessibility.
- Allow inbound traffic only from approved security groups.
- Avoid unrestricted CIDR rules.
- Restrict outbound access according to enterprise network policy.
- Use VPC endpoints where appropriate.
- Enable enhanced VPC routing.

## 9.2 IAM Security

- Use a dedicated IAM role for Redshift.
- Follow least-privilege access.
- Restrict S3 bucket and prefix permissions.
- Avoid broad managed policies.
- Separate Terraform deployment permissions from Redshift data-access permissions.
- Review IAM policies regularly.

## 9.3 Encryption

- Enable encryption at rest.
- Use customer-managed KMS keys.
- Configure appropriate KMS key policies.
- Enable key rotation where appropriate.
- Restrict access to encryption keys.

## 9.4 Credential Management

- Use Redshift-managed master credentials.
- Store credentials in Secrets Manager.
- Never hardcode database passwords.
- Avoid using the master user for application access.
- Create separate database users and roles for applications.

## 9.5 Backup and Recovery

- Configure automated snapshots.
- Set appropriate snapshot retention.
- Configure cross-Region snapshot copy if required.
- Define RPO and RTO.
- Test snapshot restoration regularly.
- Document disaster recovery procedures.

## 9.6 Monitoring and Auditing

- Enable CloudWatch logging.
- Configure CloudWatch alarms.
- Monitor CPU utilization.
- Monitor disk utilization.
- Monitor database connections.
- Monitor query performance.
- Enable CloudTrail.
- Centralize security and audit logs.

# 11. Important Production Considerations

Before deploying in production, review these points.

1. RA3 node sizing must be based on actual data volume and query workloads.
2. Two RA3 nodes are only an example configuration.
3. Verify the selected node type is available in the target AWS Region.
4. Verify that the subnet group satisfies Availability Zone requirements.
5. Review security-group egress rules.
6. Ensure required S3 and KMS permissions are configured.
7. Validate parameter-group settings against the target engine and provider version.
8. Configure cross-Region snapshot copy if required.
9. Configure remote Terraform state.
10. Enable deletion protection.
11. Keep Terraform state out of source control.
12. Test recovery before production sign-off.

The example Terraform configuration is a starting baseline and requires environment-specific validation before production use.

# Conclusion

This implementation provides a production-oriented foundation for deploying Amazon Redshift RA3 using Terraform.

It covers the core infrastructure components required for a secure enterprise data warehouse:

- Private networking.
- Encryption.
- IAM integration.
- S3 access.
- Automated backups.
- CloudWatch monitoring.
- Database access controls.
- Infrastructure protection.

For enterprise production, the next priorities should be Multi-AZ availability, cross-Region disaster recovery, workload management, query monitoring, centralized auditing, and tested recovery procedures.

**Recommended deployment approach:**

First deploy and validate in a non-production AWS environment. After security review, capacity testing, and recovery validation, promote the approved configuration to production.

``` hcl
resource "aws_redshift_cluster" "production" {

  # Cluster identification

  cluster_identifier = var.cluster_identifier

  database_name   = var.database_name
  master_username = var.master_username

  # AWS manages the master password through Secrets Manager.
  manage_master_password = true

  # Compute configuration

  node_type       = var.node_type
  number_of_nodes = var.number_of_nodes
  cluster_type    = "multi-node"

  # Encryption

  encrypted  = true
  kms_key_id = var.kms_key_arn

  # Network security

  publicly_accessible = false

  cluster_subnet_group_name = (
    aws_redshift_subnet_group.redshift_subnet.name
  )

  vpc_security_group_ids = [
    aws_security_group.redshift_sg.id
  ]

  enhanced_vpc_routing = true

  # IAM integration

  iam_roles = [
    aws_iam_role.redshift_role.arn
  ]

  # Automated backups

  automated_snapshot_retention_period = var.snapshot_retention_days

  manual_snapshot_retention_period = 90

  preferred_maintenance_window = "sun:03:00-sun:04:00"

  # Logging

  logging {
    enable               = true
    log_destination_type = "cloudwatch"

    log_exports = [
      "connectionlog",
      "userlog",
      "useractivitylog"
    ]
  }

  # Cluster maintenance

  allow_version_upgrade = true

  maintenance_track_name = "current"

  # Production protection

  deletion_protection = true

  skip_final_snapshot = false

  final_snapshot_identifier = (
    "${var.cluster_identifier}-final-snapshot"
  )

  # Parameter configuration

  cluster_parameter_group_name = (
    aws_redshift_parameter_group.production.name
  )

  tags = local.common_tags

  depends_on = [
    aws_iam_role_policy_attachment.redshift_s3_attachment
  ]

  lifecycle {
    prevent_destroy = true
  }
}
```
