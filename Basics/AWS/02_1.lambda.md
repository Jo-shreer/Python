# AWS Lambda Configuration Reference

## 1. Function name
Identifies the Lambda function within an AWS account and Region.

```hcl
resource "aws_lambda_function" "orders" {
  function_name = "orders-processor"
}
```

## 2. Description
Explains the purpose of the function.

```hcl
description = "Processes incoming orders"
```

## 3. Runtime
Specifies the language runtime used to execute the function.

```hcl
runtime = "python3.12"
```

## 4. Handler
Specifies the Python file and function Lambda invokes.

```hcl
handler = "app.lambda_handler"
```

```python
# app.py
def lambda_handler(event, context):
    return {"statusCode": 200}
```

## 5. Deployment package
Specifies the ZIP file containing code and dependencies, or a container image.

```hcl
filename         = "function.zip"
source_code_hash = filebase64sha256("function.zip")
```

## 6. Architecture
Selects the CPU architecture used by the function.

```hcl
architectures = ["arm64"]
```

## 7. Execution role
IAM role Lambda assumes to access AWS services.

```hcl
role = aws_iam_role.lambda_role.arn
```

## 8. Memory size
Sets memory allocation and influences available CPU resources.

```hcl
memory_size = 512
```

## 9. Timeout
Sets the maximum time allowed for one invocation.

```hcl
timeout = 30
```

## 10. Ephemeral storage
Sets temporary storage available under `/tmp`, from 512 MB up to 10,240 MB.

```hcl
ephemeral_storage {
  size = 1024
}
```

## 11. Environment variables
Stores application configuration separately from source code.

```hcl
environment {
  variables = {
    SQS_QUEUE_URL = aws_sqs_queue.orders.url
    APP_ENV       = "prod"
  }
}
```

```python
import os

queue_url = os.environ["SQS_QUEUE_URL"]
```

## 12. Reserved concurrency
Reserves concurrency for a function and sets its maximum concurrent executions.

```hcl
reserved_concurrent_executions = 20
```

## 13. Provisioned concurrency
Keeps execution environments initialized to reduce cold-start latency; configure it on a published version or alias.

```hcl
resource "aws_lambda_provisioned_concurrency_config" "orders" {
  function_name                     = aws_lambda_function.orders.function_name
  qualifier                         = aws_lambda_alias.prod.name
  provisioned_concurrent_executions = 5
}
```

## 14. VPC configuration
Connects Lambda to resources in a Virtual Private Cloud.

```hcl
vpc_config {
  subnet_ids         = var.private_subnet_ids
  security_group_ids = [aws_security_group.lambda.id]
}
```

## 15. Subnets
Determine which VPC subnets Lambda uses for network connectivity.

```hcl
subnet_ids = var.private_subnet_ids
```

## 16. Security groups
Control permitted network traffic for Lambda's VPC network interfaces.

```hcl
security_group_ids = [aws_security_group.lambda.id]
```

## 17. File system configuration (EFS)
Mounts a supported shared file system when the function needs shared or persistent file storage.

```hcl
file_system_config {
  arn              = aws_efs_access_point.lambda.arn
  local_mount_path = "/mnt/shared"
}
```

## 18. Dead-letter queue configuration
Routes failed asynchronous invocation events to an SQS queue or SNS topic.

```hcl
dead_letter_config {
  target_arn = aws_sqs_queue.lambda_dlq.arn
}
```

## 19. Asynchronous invocation retry settings
Controls how Lambda retries failed asynchronous invocations.

```hcl
resource "aws_lambda_function_event_invoke_config" "orders" {
  function_name          = aws_lambda_function.orders.function_name
  maximum_retry_attempts = 1
}
```

## 20. Maximum event age
Sets how long an asynchronous event can remain eligible for processing.

```hcl
maximum_event_age_in_seconds = 3600
```

## 21. On-success destination
Routes the record from a successful asynchronous invocation to a configured destination.

```hcl
destination_config {
  on_success {
    destination = aws_sqs_queue.success.arn
  }
}
```

## 22. On-failure destination
Routes records from failed asynchronous invocations to a configured destination for investigation.

```hcl
destination_config {
  on_failure {
    destination = aws_sqs_queue.failures.arn
  }
}
```

## 23. Layers
Packages shared libraries or code that can be reused by multiple functions.

```hcl
layers = [aws_lambda_layer_version.dependencies.arn]
```

## 24. X-Ray tracing
Enables supported AWS X-Ray tracing to help investigate request paths and latency.

```hcl
tracing_config {
  mode = "Active"
}
```

## 25. CloudWatch logging configuration
Controls the destination and permissions for application logs; Lambda commonly sends logs to CloudWatch Logs.

```hcl
resource "aws_iam_role_policy_attachment" "logs" {
  role       = aws_iam_role.lambda_role.name
  policy_arn = "arn:aws:iam::aws:policy/service-role/AWSLambdaBasicExecutionRole"
}
```

## 26. Log format
Chooses text or JSON formatting for supported Lambda application and system logs.

```hcl
logging_config {
  log_format = "JSON"
}
```

## 27. Log level
Controls the severity of logs emitted by supported Lambda logging facilities.

```hcl
logging_config {
  log_level = "INFO"
}
```

## 28. Log retention
Controls how long CloudWatch Logs retains log events.

```hcl
resource "aws_cloudwatch_log_group" "orders" {
  name              = "/aws/lambda/orders-processor"
  retention_in_days = 30
}
```

## 29. KMS encryption key
Allows a customer-managed KMS key to be used for supported Lambda encryption settings.

```hcl
kms_key_arn = aws_kms_key.lambda.arn
```

## 30. Code signing configuration
Can require deployed ZIP packages to be signed by trusted publishers.

```hcl
code_signing_config_arn = aws_lambda_code_signing_config.this.arn
```

## 31. Published versions
Creates an immutable snapshot of the function's code and configuration.

```hcl
publish = true
```

## 32. Aliases
Provides a stable name that points to a published Lambda version.

```hcl
resource "aws_lambda_alias" "prod" {
  name             = "prod"
  function_name    = aws_lambda_function.orders.function_name
  function_version = aws_lambda_function.orders.version
}
```

## 33. Tags
Adds labels for ownership, environment identification, and cost allocation.

```hcl
tags = {
  Environment = "prod"
  Application = "orders"
}
```

## 34. Function URL configuration
Provides an HTTP endpoint directly to Lambda without requiring API Gateway.

```hcl
resource "aws_lambda_function_url" "orders" {
  function_name      = aws_lambda_function.orders.function_name
  authorization_type = "AWS_IAM"
}
```

## 35. Resource-based permissions
Specifies which AWS services or principals can invoke the function.

```hcl
resource "aws_lambda_permission" "allow_s3" {
  statement_id  = "AllowS3Invoke"
  action        = "lambda:InvokeFunction"
  function_name = aws_lambda_function.orders.function_name
  principal     = "s3.amazonaws.com"
  source_arn    = aws_s3_bucket.uploads.arn
}
```

## 36. Runtime management configuration
Controls how Lambda manages runtime updates for supported runtimes.

```hcl
resource "aws_lambda_function" "orders" {
  # Other required arguments omitted
  runtime       = "python3.12"
  handler       = "app.lambda_handler"
  role          = aws_iam_role.lambda_role.arn
  filename      = "function.zip"

  runtime_management_config {
    update_runtime_on = "Auto"
  }
}
```

## 37. SnapStart
Reduces initialization latency for supported runtimes and configurations.

```hcl
snap_start {
  apply_on = "PublishedVersions"
}
```

## 38. Event source mappings
Connects a supported event source, such as SQS, to Lambda.

```hcl
resource "aws_lambda_event_source_mapping" "orders" {
  event_source_arn = aws_sqs_queue.orders.arn
  function_name    = aws_lambda_function.orders.arn
  batch_size       = 10
  enabled          = true
}
```

## 39. Trigger configuration
Defines how a service or event source causes Lambda to run.

```hcl
# Example: an EventBridge rule can invoke Lambda.
resource "aws_cloudwatch_event_rule" "daily" {
  name                = "daily-orders-job"
  schedule_expression = "rate(1 day)"
}
```

## 40. SQS batch size
Sets the maximum number of SQS messages Lambda receives in one batch, subject to service limits.

```hcl
batch_size = 10
```

## 41. SQS maximum batching window
Sets how long Lambda can wait to collect messages before invoking the function with a batch.

```hcl
maximum_batching_window_in_seconds = 5
```

## 42. SQS partial batch response
Allows Lambda to report failed messages individually so successful messages need not be retried with the failed ones.

```hcl
function_response_types = ["ReportBatchItemFailures"]
```

Python handler example:

```python
def lambda_handler(event, context):
    failures = []

    for record in event["Records"]:
        try:
            process_message(record["body"])
        except Exception:
            failures.append({
                "itemIdentifier": record["messageId"]
            })

    return {"batchItemFailures": failures}
```

## 43. SQS event source maximum concurrency
Limits concurrent Lambda invocations for a supported SQS event source mapping.

```hcl
scaling_config {
  maximum_concurrency = 10
}
```

## 44. Event filtering criteria
Filters events so only matching records invoke the function.

```hcl
filter_criteria {
  filter {
    pattern = jsonencode({
      body = {
        event_type = ["ORDER_CREATED"]
      }
    })
  }
}
```

## 45. SQS visibility timeout alignment
Sets how long a received message stays invisible while being processed; AWS recommends at least six times the Lambda timeout, plus the batching window.

```hcl
resource "aws_sqs_queue" "orders" {
  visibility_timeout_seconds = 185
}
```

For example, a 30-second Lambda timeout with a 5-second batching window gives a recommendation of at least 185 seconds.

## 46. SQS redrive policy and DLQ
Defines how many times a message can be received before SQS moves it to a dead-letter queue.

```hcl
redrive_policy = jsonencode({
  deadLetterTargetArn = aws_sqs_queue.orders_dlq.arn
  maxReceiveCount     = 3
})
```

## 47. IAM permissions for event source access
Grants Lambda the permissions required to poll the queue and delete successfully processed messages.

```hcl
statement {
  effect    = "Allow"
  actions   = ["sqs:ReceiveMessage", "sqs:DeleteMessage", "sqs:GetQueueAttributes"]
  resources = [aws_sqs_queue.orders.arn]
}
```

## 50. EventBridge rule or schedule configuration
Defines when a scheduled job runs or which events should trigger Lambda.

```hcl

```

## 51. CloudWatch alarms and monitoring settings
Creates alerts when metrics such as errors or duration exceed defined thresholds.

```hcl
resource "aws_cloudwatch_metric_alarm" "lambda_errors" {
  alarm_name          = "orders-lambda-errors"
  namespace           = "AWS/Lambda"
  metric_name         = "Errors"
  statistic           = "Sum"
  period              = 300
  evaluation_periods  = 1
  threshold           = 1
  comparison_operator = "GreaterThanOrEqualToThreshold"

  dimensions = {
    FunctionName = aws_lambda_function.orders.function_name
  }
}
```

---

## Important production reminders

- Use Terraform to provision infrastructure and manage configuration consistently.
- Never hardcode AWS access keys in Lambda code; use its execution role.
- Keep IAM permissions least-privilege and scoped to the resources the function needs.
- Use environment variables for ordinary configuration and a secrets service for sensitive values.
- Make SQS processing idempotent because messages can be delivered more than once.
- Configure retries, visibility timeout, and DLQs according to the trigger type.
- Test the exact provider version and AWS service limits before applying these examples; some settings belong to separate Terraform resources rather than the Lambda function resource itself.
