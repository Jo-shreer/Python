# Terraform: Connect Private EC2 to Amazon SQS Using Interface VPC Endpoint

## 1. Prerequisites

The following resources should already exist:

- AWS VPC
- Private subnet(s)
- EC2 instance
- EC2 Security Group
- SQS Queue

We will pass their IDs and ARNs as Terraform variables.

## 2. Terraform Configuration

### File: main.tf

```hcl
terraform {
  required_version = ">= 1.5.0"

  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 5.0"
    }
  }
}

provider "aws" {
  region = var.aws_region
}

# --------------------------------
# 1. SQS VPC Endpoint Security Group
# --------------------------------

resource "aws_security_group" "sqs_endpoint" {
  name        = "sqs-interface-endpoint-sg"
  description = "Allow HTTPS from EC2 to SQS endpoint"
  vpc_id      = var.vpc_id

  ingress {
    description     = "Allow HTTPS from EC2"
    from_port       = 443
    to_port         = 443
    protocol        = "tcp"
    security_groups = [var.ec2_security_group_id]
  }

  tags = {
    Name = "sqs-interface-endpoint-sg"
  }
}

# --------------------------------
# 2. Create SQS Interface Endpoint
# --------------------------------

resource "aws_vpc_endpoint" "sqs" {
  vpc_id            = var.vpc_id
  service_name      = "com.amazonaws.${var.aws_region}.sqs"
  vpc_endpoint_type = "Interface"

  subnet_ids = var.private_subnet_ids

  security_group_ids = [
    aws_security_group.sqs_endpoint.id
  ]

  private_dns_enabled = true

  tags = {
    Name        = "sqs-interface-endpoint"
    Environment = "dev"
  }
}

# --------------------------------
# 3. Create IAM Role for EC2
# --------------------------------

resource "aws_iam_role" "ec2_sqs_role" {
  name = "EC2-SQS-Access-Role"

  assume_role_policy = jsonencode({
    Version = "2012-10-17"

    Statement = [
      {
        Effect = "Allow"

        Principal = {
          Service = "ec2.amazonaws.com"
        }

        Action = "sts:AssumeRole"
      }
    ]
  })
}

# --------------------------------
# 4. Create SQS IAM Policy
# --------------------------------

resource "aws_iam_role_policy" "sqs_access" {
  name = "EC2-SQS-Access-Policy"
  role = aws_iam_role.ec2_sqs_role.id

  policy = jsonencode({
    Version = "2012-10-17"

    Statement = [
      {
        Effect = "Allow"

        Action = [
          "sqs:SendMessage",
          "sqs:ReceiveMessage",
          "sqs:DeleteMessage",
          "sqs:GetQueueAttributes",
          "sqs:GetQueueUrl"
        ]

        Resource = var.sqs_queue_arn
      }
    ]
  })
}

# --------------------------------
# 5. Create IAM Instance Profile
# --------------------------------

resource "aws_iam_instance_profile" "ec2_sqs_profile" {
  name = "EC2-SQS-Instance-Profile"

  role = aws_iam_role.ec2_sqs_role.name
}

# --------------------------------
# 6. Outputs
# --------------------------------

output "sqs_endpoint_id" {
  value = aws_vpc_endpoint.sqs.id
}

output "sqs_endpoint_dns" {
  value = aws_vpc_endpoint.sqs.dns_entry
}

output "sqs_endpoint_security_group" {
  value = aws_security_group.sqs_endpoint.id
}

output "iam_instance_profile" {
  value = aws_iam_instance_profile.ec2_sqs_profile.name
}
```

## 3. Define Terraform Variables

### File: variables.tf

```hcl
variable "aws_region" {
  description = "AWS region"
  type        = string
  default     = "eu-west-1"
}

variable "vpc_id" {
  description = "Existing VPC ID"
  type        = string
}

variable "private_subnet_ids" {
  description = "Private subnet IDs for endpoint"
  type        = list(string)
}

variable "ec2_security_group_id" {
  description = "Existing EC2 security group ID"
  type        = string
}

variable "sqs_queue_arn" {
  description = "Existing SQS queue ARN"
  type        = string
}
```

## 4. Provide Variable Values

### File: terraform.tfvars

```hcl
aws_region = "eu-west-1"

vpc_id = "vpc-0123456789"

private_subnet_ids = [
  "subnet-0123456789",
  "subnet-9876543210"
]

ec2_security_group_id = "sg-0123456789"

sqs_queue_arn = "arn:aws:sqs:eu-west-1:123456789012:my-queue"
```

Replace the example IDs and ARN with your actual AWS resource values.

## 5. Attach IAM Instance Profile to EC2

The above Terraform creates the IAM role and instance profile.

If your EC2 instance is already managed by Terraform through an `aws_instance` resource, add the following argument to that existing resource:

```hcl
iam_instance_profile = aws_iam_instance_profile.ec2_sqs_profile.name
```

Do not create a second EC2 instance just to attach the role.

If EC2 is not managed by Terraform, attach the created instance profile to the existing instance through:

EC2 → Instances → Select instance → Actions → Security → Modify IAM role.

## 6. EC2 Security Group Configuration

We are reusing the existing EC2 Security Group.

Its outbound rules must allow:

| Setting | Value |
|---|---|
| Protocol | TCP |
| Port | 443 |
| Destination | SQS Endpoint Security Group |

If the existing EC2 Security Group already allows all outbound traffic, no additional rule is needed.

If outbound traffic is restricted, add a Terraform egress rule:

```hcl
resource "aws_vpc_security_group_egress_rule" "ec2_to_sqs" {
  security_group_id = var.ec2_security_group_id

  referenced_security_group_id = aws_security_group.sqs_endpoint.id

  ip_protocol = "tcp"
  from_port   = 443
  to_port     = 443
}
```

Only add this if an equivalent outbound rule does not already exist.

The endpoint Security Group's inbound TCP 443 rule is already configured in `main.tf`.

## 7. Execute Terraform Commands

Run the following commands in order:

### Initialise Terraform

```bash
terraform init
```

### Validate Configuration

```bash
terraform validate
```

### Format Configuration

```bash
terraform fmt
```

### Review Execution Plan

```bash
terraform plan
```

### Apply Configuration

```bash
terraform apply
```

Type `yes` when prompted.

Terraform will create:

1. SQS Interface VPC Endpoint.
2. Endpoint Security Group.
3. IAM Role for EC2.
4. IAM permissions policy for SQS.
5. IAM Instance Profile.

## 8. Verify Connectivity

Connect to the EC2 instance.

### Check DNS

```bash
nslookup sqs.eu-west-1.amazonaws.com
```

Expected: Private IP addresses belonging to the SQS VPC Endpoint.

### Check HTTPS

```bash
curl -I https://sqs.eu-west-1.amazonaws.com
```

An HTTP response confirms that an HTTPS response was received, but does not independently prove IAM authorization.

### Test SQS Access

```bash
aws sqs get-queue-url \
  --queue-name my-queue \
  --region eu-west-1
```

### Send a Message

```bash
aws sqs send-message \
  --queue-url YOUR_QUEUE_URL \
  --message-body "Hello from private EC2" \
  --region eu-west-1
```

### Receive a Message

```bash
aws sqs receive-message \
  --queue-url YOUR_QUEUE_URL \
  --region eu-west-1
```

If successful, your private EC2 instance is communicating with SQS through the Interface VPC Endpoint.

## 9. Terraform for Other AWS Services

The same Terraform approach can be reused for other AWS services that support Interface VPC Endpoints.

Only the following typically need to change:

**Service name:**

```hcl
service_name = "com.amazonaws.${var.aws_region}.sns"
```

For SNS, for example.

**IAM permissions:**

Replace the SQS permissions with the appropriate service-specific IAM permissions.

**Endpoint security group:**

Reuse the same endpoint Security Group if the required access pattern is identical.

Examples:

| AWS Service | Endpoint Service |
|---|---|
| SQS | sqs |
| SNS | sns |
| Secrets Manager | secretsmanager |
| Systems Manager | ssm |
| CloudWatch Logs | logs |
| KMS | kms |
| ECR API | ecr.api |

Note: S3 and DynamoDB commonly use Gateway VPC Endpoints, so their Terraform configurations differ.

## 10. AWS Cost Considerations

Interface VPC Endpoint charges include:

1. **Hourly endpoint charges:** Charged per endpoint per Availability Zone.
2. **Data processing charges:** Charged based on GB processed through the endpoint.
3. **SQS charges:** Separate request-based charges for sending, receiving and deleting messages.

Additional charges may apply for KMS and CloudWatch usage.

For example, if you deploy the endpoint into two Availability Zones, you pay two endpoint-AZ hourly charges.

The endpoint continues to incur hourly charges until it is deleted.

Pricing references:

- https://aws.amazon.com/privatelink/pricing/
- https://aws.amazon.com/sqs/pricing/
- https://calculator.aws/

## 11. Final Architecture

EC2 Instance (Private Subnet)
        |
        |
EC2 Security Group
        |
        | HTTPS / TCP 443
        |
SQS Interface VPC Endpoint
        |
        | Endpoint Security Group
        |
AWS PrivateLink
        |
        |
Amazon SQS

IAM Role attached to EC2 provides authorization to access the SQS queue.

**Important prerequisites:**

- VPC DNS support and DNS hostnames must be enabled for Private DNS.
- The EC2 Security Group must permit outbound TCP 443.
- The endpoint Security Group must permit inbound TCP 443 from EC2.
- The EC2 IAM role must have the required SQS permissions.
- The SQS queue and endpoint must be in the intended AWS region.
- If the SQS queue uses a customer-managed KMS key, additional KMS permissions may be required.

**Conclusion:**

Terraform automates the creation of the SQS Interface VPC Endpoint, Security Group, IAM Role, IAM Policy and Instance Profile, enabling private EC2 workloads to communicate with Amazon SQS without requiring NAT Gateway or internet connectivity for this connection.
