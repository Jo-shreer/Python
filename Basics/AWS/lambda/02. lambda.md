# AWS Lambda Configuration — Grouped by Owner

## 1. Lambda Function Owner

These settings belong to the Lambda function itself.

### 1.1 Function name
Identifies the function in your AWS account and Region.

```hcl
function_name = "orders-processor"
```

### 1.2 Description
Describes the function's purpose.

```hcl
description = "Processes incoming orders"
```

### 1.3 Runtime
Specifies the language runtime.

```hcl
runtime = "python3.12"
```

### 1.4 Handler
Specifies the Python file and entry-point function.

```hcl
handler = "app.lambda_handler"
```

```python
def lambda_handler(event, context):
    return {"statusCode": 200}
```

### 1.5 Deployment package
Specifies the ZIP package containing code and dependencies, or a container image.

```hcl
filename         = "function.zip"
source_code_hash = filebase64sha256("function.zip")
```

### 1.6 Architecture
Selects the CPU architecture.

```hcl
architectures = ["arm64"]
```

### 1.7 Memory
Sets memory allocation and influences available CPU resources.

```hcl
memory_size = 512
```

### 1.8 Timeout
Sets the maximum duration of an invocation.

```hcl
timeout = 30
```

### 1.9 Ephemeral storage
Sets temporary disk space available under `/tmp`.

```hcl
ephemeral_storage {
  size = 1024
}
```

### 1.10 Environment variables
Stores application configuration separately from code.

```hcl
environment {
  variables = {
    SQS_QUEUE_URL = aws_sqs_queue.orders.url
    APP_ENV       = "prod"
  }
}
```

```python
import os

queue_url = os.environ["SQS_QUEUE_URL"]
```

### 1.11 Reserved concurrency
Reserves capacity for the function and caps its maximum concurrent executions.

```hcl
reserved_concurrent_executions = 20
```

### 1.12 Layers
Shares dependencies or code across functions.

```hcl
layers = [aws_lambda_layer_version.dependencies.arn]
```

### 1.13 VPC configuration
Connects the function to private or other resources in a VPC.

```hcl
vpc_config {
  subnet_ids         = var.private_subnet_ids
  security_group_ids = [aws_security_group.lambda.id]
}
```

### 1.14 Subnets
Selects the VPC subnets used by Lambda's network interfaces.

```hcl
subnet_ids = var.private_subnet_ids
```

### 1.15 Security groups
Controls network traffic for Lambda's VPC network interfaces.

```hcl
security_group_ids = [aws_security_group.lambda.id]
```

### 1.16 EFS file system
Mounts shared persistent storage when the function requires it.

```hcl
file_system_config {
  arn              = aws_efs_access_point.lambda.arn
  local_mount_path = "/mnt/shared"
}
```

### 1.17 X-Ray tracing
Enables supported request tracing.

```hcl
tracing_config {
  mode = "Active"
}
```

### 1.18 Runtime management
Controls Lambda-managed runtime updates.

```hcl
runtime_management_config {
  update_runtime_on = "Auto"
}
```

### 1.19 SnapStart
Reduces initialization latency for supported runtimes and configurations.

```hcl
snap_start {
  apply_on = "PublishedVersions"
}
```

### 1.20 Tags
Labels the function for environment, ownership, and cost allocation.

```hcl
tags = {
  Environment = "prod"
  Application = "orders"
}
```

## 2. IAM and Security Owner

These settings control what the function can access and who can invoke it.

### 2.1 Execution role
Specifies the IAM role Lambda assumes when executing code.

```hcl
role = aws_iam_role.lambda_role.arn
```

### 2.2 Trust policy
Allows the Lambda service to assume the execution role.

```hcl
assume_role_policy = jsonencode({
  Version = "2012-10-17"
  Statement = [{
    Effect    = "Allow"
    Principal = { Service = "lambda.amazonaws.com" }
    Action    = "sts:AssumeRole"
  }]
})
```

### 2.3 Permissions policy
Grants the function specific AWS actions on specified resources.

```hcl
statement {
  effect    = "Allow"
  actions   = ["sqs:SendMessage"]
  resources = [aws_sqs_queue.orders.arn]
}
```

### 2.4 Resource-based invocation permission
Allows a service or principal, such as S3, to invoke Lambda.

```hcl
resource "aws_lambda_permission" "allow_s3" {
  statement_id  = "AllowS3Invoke"
  action        = "lambda:InvokeFunction"
  function_name = aws_lambda_function.orders.function_name
  principal     = "s3.amazonaws.com"
  source_arn    = aws_s3_bucket.uploads.arn
}
```

### 2.5 KMS key
Configures a customer-managed KMS key for supported Lambda encryption settings.

```hcl
kms_key_arn = aws_kms_key.lambda.arn
```

### 2.6 Code signing
Requires supported ZIP deployment packages to meet configured signing requirements.

```hcl
code_signing_config_arn = aws_lambda_code_signing_config.this.arn
```

### 2.7 Secrets
Stores sensitive values, such as database passwords, in a dedicated secrets service rather than ordinary configuration.

```python
import boto3

secrets = boto3.client("secretsmanager")
result = secrets.get_secret_value(SecretId="prod/database")
```

The execution role needs permission to retrieve the secret.

## 3. SQS Queue Owner

These settings belong to the SQS queue, not the Lambda function.

### 3.1 Queue type
Selects Standard or FIFO delivery behavior.

```hcl
resource "aws_sqs_queue" "orders" {
  name = "orders-queue"
}
```

For FIFO, the queue name must end in `.fifo`.

### 3.2 Message retention
Sets how long messages remain in the queue.

```hcl
message_retention_seconds = 345600
```

### 3.3 Visibility timeout
Sets how long a received message remains hidden while being processed.

```hcl
visibility_timeout_seconds = 185
```

For an SQS-triggered Lambda, AWS recommends a visibility timeout of at least six times the function timeout, plus the batching window.

### 3.4 Delay seconds
Delays the initial availability of new messages.

```hcl
delay_seconds = 0
```

### 3.5 Maximum message size
Sets the maximum accepted message size.

```hcl
max_message_size = 262144
```

### 3.6 Long polling
Sets how long a queue receive request waits for messages.

```hcl
receive_wait_time_seconds = 20
```

### 3.7 Queue encryption
Enables supported server-side encryption for messages.

```hcl
sqs_managed_sse_enabled = true
```

### 3.8 Redrive policy and DLQ
Moves messages to a dead-letter queue after the configured number of receives.

```hcl
redrive_policy = jsonencode({
  deadLetterTargetArn = aws_sqs_queue.orders_dlq.arn
  maxReceiveCount     = 3
})
```

### 3.9 FIFO message group ID
Groups FIFO messages to preserve ordering within each group.

```python
sqs.send_message(
    QueueUrl=queue_url,
    MessageBody="Process order",
    MessageGroupId="customer-42"
)
```

### 3.10 FIFO deduplication ID
Identifies duplicate sends within the FIFO deduplication interval when explicit deduplication IDs are used.

```python
sqs.send_message(
    QueueUrl=queue_url,
    MessageBody="Process order",
    MessageGroupId="customer-42",
    MessageDeduplicationId="order-123"
)
```

FIFO deduplication does not replace application-level idempotency.

## 4. Lambda Event Source Mapping Owner

This configuration connects an event source, such as SQS, to Lambda.

### 4.1 Event source mapping
Connects the SQS queue to the Lambda function.

```hcl
resource "aws_lambda_event_source_mapping" "orders" {
  event_source_arn = aws_sqs_queue.orders.arn
  function_name    = aws_lambda_function.orders.arn
  enabled          = true
}
```

### 4.2 Batch size
Sets the maximum number of messages delivered per invocation, subject to service limits.

```hcl
batch_size = 10
```

### 4.3 Maximum batching window
Sets how long Lambda can wait to collect messages before invoking the function.

```hcl
maximum_batching_window_in_seconds = 5
```

### 4.4 Partial batch response
Allows the handler to report individual failed records.

```hcl
function_response_types = ["ReportBatchItemFailures"]
```

```python
def lambda_handler(event, context):
    failures = []

    for record in event["Records"]:
        try:
            process_message(record["body"])
        except Exception:
            failures.append({
                "itemIdentifier": record["messageId"]
            })

    return {"batchItemFailures": failures}
```

### 4.5 Maximum event source concurrency
Limits concurrent Lambda invocations for a supported SQS mapping.

```hcl
scaling_config {
  maximum_concurrency = 10
}
```

### 4.6 Event filtering
Filters events so only matching records are passed to the function.

```hcl
filter_criteria {
  filter {
    pattern = jsonencode({
      body = {
        event_type = ["ORDER_CREATED"]
      }
    })
  }
}
```

### 4.7 Event source IAM permissions
The Lambda execution role needs permission to poll the queue and delete successfully processed messages.

```hcl
actions = [
  "sqs:ReceiveMessage",
  "sqs:DeleteMessage",
  "sqs:GetQueueAttributes"
]
```

### 4.8 Maximum concurrency versus reserved concurrency
Event source maximum concurrency limits processing through a supported mapping; reserved concurrency applies to the function overall and can also cap its total concurrency.

## 5. Asynchronous Invocation Owner

These settings apply to Lambda's asynchronous invocation mechanism, not to SQS event source mapping retries.

### 5.1 Retry attempts
Sets how many additional attempts Lambda makes after an asynchronous function error.

```hcl
maximum_retry_attempts = 1
```

### 5.2 Maximum event age
Sets how long an asynchronous event remains eligible for processing.

```hcl
maximum_event_age_in_seconds = 3600
```

### 5.3 On-success destination
Routes records from successful asynchronous invocations to a destination.

```hcl
destination_config {
  on_success {
    destination = aws_sqs_queue.success.arn
  }
}
```

### 5.4 On-failure destination
Routes records from failed asynchronous invocations to a destination.

```hcl
destination_config {
  on_failure {
    destination = aws_sqs_queue.failures.arn
  }
}
```

### 5.5 Lambda asynchronous DLQ
Sends failed asynchronous events to an SQS queue or SNS topic using the function's dead-letter configuration.

```hcl
dead_letter_config {
  target_arn = aws_sqs_queue.lambda_dlq.arn
}
```

## 6. Logging and Monitoring Owner

### 6.1 CloudWatch Logs permissions
Allows Lambda to create log streams and write logs.

```hcl
policy_arn = "arn:aws:iam::aws:policy/service-role/AWSLambdaBasicExecutionRole"
```

### 6.2 Log group and retention
Creates a log group and defines how long logs are retained.

```hcl
resource "aws_cloudwatch_log_group" "orders" {
  name              = "/aws/lambda/orders-processor"
  retention_in_days = 30
}
```

### 6.3 Log format
Configures supported Lambda logs as JSON or text.

```hcl
logging_config {
  log_format = "JSON"
}
```

### 6.4 Log level
Controls the minimum severity of supported Lambda application logs.

```hcl
logging_config {
  log_level = "INFO"
}
```

### 6.5 CloudWatch alarms
Alerts when monitored metrics cross a threshold.

```hcl
resource "aws_cloudwatch_metric_alarm" "lambda_errors" {
  alarm_name          = "orders-lambda-errors"
  namespace           = "AWS/Lambda"
  metric_name         = "Errors"
  statistic           = "Sum"
  period              = 300
  evaluation_periods  = 1
  threshold           = 1
  comparison_operator = "GreaterThanOrEqualToThreshold"

  dimensions = {
    FunctionName = aws_lambda_function.orders.function_name
  }
}
```

## 7. Release and Endpoint Owner

### 7.1 Published versions
Creates an immutable snapshot of function code and configuration.

```hcl
publish = true
```

### 7.2 Aliases
Provides a stable name that points to a published version.

```hcl
resource "aws_lambda_alias" "prod" {
  name             = "prod"
  function_name    = aws_lambda_function.orders.function_name
  function_version = aws_lambda_function.orders.version
}
```

### 7.3 Provisioned concurrency
Keeps execution environments initialized to reduce cold-start latency.

```hcl
resource "aws_lambda_provisioned_concurrency_config" "orders" {
  function_name                     = aws_lambda_function.orders.function_name
  qualifier                         = aws_lambda_alias.prod.name
  provisioned_concurrent_executions = 5
}
```

### 7.4 Function URL
Creates a direct HTTP endpoint for Lambda.

```hcl
resource "aws_lambda_function_url" "orders" {
  function_name      = aws_lambda_function.orders.function_name
  authorization_type = "AWS_IAM"
}
```

### 7.5 API Gateway integration
Connects an API route to Lambda for HTTP request handling.

```hcl
resource "aws_apigatewayv2_integration" "orders" {
  api_id                 = aws_apigatewayv2_api.api.id
  integration_type       = "AWS_PROXY"
  integration_uri        = aws_lambda_function.orders.invoke_arn
  payload_format_version = "2.0"
}
```

### 7.6 EventBridge schedule
Defines when a scheduled job should run.

```hcl
resource "aws_cloudwatch_event_rule" "daily" {
  name                = "daily-report"
  schedule_expression = "cron(0 2 * * ? *)"
}
```

### 7.7 S3 trigger
Configures S3 to notify Lambda when a selected bucket event occurs; the Lambda resource policy must also allow S3 invocation.

```hcl
resource "aws_s3_bucket_notification" "uploads" {
  bucket = aws_s3_bucket.uploads.id

  lambda_function {
    lambda_function_arn = aws_lambda_function.orders.arn
    events              = ["s3:ObjectCreated:*"]
  }

  depends_on = [aws_lambda_permission.allow_s3]
}
```

## 8. Application-Level Reliability Owner

These are application design responsibilities, not single Lambda configuration switches.

### 8.1 Idempotency
Prevents duplicate messages from repeating the same business operation.

```python
table.put_item(
    Item={"order_id": order_id, "status": "COMPLETED"},
    ConditionExpression="attribute_not_exists(order_id)"
)
```

### 8.2 Error handling
Catches failures and reports them appropriately so the trigger can apply its retry behavior.

```python
try:
    process_order(order)
except TemporaryError:
    raise
```

### 8.3 Input validation
Validates event data before processing.

```python
order_id = event.get("order_id")
if not order_id:
    raise ValueError("order_id is required")
```

### 8.4 Downstream protection
Uses suitable concurrency limits, connection management, and retry/backoff strategies to protect databases and other services.

```python
# Example: reuse clients outside the handler.
import boto3

sqs = boto3.client("sqs")
```

## Important reminders

- Terraform should manage infrastructure and repeatable configuration.
- The execution role controls what Lambda can access; resource-based permissions control who can invoke it.
- SQS queue settings and Lambda event source mapping settings are different owners.
- SQS redrive settings control SQS message retries; asynchronous invocation settings control Lambda's asynchronous event retries.
- A queue URL is ordinary configuration; don't store AWS access keys in environment variables.
- Use idempotency to make repeated processing safe.
- Validate examples against your AWS provider version and actual service limits before deploying.
