# PART 1 – INTRODUCTION TO AWS API GATEWAY

## 1. What is Amazon API Gateway?

Amazon API Gateway is a fully managed AWS service used to create, publish, secure, monitor, maintain and manage APIs.

It provides a central entry point between API consumers and backend services.

A client does not need to know where the backend service is hosted. It communicates with API Gateway using HTTPS.

API Gateway handles:
- Incoming HTTP requests.
- Authentication and authorization.
- Request validation.
- Request and response transformation.
- Backend integrations.
- Throttling and rate limiting.
- API keys and usage plans.
- Caching.
- CORS.
- Monitoring and logging.
- API versioning through stages and deployments.
- Custom domain names.
- Private API access.
- Error handling.

### Real-world example

Imagine an e-commerce application.

The frontend needs to:
1. Retrieve products.
2. Create orders.
3. Update customer details.
4. Cancel orders.
5. Retrieve order history.

Instead of allowing the frontend to directly communicate with databases and internal services, API Gateway provides controlled endpoints.

Example:

GET /products
GET /products/101
POST /orders
GET /orders/501
PUT /customers/101
DELETE /orders/501

API Gateway receives the request and routes it to the correct backend.

## 3. Types of Amazon API Gateway

AWS offers three main API Gateway API types.

### A. REST API – API Gateway V1

REST API provides advanced API management capabilities.

Features:
- API keys.
- Usage plans.
- Request validation.
- Response mapping.
- API caching.
- Private APIs.
- Resource policies.
- Lambda authorizers.
- Cognito authorizers.
- AWS service integrations.
- Advanced API management.

Use REST API when you need advanced API management features.

### B. HTTP API – API Gateway V2

HTTP API provides a simpler API implementation.

Features:
- Lower-cost request processing in many use cases.
- Lambda integrations.
- HTTP integrations.
- JWT authorizers.
- CORS configuration.
- Automatic deployments.
- Custom domain support.

Use HTTP API when you need straightforward API routing and do not require REST API-specific capabilities.

### C. WebSocket API

WebSocket API supports persistent, bidirectional communication.

Examples:
- Chat applications.
- Real-time notifications.
- Live dashboards.
- Multiplayer games.
- Collaborative applications.

### REST API vs HTTP API vs WebSocket

| Feature | REST API | HTTP API | WebSocket |
|---|---|---|---|
| Protocol | HTTP/HTTPS | HTTP/HTTPS | WebSocket |
| API type | REST | HTTP | Event-based |
| API keys and usage plans | Yes | No equivalent usage-plan feature | No equivalent REST usage plan |
| Caching | Yes | No equivalent built-in cache | No |
| Request validation | Yes | More limited | Different model |
| Lambda integration | Yes | Yes | Yes |
| JWT authorization | Cognito or Lambda authorizer | Native JWT or Lambda authorizer | Different authorization model |
| Private REST endpoint | Yes | No equivalent | No equivalent |
| Best for | Advanced REST APIs | Simple APIs | Real-time communication |

# PART 2 – REST API FUNDAMENTALS

## 4. Important REST API terminology

### REST API

The main API container.

Example:
users-rest-api

### Resource

A resource represents a URL path.

Example:
- /users
- /products
- /orders
- /customers

### Nested resource

A resource under another resource.

Example:

/users/{userId}
/users/{userId}/orders
/orders/{orderId}/items

### Method

A method defines the HTTP operation.

Examples:
GET, POST, PUT, PATCH, DELETE.

### Method Request

Defines what the API accepts from the client.

Examples:
- Headers.
- Path parameters.
- Query parameters.
- Request body.
- Authorization configuration.

### Integration Request

Defines how API Gateway sends a request to the backend.

Examples:
- Lambda invocation.
- HTTP backend request.
- DynamoDB operation.

### Integration Response

Defines how a backend response is processed for non-proxy integrations.

### Method Response

Defines the response contract exposed to the client.

### Deployment

A snapshot of API configuration.

### Stage

A named environment pointing to an API deployment.

Examples:
- dev
- test
- staging
- prod

### Authorizer

A mechanism to authenticate and authorize API consumers.

### Usage Plan

Controls consumer request-rate targets and quotas.

## 5. HTTP methods in detail

### GET

Used to retrieve information.

Example:

GET /users/101

Response:

{
  "id": 101,
  "name": "John",
  "email": "john@example.com"
}

### POST

Used to create a new resource or perform an operation.

Example:

POST /users

Request:

{
  "name": "John",
  "email": "john@example.com"
}

Response:

{
  "id": 101,
  "message": "User created"
}

### PUT

Used to replace an existing resource.

Example:

PUT /users/101

Request:

{
  "name": "John Smith",
  "email": "johnsmith@example.com"
}

### PATCH

Used to partially update a resource.

Example:

PATCH /users/101

Request:

{
  "name": "John Updated"
}

### DELETE

Used to delete a resource.

Example:

DELETE /users/101

### OPTIONS

Used to discover supported methods and handle browser CORS preflight requests.

### HEAD

Similar to GET, but returns headers without a response body.

### ANY

An API Gateway catch-all method that can accept different HTTP methods on a resource. It is useful with proxy resources.

HEADER:

AUTHORIZER:

# PART 4 – REQUEST VALIDATION AND MODELS

## 10. What is request validation?

Request validation checks incoming requests before forwarding them to the backend.

Benefits:
- Rejects invalid requests early.
- Reduces unnecessary Lambda invocations.
- Enforces API contracts.
- Reduces backend processing.
- Improves API consistency.

### Request validator types

1. Validate body only.
2. Validate parameters only.
3. Validate body and parameters.

Terraform:

```hcl
resource "aws_api_gateway_request_validator" "validator" {
  name = "users-request-validator"

  rest_api_id = aws_api_gateway_rest_api.api.id

  validate_request_body = true

  validate_request_parameters = true
}
```

### Request model

A request model describes the expected JSON structure.

Example:

```json
{
  "$schema": "http://json-schema.org/draft-04/schema#",
  "title": "CreateUserRequest",
  "type": "object",
  "required": [
    "name",
    "email"
  ],
  "properties": {
    "name": {
      "type": "string",
      "minLength": 2,
      "maxLength": 100
    },
    "email": {
      "type": "string"
    },
    "age": {
      "type": "integer",
      "minimum": 18
    }
  },
  "additionalProperties": false
}
```

Terraform:

```hcl
resource "aws_api_gateway_model" "user_model" {
  rest_api_id = aws_api_gateway_rest_api.api.id

  name = "CreateUserRequest"

  content_type = "application/json"

  schema = jsonencode({
    "$schema" = "http://json-schema.org/draft-04/schema#"

    title = "CreateUserRequest"

    type = "object"

    required = ["name", "email"]

    properties = {
      name = {
        type      = "string"
        minLength = 2
      }

      email = {
        type = "string"
      }

      age = {
        type    = "integer"
        minimum = 18
      }
    }
  })
}
```

Associate the model with the POST method:

```hcl
request_models = {
  "application/json" = aws_api_gateway_model.user_model.name
}

request_validator_id = aws_api_gateway_request_validator.validator.id
```

# PART 5 – INTEGRATION TYPES AND PARAMETERS

## 11. Integration types

The integration connects API Gateway to the backend.

### AWS

Non-proxy AWS service integration.

Example:
API Gateway directly calls DynamoDB.

API Gateway can transform requests and responses.

### AWS_PROXY

Lambda proxy integration.

API Gateway forwards the request context and payload to Lambda.

Lambda returns the response.

### HTTP

Non-proxy HTTP backend integration.

Useful when custom mapping is needed.

### HTTP_PROXY

Proxy integration with an HTTP backend.

API Gateway forwards the request and backend response with less transformation.

### MOCK

No real backend is called.

Useful for:
- Mock APIs.
- Testing.
- Static responses.
- CORS preflight responses.

## 12. Integration parameters

Terraform resource:

aws_api_gateway_integration

| Parameter | Purpose |
|---|---|
| rest_api_id | API identifier |
| resource_id | Resource identifier |
| http_method | API method |
| type | Integration type |
| integration_http_method | Backend HTTP method |
| uri | Backend integration URI |
| credentials | IAM role ARN |
| connection_type | INTERNET or VPC_LINK |
| connection_id | VPC Link identifier |
| request_parameters | Parameter mapping |
| request_templates | VTL request mapping |
| passthrough_behavior | Unmatched content type behavior |
| timeout_milliseconds | Integration timeout |
| cache_key_parameters | Cache key parameters |
| cache_namespace | Cache namespace |
| content_handling | Binary/text conversion |
| tls_config | Backend TLS configuration |

### integration_http_method

For Lambda proxy integration, this must be POST even if the client calls GET.

Example:

```hcl
http_method = "GET"

integration_http_method = "POST"

type = "AWS_PROXY"
```

### uri

Lambda integration URI example:

```hcl
uri = aws_lambda_function.users.invoke_arn
```

For a Lambda integration, the provider accepts the Lambda invocation URI in the expected form.

### credentials

Specifies an IAM role used by API Gateway to invoke an AWS service.

Not always required for Lambda if you use a Lambda resource-based permission.

### connection_type

INTERNET:
Backend is accessed through the internet-facing integration path.

VPC_LINK:
Backend is accessed through a configured VPC Link.

### connection_id

The VPC Link ID when using VPC_LINK.

### request_templates

Used for mapping request payloads with Velocity Template Language (VTL).

Example:

```vtl
{
  "operation": "GetItem",
  "key": {
    "id": {
      "S": "$input.params('userId')"
    }
  }
}
```

### passthrough_behavior

Common values:

WHEN_NO_MATCH

WHEN_NO_TEMPLATES

NEVER

Controls what happens when the request Content-Type does not match an available mapping template.

### timeout_milliseconds

Controls the integration timeout.

The default is generally 29 seconds for REST APIs, with quota-dependent possibilities for higher values in supported configurations.

### cache_key_parameters

Defines which request parameters identify a cached response.

Example:

```hcl
cache_key_parameters = [
  "method.request.querystring.category"
]
```

### content_handling

Common values:

CONVERT_TO_BINARY

CONVERT_TO_TEXT

### tls_config

Used to configure supported backend TLS settings.

# PART 6 – LAMBDA PROXY AND NON-PROXY INTEGRATION

## 13. Lambda proxy integration

Request:

GET /users/101

API Gateway sends request information to Lambda.

Example Lambda event:

```json
{
  "resource": "/users/{userId}",
  "path": "/users/101",
  "httpMethod": "GET",
  "headers": {
    "Accept": "application/json"
  },
  "pathParameters": {
    "userId": "101"
  },
  "queryStringParameters": null,
  "body": null,
  "isBase64Encoded": false
}
```

Example Lambda response:

```json
{
  "statusCode": 200,
  "headers": {
    "Content-Type": "application/json"
  },
  "body": "{\"id\":101,\"name\":\"John\"}",
  "isBase64Encoded": false
}
```

Important:

- statusCode must be a valid response status.
- body should be a string for the standard Lambda proxy response.
- headers should be correctly formatted.
- isBase64Encoded indicates binary response encoding.

### Lambda proxy advantages

- Less mapping configuration.
- Simple backend development.
- Flexible request handling.
- Lambda controls response status and headers.
- Easier integration maintenance.

### Lambda proxy disadvantages

- Lambda must handle request validation and application errors.
- Backend response must follow the expected format.
- Less opportunity for API Gateway response transformation.

## 14. Non-proxy integration

In non-proxy integration, API Gateway controls more of the request and response transformation.

Request:

Client sends JSON.

API Gateway mapping template transforms JSON.

Backend receives a different payload.

Backend returns data.

API Gateway maps the response.

Client receives the final HTTP response.

Use non-proxy integration when:
- Direct AWS service integration is required.
- Backend request formats differ from client request formats.
- Custom request and response transformation is needed.

# PART 7 – AUTHENTICATION AND AUTHORIZATION

## 15. Authorization types

### NONE

No authorization.

Suitable for intentionally public APIs.

### AWS_IAM

Uses AWS Signature Version 4.

Suitable for:
- Internal AWS workloads.
- IAM-authenticated clients.
- AWS service-to-service communication.

### CUSTOM

Uses a Lambda authorizer.

The Lambda authorizer evaluates the request and returns an IAM policy.

### COGNITO_USER_POOLS

Uses Amazon Cognito user pools.

Suitable for user authentication in applications.

## 16. Lambda authorizers

Two major types:

TOKEN authorizer:

Receives an authorization token.

REQUEST authorizer:

Receives supported request information, such as headers, query strings and path parameters.

Important parameters:

- name
- rest_api_id
- authorizer_uri
- authorizer_credentials
- identity_source
- type
- authorizer_result_ttl_in_seconds
- provider_arns
- identity_validation_expression

### Authorizer caching

Example:

```hcl
authorizer_result_ttl_in_seconds = 300
```

This configures a five-minute authorizer result cache.

Caching can reduce Lambda authorizer invocations.

Be careful: identity sources and authorization decisions must be designed so that cached decisions cannot accidentally be reused for another identity.

## 17. API keys

API keys identify API consumers.

Client request:

```http
GET /users
X-API-Key: YOUR_API_KEY
```

Terraform resources:

- aws_api_gateway_api_key
- aws_api_gateway_usage_plan
- aws_api_gateway_usage_plan_key

Example:

```hcl
resource "aws_api_gateway_api_key" "customer" {
  name    = "customer-api-key"
  enabled = true
}

resource "aws_api_gateway_usage_plan" "customer" {
  name = "customer-usage-plan"

  api_stages {
    api_id = aws_api_gateway_rest_api.api.id

    stage = aws_api_gateway_stage.prod.stage_name
  }

  throttle_settings {
    rate_limit  = 100
    burst_limit = 200
  }

  quota_settings {
    limit  = 10000
    period = "DAY"
  }
}

resource "aws_api_gateway_usage_plan_key" "customer" {
  key_id        = aws_api_gateway_api_key.customer.id

  key_type      = "API_KEY"

  usage_plan_id = aws_api_gateway_usage_plan.customer.id
}
```

Important:

- API keys are not user authentication.
- Usage-plan quotas are best-effort.
- Do not use them as a hard billing or security boundary.
- Protect API keys as secrets.

# PART 8 – STAGES AND DEPLOYMENTS

## 18. API deployment

A deployment creates a snapshot of the API configuration.

Without deployment, configuration changes will not become available through the stage.

Terraform resource:

aws_api_gateway_deployment

Important arguments:

- rest_api_id
- description
- triggers
- variables

Example:

```hcl
resource "aws_api_gateway_deployment" "api" {
  rest_api_id = aws_api_gateway_rest_api.api.id

  triggers = {
    redeployment = sha1(jsonencode([
      aws_api_gateway_resource.users.id,
      aws_api_gateway_method.get_users.id,
      aws_api_gateway_integration.get_users.id
    ]))
  }

  lifecycle {
    create_before_destroy = true
  }

  depends_on = [
    aws_api_gateway_integration.get_users
  ]
}
```

For a larger API, ensure deployment triggers capture changes to all relevant methods, integrations, models, authorizers and resources.

# PART 9 – CACHING, THROTTLING AND PERFORMANCE

## 20. API Gateway caching

Caching stores eligible backend responses.

Example:

First request:
Client → API Gateway → Lambda → Database.

Second request:
Client → API Gateway → Cache.

The second request may not need to invoke Lambda.

### Cache parameters

- cache_cluster_enabled
- cache_cluster_size
- cache_ttl_in_seconds
- cache_key_parameters
- caching_enabled
- cache_data_encrypted

Example method settings:

```hcl
resource "aws_api_gateway_method_settings" "cache" {
  rest_api_id = aws_api_gateway_rest_api.api.id

  stage_name = aws_api_gateway_stage.prod.stage_name

  method_path = "GET/users"

  settings {
    caching_enabled      = true
    cache_ttl_in_seconds = 300
    cache_data_encrypted = true
  }
}
```

### Cache sizes

Common capacities include:

- 0.5 GB
- 1.6 GB
- 6.1 GB
- 13.5 GB
- 28.4 GB
- 58.2 GB

Verify available sizes and pricing in the target Region.

### When to enable caching

Good candidates:
- Product catalogue.
- Public reference data.
- Read-heavy endpoints.
- Slowly changing information.

Poor candidates:
- Frequently changing information.
- User-specific private data without correct cache partitioning.
- Sensitive responses.
- Transactions requiring fresh consistency.

### Cache invalidation

Cache invalidation can be controlled through TTL and supported cache invalidation behavior.

Never assume a cached response represents the latest database value.

## 21. Throttling

Throttling protects API Gateway and backend systems from excessive traffic.

Important parameters:

rate_limit:
Average request rate per second.

burst_limit:
Temporary burst capacity.

Example:

```hcl
throttle_settings {
  rate_limit  = 100
  burst_limit = 200
}
```

This configures 100 requests per second and a burst capacity of 200 as target limits.

### HTTP 429

When throttling occurs, API Gateway can return:

```http
HTTP/1.1 429 Too Many Requests
```

Clients should implement:
- Exponential backoff.
- Random jitter.
- Retry limits.
- Retry handling for idempotent requests.

# PART 10 – CORS

## 22. What is CORS?

Cross-Origin Resource Sharing allows a browser application to call an API hosted on another origin.

Example:

Frontend:
https://frontend.example.com

API:
https://api.example.com

Important headers:

```http
Access-Control-Allow-Origin: https://frontend.example.com

Access-Control-Allow-Methods: GET,POST,PUT,PATCH,DELETE,OPTIONS

Access-Control-Allow-Headers: Content-Type,Authorization,X-Api-Key

Access-Control-Allow-Credentials: true
```

Production considerations:

## 33. Lambda function code

File: lambda/index.py

```python
import json
import logging

logger = logging.getLogger()

logger.setLevel(logging.INFO)


def lambda_handler(event, context):

    try:

        path_parameters = event.get(
            "pathParameters"
        ) or {}

        user_id = path_parameters.get(
            "userId"
        )

        if not user_id:

            return {
                "statusCode": 400,
                "headers": {
                    "Content-Type": "application/json"
                },
                "body": json.dumps({
                    "message": "userId is required"
                })
            }

        logger.info(
            "Processing customer request"
        )

        response = {
            "id": user_id,
            "name": "John",
            "status": "ACTIVE"
        }

        return {
            "statusCode": 200,
            "headers": {
                "Content-Type": "application/json"
            },
            "body": json.dumps(response)
        }

    except Exception:

        logger.exception(
            "Unexpected application error"
        )

        return {
            "statusCode": 500,
            "headers": {
                "Content-Type": "application/json"
            },
            "body": json.dumps({
                "message": "Internal server error"
            })
        }
```

This is a demonstration backend. A real application should query its database, validate access to the requested customer, and avoid returning data without authorization.

## 42. Monthly cost calculation

Example assumptions:

- 5 million requests per month.
- 3 KB response per request.
- Illustrative request rate: €3.6514 per million.
- Illustrative data transfer rate: €0.07723233 per GB.

Request cost:

5,000,000 / 1,000,000 × €3.6514

= €18.257

Data transfer:

5,000,000 × 3 KB

= 15,000,000 KB

Approximately 14.3 GB.

Transfer cost:

14.3 × €0.07723233

= approximately €1.10

Estimated API Gateway charge:

€18.26 + €1.10

= approximately €19.36 per month.

This is an illustrative pricing calculation based on the AWS European pricing example, not a guaranteed Ireland quote.

It excludes Lambda, database, logging, WAF and other service costs.

€0.0375 × 24

# PART 17 – COST OPTIMISATION STRATEGIES

## 46. How to reduce API Gateway costs

### Strategy 1: Select the correct API type

If you do not need:
- API Gateway REST API caching.
- Usage plans.
- API keys.
- Private REST endpoints.
- Advanced request validation.

Consider HTTP API.

HTTP API is generally less expensive for equivalent request volume.

### Strategy 2: Reduce response payload size

Large responses increase data transfer charges.

Instead of returning:

- Unnecessary database fields.
- Large unused objects.
- Repeated metadata.
- Large nested responses.

Return only what the consumer requires.

Example:

Before:

```json
{
  "id": 101,
  "name": "John",
  "email": "john@example.com",
  "internalNotes": "Sensitive internal data",
  "unusedMetadata": {},
  "largeDescription": "..."
}
```

After:

```json
{
  "id": 101,
  "name": "John"
}
```

### Strategy 3: Enable caching for suitable GET requests

Cache slowly changing information.

Example:
GET /products

TTL:
300 seconds.

But do not cache dynamic or sensitive information without a safe cache-key strategy.

### Strategy 4: Reduce unnecessary API calls

Instead of:

GET /users/101

GET /users/101/orders

GET /users/101/preferences

Consider an aggregated endpoint if the application benefits from fewer round trips.

However, avoid creating excessively large responses or tightly coupled endpoints.

### Strategy 5: Optimise Lambda execution

Lambda costs depend on requests, memory and execution duration.

Improve:
- Code efficiency.
- Database query performance.
- Connection reuse.
- Memory allocation.
- Timeout settings.
- Cold-start performance.

### Strategy 6: Reduce CloudWatch log costs

- Set appropriate log retention.
- Avoid unnecessary INFO logs in production.
- Do not enable full request-body tracing by default.
- Avoid excessive debug output.
- Use structured logs.
- Filter unnecessary log events.

### Strategy 7: Reduce X-Ray usage where appropriate

Enable tracing where it delivers operational value.

Review trace sampling and retention costs.

### Strategy 8: Use throttling

Throttling does not directly reduce the price of every legitimate request.

It helps prevent traffic spikes from creating uncontrolled downstream costs.

### Strategy 9: Use compression

Enable suitable compression for larger text responses.

Compression can reduce outbound transfer, though CPU and latency trade-offs should be measured.

### Strategy 10: Configure budgets and alerts

Create AWS Budgets for:
- API Gateway.
- Lambda.
- CloudWatch.
- DynamoDB.
- Total account expenditure.

Use cost anomaly detection for unexpected spikes.

## 47. Cost comparison: REST API vs HTTP API

Example only; request pricing is Region- and tier-dependent.

| Feature | REST API | HTTP API |
|---|---|---|
| Typical request cost | Higher | Lower |
| Caching | Built in | No equivalent built-in cache |
| API keys/usage plans | Yes | No equivalent |
| Request validation | Advanced | More limited |
| Private REST endpoint | Yes | No equivalent |
| Advanced integration mapping | Yes | More limited |
| Simple Lambda API | Supported | Supported |

Recommendation:

Use HTTP API for simple high-volume serverless applications when its feature set is sufficient.

Use REST API when its advanced features are required.

REST API quotas include:

## 49. Common API Gateway errors

### 400 Bad Request

- Missing required parameters.
- Failed request validation.
- Invalid request format.

Check:
- Request model.
- Content-Type.
- Query parameters.
- Path parameters.

### 401 Unauthorized

Possible reasons:
- Missing token.
- Invalid token.
- Failed authorizer.

Check:
- Authorization header.
- Cognito configuration.
- Lambda authorizer.
- Token expiry.

### 403 Forbidden

Possible reasons:
- IAM permission denied.
- Resource policy denial.
- Invalid API key.
- WAF block.
- Private API access restrictions.

Check:
- IAM policy.
- Resource policy.
- Usage plan association.
- VPC endpoint policy.
- WAF logs.

### 404 Not Found

Possible reasons:
- Incorrect resource path.
- Wrong stage.
- Incorrect URL.
- Missing resource deployment.

### 405 Method Not Allowed

Possible reason:
HTTP method is not configured for the requested resource.

### 413 Payload Too Large

Request payload exceeds the supported request limit.

### 415 Unsupported Media Type

Content-Type is not supported by the configured method or integration.

### 429 Too Many Requests

Possible reasons:
- Stage throttling.
- Usage plan throttling.
- Account-level request throttling.

### 500 Internal Server Error

Possible reasons:
- Backend integration failure.
- Internal API Gateway processing error.
- Incorrect backend configuration.

### 502 Bad Gateway

Common Lambda proxy issue:
Lambda returns an invalid response structure.

Expected response:

```json
{
  "statusCode": 200,
  "headers": {
    "Content-Type": "application/json"
  },
  "body": "{\"message\":\"Success\"}"
}
```

### 504 Gateway Timeout

Possible reasons:
- Backend takes too long.
- Database queries are slow.
- Lambda execution is too slow.
- Integration timeout is exceeded.

# PART 22 – INTERVIEW QUESTIONS AND ANSWERS

## 63. Basic questions

Q1. What is AWS API Gateway?

A. A managed AWS service for creating, publishing, securing, monitoring and managing APIs.

Q2. What is a REST API?

A. An HTTP-based API following REST architectural principles.

Q3. What is a resource?

A. A URL path representing an API resource.

Q4. What is a method?

A. An HTTP operation associated with a resource.

Q5. What is the difference between GET and POST?

A. GET retrieves information; POST creates a resource or performs an operation.

Q6. What is an API stage?

A. A named environment associated with an API deployment.

Q7. What is an API deployment?

A. A snapshot of the REST API configuration.

Q8. What is an API resource policy?

A. A resource-based policy controlling who can invoke the API.

Q9. What is an API key?

A. A consumer identifier used with usage plans.

Q10. What is a usage plan?

A. A configuration that defines API key associations, throttling targets and quotas.

## 64. Integration questions

Q11. What is Lambda proxy integration?

A. Integration where API Gateway forwards request information to Lambda and Lambda returns the HTTP response.

Q12. What is non-proxy integration?

A. Integration where API Gateway controls request and response transformation.

Q13. What is MOCK integration?

A. An integration that returns a configured response without calling a backend.

Q14. Can API Gateway invoke DynamoDB directly?

A. Yes, using supported AWS service integration actions.

Q15. What is VTL?

A. Velocity Template Language, used for request and response mapping templates.

Q16. What is the difference between method request and integration request?

A. Method request defines client input; integration request defines backend input.

Q17. What is the difference between integration response and method response?

A. Integration response handles backend output; method response defines the client-facing response contract.

## 65. Security questions

Q18. What are API Gateway authorizers?

A. Components that evaluate identity and access permissions.

Q19. What is a Lambda authorizer?

A. A Lambda function that evaluates request identity and returns an authorization policy.

Q20. What is the difference between TOKEN and REQUEST authorizers?

A. TOKEN receives a token-based identity input; REQUEST evaluates supported request information.

Q21. What is AWS_IAM authorization?

A. Authorization based on AWS Signature Version 4 and IAM permissions.

Q22. What is Cognito authorization?

A. Authorization using Amazon Cognito user pool identities and supported OAuth scopes.

Q23. Why should API keys not be used as authentication?

A. They identify consumers and support usage metering but do not prove an individual user's identity.

## 66. Performance questions

Q24. What is API Gateway caching?

A. It stores eligible responses to reduce backend requests.

Q25. What is throttling?

A. It limits target request rates and burst capacity.

Q26. What is burst limit?

A. The temporary request capacity allowed above the steady target rate.

Q27. What is integration latency?

A. Time spent waiting for the backend integration.

Q28. What is API Gateway latency?

A. Total time taken by API Gateway to return the response.

Q29. How do you reduce API latency?

A. Optimise backend processing, database queries, payload size, connection handling and suitable caching.

## 67. Production questions

Q30. How do you deploy an API Gateway REST API?

A. Create the REST API configuration, create a deployment, associate it with a stage, and expose the invoke URL.

Q31. What happens if you change an API method?

A. The configuration must be deployed again before the stage uses the updated snapshot.

Q32. How do you monitor API Gateway?

A. CloudWatch metrics, access logs, execution logs and X-Ray tracing.

Q33. How do you protect API Gateway from excessive traffic?

A. Throttling, usage plans, WAF, authentication and suitable backend protection.

Q34. How do you connect API Gateway to a private backend?

A. Use an appropriate VPC Link integration.

Q35. What is the difference between a private API and VPC Link?

A. Private API controls how clients reach API Gateway; VPC Link connects API Gateway to supported private backends.

Q36. What is CORS?

A. A browser security mechanism controlling cross-origin access.

Q37. How do you troubleshoot a 502 error?

A. Check Lambda logs, proxy response structure, integration settings and invocation permissions.

Q38. How do you troubleshoot a 504 error?

A. Check backend latency, Lambda duration, integration timeout and database performance.

Q39. How do you reduce API Gateway cost?

A. Select the appropriate API type, optimise response size, cache suitable responses, monitor traffic and reduce unnecessary backend work.

Q40. How do you handle long-running backend tasks?

A. Return an accepted response and process the work asynchronously through services such as SQS, Step Functions or EventBridge.
