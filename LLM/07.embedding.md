# Embeddings in LangChain and OpenAI — Complete Practical Guide

## 1. What are embeddings?

### What are they?

An **embedding** is a numerical representation of text, usually stored as a list of floating-point numbers called a vector.

For example, imagine these sentences:

- "I love programming."
- "I enjoy writing code."
- "The weather is sunny today."

An embedding model converts each sentence into a vector.

Illustrative example (not actual OpenAI output):

```python
"I love programming."
[0.21, 0.84, -0.32, 0.15, 0.67]

"I enjoy writing code."
[0.23, 0.81, -0.29, 0.18, 0.63]

"The weather is sunny today."
[-0.72, 0.14, 0.91, -0.45, 0.11]
```

The first two vectors are likely to be closer to each other because their meanings are related.

The third vector represents a different subject, so it is likely to be farther away.

**Important:** These are simplified five-dimensional examples. Real OpenAI embeddings contain hundreds or thousands of numbers.

### Why do we need embeddings?

Imagine you have a knowledge base containing:

```text
Document 1: Python is a popular programming language.

Document 2: FastAPI is a Python framework for building APIs.

Document 3: LangChain helps developers build applications using LLMs.

Document 4: The Eiffel Tower is located in Paris.
```

A user asks:

```text
Which framework can I use to build an API with Python?
```

Traditional keyword search might look for documents containing the exact words "framework", "build", "API", and "Python".

Semantic search uses embeddings to identify documents with related meaning.

It can retrieve Document 2 even if the user's wording differs from the document's wording.

### Where are embeddings used?

- Semantic search
- Retrieval-Augmented Generation (RAG)
- Recommendation systems
- Document clustering
- Text classification
- Duplicate detection
- Question-answering applications
- Knowledge-base search

### How embeddings fit into RAG

```text
              DOCUMENTS
                  |
                  v

                  |
                  v

                  |
                  v
          Numerical vectors
                  |
                  v

                  |
                  |
USER QUESTION    |
      |           |
      v           |

```

The embedding model helps find relevant information. The chat model uses that information to generate an answer.

**Remember:** Embeddings do not generate answers. They represent text numerically so that your application can compare and retrieve it.

## 2. How embedding models work

### What happens inside an embedding model?

An embedding model is a neural network trained to represent text in a numerical vector space.

At a simplified level, the process is:

1. The model receives text.
2. The text is tokenized.
3. The model processes the tokens.
4. It builds a representation of the text.
5. It produces a fixed-length vector.

For example:

```text
Input:
"Python is used for machine learning."

          |
          v

      Tokenization

          |
          v

   Neural network processing

          |
          v

    Numerical representation

          |
          v

Output:
[0.12, -0.43, 0.87, ...]
```

### How does the model understand similarity?

Embedding models are trained so that text with related meanings tends to have related vector representations.

For example:

```text
"How can I learn Python?"
"What is the best way to study Python?"
"How do I start programming in Python?"
```

These sentences may have relatively similar embeddings.

However:

```text
"What is the capital of France?"
```

will likely have a different embedding.

### Important concepts

**Vector:** A list of numerical values.

**Dimension:** The number of values in a vector.

**Vector space:** The mathematical space in which vectors are represented.

**Similarity:** A measurement of how closely related two vectors are.

**Distance:** A measurement of how far apart two vectors are.

## 3. OpenAIEmbeddings

### What is OpenAIEmbeddings?

`OpenAIEmbeddings` is LangChain's integration for generating embeddings using OpenAI embedding models.

It allows you to generate vectors without directly calling the OpenAI embeddings API.

You can use it with vector stores such as:

- FAISS
- Chroma
- Pinecone
- Other vector databases supported by LangChain

### Why use it?

It provides a consistent interface for generating embeddings.

For example, you can use the same embedding object when:

- Creating document embeddings.
- Creating a query embedding.
- Building a vector database.
- Searching for relevant documents.

### Installation

```bash
pip install -U langchain langchain-openai langchain-community faiss-cpu python-dotenv tiktoken
```

### Configure your API key

Create a `.env` file:

```env
OPENAI_API_KEY=your_openai_api_key
```

Load it:

```python
from dotenv import load_dotenv

load_dotenv()
```

### Initialize OpenAIEmbeddings

```python
from langchain_openai import OpenAIEmbeddings

embeddings = OpenAIEmbeddings(
    model="text-embedding-3-small"
)

print(embeddings)
```

Here:

- `OpenAIEmbeddings` is the LangChain integration.
- `model` specifies the OpenAI embedding model.
- `text-embedding-3-small` is a cost-effective general-purpose embedding model.

OpenAI also provides `text-embedding-3-large`, which produces larger default vectors and may provide better retrieval quality for demanding applications.

### Choosing an embedding model

| Model | Default dimensions | Typical use |
|---|---:|---|
| `text-embedding-3-small` | 1536 | General-purpose search and RAG |
| `text-embedding-3-large` | 3072 | Applications prioritizing retrieval quality |
| `text-embedding-ada-002` | 1536 | Older model; generally prefer v3 for new projects |

For learning and many RAG applications, start with:

```python
embeddings = OpenAIEmbeddings(
    model="text-embedding-3-small"
)
```

## 4. embed_query()

### What is embed_query()?

`embed_query()` converts one query or question into a numerical vector.

### Why do we need it?

When a user asks a question in a RAG application, you need to convert that question into a vector so it can be compared with the document vectors already stored in your vector database.

### Example

```python
from langchain_openai import OpenAIEmbeddings

embeddings = OpenAIEmbeddings(
    model="text-embedding-3-small"
)

query = "What is Python used for?"

query_vector = embeddings.embed_query(query)

print(type(query_vector))
print(len(query_vector))
print(query_vector[:5])
```

### Expected output

```text
<class 'list'>
1536
[-0.0123, 0.0456, 0.0789, -0.0234, 0.0156]
```

The numerical values are illustrative. Actual embeddings depend on the input and API response.

### Understand the result

```python
query_vector = embeddings.embed_query(
    "What is Python used for?"
)
```

The returned value is a single vector:

```python
[
    0.012,
    -0.032,
    0.056,
    ...
]
```

It contains 1536 values when using the default dimensions of `text-embedding-3-small`.

**Remember:** Use `embed_query()` when you want to embed a single search query.

## 5. embed_documents()

### What is embed_documents()?

`embed_documents()` converts multiple text documents into numerical vectors.

### Why do we need it?

Before searching your knowledge base, you need to convert its documents into vectors and store those vectors in a vector database.

### Example

```python
from langchain_openai import OpenAIEmbeddings

embeddings = OpenAIEmbeddings(
    model="text-embedding-3-small"
)

documents = [
    "Python is a programming language.",
    "FastAPI is a framework for building APIs.",
    "LangChain is used to build LLM applications."
]

document_vectors = embeddings.embed_documents(documents)

print(len(document_vectors))
print(len(document_vectors[0]))
print(document_vectors[0][:5])
```

### Expected output

```text
3
1536
[-0.0123, 0.0456, 0.0789, -0.0234, 0.0156]
```

The exact vector values will differ.

### Understand the result

You supplied three documents.

Therefore:

```python
len(document_vectors)
```

returns:

```text
3
```

Each document gets one vector.

```python
len(document_vectors[0])
```

returns:

```text
1536
```

Each vector contains 1536 dimensions.

### Difference between embed_query() and embed_documents()

| Method | Input | Output |
|---|---|---|
| `embed_query()` | One text string | One vector |
| `embed_documents()` | List of text strings | List of vectors |

Example:

```python
query_vector = embeddings.embed_query(
    "What is FastAPI?"
)

document_vectors = embeddings.embed_documents([
    "FastAPI is a Python framework.",
    "Python is a programming language."
])
```

### Why does LangChain have two methods?

The LangChain embeddings interface separates query embedding from document embedding because some embedding providers use different instructions or strategies for queries and documents.

With standard OpenAI embedding models, both methods generally use the same embedding model and compatible representation.

This is important: **use the same embedding model and compatible dimensions for indexing and searching.**

## 6. Embedding dimensions

### What are embedding dimensions?

Dimensions represent the number of numerical values in an embedding vector.

For example:

```python
vector = [0.12, 0.45, -0.32, 0.67]
```

This vector has four dimensions.

A real OpenAI embedding might have 1536 dimensions:

```python
[
    0.12,
    0.45,
    -0.32,
    0.67,
    ...
]
```

### Why do dimensions matter?

Dimensions affect:

- Vector storage requirements.
- Memory consumption.
- Search performance.
- Index size.
- Potential retrieval quality.

Larger dimensions generally require more storage and computation.

However, more dimensions do not automatically mean better results for every application.

### OpenAI embedding dimensions

| Model | Default dimensions |
|---|---:|
| `text-embedding-3-small` | 1536 |
| `text-embedding-3-large` | 3072 |

OpenAI's third-generation embedding models support reducing the output dimensions using the `dimensions` parameter.

### Example: Reduce dimensions

```python
from langchain_openai import OpenAIEmbeddings

embeddings = OpenAIEmbeddings(
    model="text-embedding-3-small",
    dimensions=512
)

vector = embeddings.embed_query(
    "What is machine learning?"
)

print(len(vector))
```

Expected output:

```text
512
```

You requested a 512-dimensional embedding instead of the default 1536-dimensional embedding.

### When should you reduce dimensions?

Consider reducing dimensions when:

- Your vector database has storage constraints.
- You have a very large collection of documents.
- You want to reduce memory requirements.
- You have tested that retrieval quality remains acceptable.

### Important warning

The dimension must match the vector index configuration.

For example:

```text
Document embeddings: 512 dimensions
Query embeddings:    1536 dimensions
```

These vectors cannot be compared directly.

Also, if you change the embedding model or dimensions, you generally need to regenerate and re-index your existing document embeddings.

## 7. Similarity metrics

### What are similarity metrics?

Similarity metrics are mathematical methods used to compare two vectors.

They help determine whether two pieces of text have related meanings.

For example:

```text
Query:
"What is Python?"

Document A:
"Python is a programming language."

Document B:
"The weather is sunny."
```

The similarity metric helps rank the documents based on their vector representations.

### Common similarity metrics

1. Cosine similarity
2. Euclidean distance
3. Dot product

Different vector databases and indexing systems may use different distance strategies.

---

## 8. Cosine similarity

### What is cosine similarity?

Cosine similarity measures the angle between two vectors.

It focuses on the direction of the vectors rather than their absolute magnitudes.

The formula is:

\[
\text{Cosine Similarity}(A,B)=
\frac{A\cdot B}{\|A\|\|B\|}
\]

Where:

- \(A\) = first vector
- \(B\) = second vector
- \(A\cdot B\) = dot product
- \(\|A\|\) and \(\|B\|\) = vector magnitudes

### How to interpret it

For non-zero vectors:

| Value | General interpretation |
|---:|---|
| 1 | Same direction |
| 0 | Perpendicular vectors |
| -1 | Opposite directions |

These values describe vector geometry, not a guaranteed percentage of semantic similarity.

### Python example

```python
import numpy as np

vector_a = np.array([1, 2, 3])
vector_b = np.array([1, 2, 4])

similarity = np.dot(vector_a, vector_b) / (
    np.linalg.norm(vector_a) *
    np.linalg.norm(vector_b)
)

print(similarity)
```

Expected output:

```text
0.9915
```

The vectors point in similar directions, so their cosine similarity is high.

### When should you use cosine similarity?

Cosine similarity is a common choice for semantic search and embedding-based retrieval.

OpenAI recommends cosine similarity for comparing its embeddings.

---

## 9. Euclidean distance

### What is Euclidean distance?

Euclidean distance measures the straight-line distance between two points in vector space.

The formula is:

\[
d(A,B)=\sqrt{\sum_{i=1}^{n}(A_i-B_i)^2}
\]

A smaller distance means the vectors are closer together.

### Python example

```python
import numpy as np

vector_a = np.array([1, 2, 3])
vector_b = np.array([1, 2, 4])

distance = np.linalg.norm(vector_a - vector_b)

print(distance)
```

Expected output:

```text
1.0
```

Only the third coordinate differs, by one unit.

### How to interpret it

| Distance | General interpretation |
|---:|---|
| 0 | Identical vectors |
| Small distance | Vectors are close |
| Large distance | Vectors are farther apart |

Unlike cosine similarity, smaller Euclidean distance indicates greater closeness.

### When is Euclidean distance useful?

- Vector search.
- Geometric clustering.
- Nearest-neighbour search.
- Applications where vector magnitude is meaningful.

---

## 10. Dot product

### What is dot product?

The dot product multiplies corresponding vector elements and adds the results.

The formula is:

\[
A\cdot B=\sum_{i=1}^{n} A_iB_i
\]

### Python example

```python
import numpy as np

vector_a = np.array([1, 2, 3])
vector_b = np.array([4, 5, 6])

result = np.dot(vector_a, vector_b)

print(result)
```

Expected output:

```text
32
```

Calculation:

```text
(1 × 4) + (2 × 5) + (3 × 6)

= 4 + 10 + 18

= 32
```

### When is dot product useful?

- Vector similarity calculations.
- Machine learning.
- Neural networks.
- Vector database search.

### Comparison of the three metrics

| Metric | What it measures | Better match |
|---|---|---|
| Cosine similarity | Directional similarity | Higher score |
| Euclidean distance | Straight-line distance | Lower distance |
| Dot product | Alignment and magnitude | Usually higher score |

### Important OpenAI detail

OpenAI embeddings are normalized to length 1.

For normalized vectors:

- Cosine similarity equals the dot product.
- Cosine similarity and Euclidean distance produce the same ranking.

This makes cosine-based comparison particularly convenient for OpenAI embeddings.

## 11. Embedding token limits

### What is an embedding token limit?

Embedding models have a maximum number of tokens they can accept in an individual input.

If your input exceeds the model's maximum token limit, the API will reject it unless your application splits the text into smaller inputs first.

For OpenAI embedding models, the maximum input length is **8192 tokens per input**.

The API also has a maximum combined input size of 300,000 tokens per request.

### Example

Suppose you want to embed a document containing 20,000 tokens.

You cannot send it as one input.

Instead, split it into smaller chunks:

```text
Original document
       |
       v
20,000 tokens
       |
       v
Split into chunks
       |
       +---- Chunk 1: 1,000 tokens
       |
       +---- Chunk 2: 1,000 tokens
       |
       +---- Chunk 3: 1,000 tokens
       |
       +---- ...
       |
       v
Generate embeddings
       |
       v
Store vectors
```

### Count tokens using tiktoken

Install:

```bash
pip install tiktoken
```

Example:

```python
import tiktoken

encoding = tiktoken.get_encoding("cl100k_base")

text = """
Python is a popular programming language.
It is used in machine learning and automation.
"""

tokens = encoding.encode(text)

print("Token count:", len(tokens))
```

Expected output:

```text
Token count: <calculated token count>
```

The number depends on the exact text.

For OpenAI's third-generation embedding models, `cl100k_base` is the documented encoding to use for token counting.

### Check whether text exceeds the limit

```python
import tiktoken

encoding = tiktoken.get_encoding("cl100k_base")

def count_tokens(text):
    return len(encoding.encode(text))

text = "Python is a programming language."

token_count = count_tokens(text)

if token_count <= 8192:
    print("Text is within the embedding limit.")
else:
    print("Split the text before embedding.")

print("Tokens:", token_count)
```

### Why is text splitting important in RAG?

In RAG, you generally split documents into chunks before generating embeddings.

For example:

```text
Large PDF
   |
   v
Extract text
   |
   v
Split into chunks
   |
   v
Generate embeddings
   |
   v
Store in vector database
```

Chunking helps keep inputs within token limits and makes retrieval more focused.

## 12. Embedding cost management

### What determines embedding cost?

Embedding cost is primarily based on the number of input tokens sent to the embedding model.

For example, if you embed:

- 100 documents containing 500 tokens each,
- the total input is approximately 50,000 tokens.

The more text you embed, the more you pay.

### OpenAI model pricing

The following published model prices are per one million input tokens:

| Model | Standard API price |
|---|---:|
| `text-embedding-3-small` | $0.02 / 1M tokens |
| `text-embedding-3-large` | $0.13 / 1M tokens |

Check the current pricing page before production use because prices can change.

### Example cost calculation

Suppose you embed 10 million tokens using `text-embedding-3-small`.

\[
\text{Cost} =
\frac{10,000,000}{1,000,000}
\times \$0.02
\]

Expected cost:

```text
$0.20
```

Using the published standard price above, the same 10 million tokens with `text-embedding-3-large` would cost:

```text
$1.30
```

### How to reduce embedding costs

**1. Choose the right model**

Start with `text-embedding-3-small` and evaluate retrieval quality before moving to a larger model.

**2. Avoid unnecessary embedding calls**

Do not regenerate embeddings every time a user asks a question.

Generate document embeddings when documents are added or changed.

**3. Cache embeddings**

If the same text appears again, reuse its previously generated vector.

A simple in-memory example:

```python
embedding_cache = {}

def get_embedding(text, embeddings):
    if text not in embedding_cache:
        embedding_cache[text] = embeddings.embed_query(text)

    return embedding_cache[text]
```

This is an educational example. For production, use persistent caching and a content hash as the cache key.

**4. Use batch embedding**

Embed multiple documents together instead of making a separate API request for every document.

```python
vectors = embeddings.embed_documents([
    "Python is a programming language.",
    "FastAPI is a Python framework.",
    "LangChain builds LLM applications."
])
```

**5. Remove unnecessary content**

Avoid embedding repeated navigation text, irrelevant headers, duplicate pages, and unnecessary boilerplate.

**6. Use appropriate chunk sizes**

Extremely small chunks can create many vectors and increase indexing and storage overhead.

Extremely large chunks can make retrieval less precise.

Test different chunk sizes against your actual questions.

**7. Use reduced dimensions when appropriate**

For supported v3 models, smaller output vectors can reduce vector storage and search overhead.

Measure retrieval quality before adopting a smaller dimension.

## 13. Vector indexing

### What is vector indexing?

Vector indexing is the process of organizing vectors so that similar vectors can be searched efficiently.

Imagine you have one million document embeddings.

Comparing a query vector with every document vector can become expensive.

A vector index helps retrieve nearby vectors more efficiently.

### Why do we need vector indexing?

Without an index, a basic search may compare the query against every stored vector.

This is called a brute-force or exact search.

For a large collection, this can become slow.

Vector indexing helps improve retrieval speed.

### How does it work?

A simplified flow:

```text
Document chunks
      |
      v
Embedding model
      |
      v
Document vectors
      |
      v
Vector index
      |
      v
Organized for searching
      |
      |
User query
      |
      v
Query embedding
      |
      v
Search the vector index
      |
      v
Nearest vectors
      |
      v
Relevant documents
```

### Common vector index approaches

**1. Flat index**

Stores vectors and performs exact comparisons.

Advantages:
- Simple.
- Exact nearest-neighbour results.
- Useful for smaller collections and evaluation.

Disadvantages:
- Search can become expensive as the collection grows.

**2. HNSW (Hierarchical Navigable Small World)**

Uses a graph structure to navigate between nearby vectors.

Advantages:
- Fast approximate nearest-neighbour search.
- Common in production vector databases.

Disadvantages:
- Uses additional memory.
- Approximate search can occasionally miss the exact nearest neighbours.

**3. IVF (Inverted File Index)**

Partitions vectors into groups or clusters and searches selected groups.

Advantages:
- Can reduce the number of comparisons.
- Useful for large vector collections.

Disadvantages:
- Requires index configuration and tuning.
- May trade some recall for speed.

### Exact versus approximate search

| Approach | Search behavior | Main trade-off |
|---|---|---|
| Flat | Compares against all vectors | Exact but potentially slower |
| HNSW | Navigates a graph | Fast approximate search |
| IVF | Searches selected partitions | Efficient with suitable tuning |

The right choice depends on collection size, latency requirements, memory, and retrieval accuracy.

## 14. Create a vector index using LangChain and FAISS

### What is FAISS?

FAISS stands for Facebook AI Similarity Search.

It is a library for efficient similarity search and clustering of dense vectors.

LangChain provides a FAISS vector-store integration.

### Install FAISS

```bash
pip install -U faiss-cpu langchain-community langchain-openai
```

### Step 1: Create sample documents

```python
from langchain_core.documents import Document

documents = [
    Document(
        page_content="Python is a popular programming language.",
        metadata={"topic": "programming"}
    ),
    Document(
        page_content="FastAPI is a Python framework for building APIs.",
        metadata={"topic": "framework"}
    ),
    Document(
        page_content="LangChain helps developers build LLM applications.",
        metadata={"topic": "llm"}
    ),
    Document(
        page_content="The Eiffel Tower is a famous landmark in Paris.",
        metadata={"topic": "travel"}
    )
]
```

Each `Document` contains:

- `page_content`: the text to embed.
- `metadata`: additional information about the document.

### Step 2: Initialize the embedding model

```python
from langchain_openai import OpenAIEmbeddings

embeddings = OpenAIEmbeddings(
    model="text-embedding-3-small"
)
```

### Step 3: Create the FAISS vector store

```python
from langchain_community.vectorstores import FAISS

vector_store = FAISS.from_documents(
    documents,
    embeddings
)
```

What happens internally?

1. LangChain reads the document text.
2. It calls the embedding model.
3. OpenAI returns a vector for each document.
4. FAISS stores the vectors in an index.
5. LangChain maintains the associated documents and metadata.

### Step 4: Search the vector store

```python
query = "Which tool can I use to build a Python API?"

results = vector_store.similarity_search(
    query,
    k=2
)

for result in results:
    print(result.page_content)
    print(result.metadata)
    print("---")
```

Possible output:

```text
FastAPI is a Python framework for building APIs.
{'topic': 'framework'}
---
Python is a popular programming language.
{'topic': 'programming'}
---
```

The exact ranking depends on the embedding model and similarity search.

### Step 5: Search with scores

```python
results = vector_store.similarity_search_with_score(
    "Which tool can I use to build a Python API?",
    k=2
)

for document, score in results:
    print("Document:", document.page_content)
    print("Score:", score)
    print("---")
```

**Important:** With the default LangChain FAISS configuration, the score is generally an L2 distance, where a smaller value means a closer vector. The score is not a probability.

### Step 6: Save the vector store

```python
vector_store.save_local("faiss_index")
```

This saves the index and associated document store locally.

### Step 7: Load the vector store

```python
loaded_vector_store = FAISS.load_local(
    "faiss_index",
    embeddings,
    allow_dangerous_deserialization=True
)
```

Only load a FAISS store you created yourself or otherwise trust. The option permits deserialization of stored Python objects and can be unsafe for untrusted files.

### Step 8: Search again

```python
results = loaded_vector_store.similarity_search(
    "What is LangChain?",
    k=2
)

for result in results:
    print(result.page_content)
```

You have now created, saved, loaded, and searched a vector index.

## 15. How vector indexing fits into a complete RAG application

Let's connect the concepts.

### Indexing stage

This usually happens when you add or update your knowledge base.

```text
PDF / CSV / Website
        |
        v
  Document loader
        |
        v
    Text splitter
        |
        v
   Document chunks
        |
        v
   OpenAIEmbeddings
        |
        v
   Numerical vectors
        |
        v
    Vector index
        |
        v
   Stored documents
```

### Retrieval stage

This happens when a user asks a question.

```text
User question
      |
      v
OpenAIEmbeddings
      |
      v
Query vector
      |
      v
Vector similarity search
      |
      v
Top relevant documents
      |
      v
Prompt + retrieved context
      |
      v
ChatOpenAI
      |
      v
Generated answer
```

### Important distinction

**Embedding generation** converts text into vectors.

**Vector indexing** organizes vectors for efficient retrieval.

**Vector retrieval** finds vectors most relevant to a query.

**LLM generation** uses retrieved information to produce an answer.

These are four separate responsibilities.

```python

from langchain_openai import OpenAIEmbeddings

from langchain_core.documents import Document

load_dotenv()

# 1. Create the embedding model

    model="text-embedding-3-small"
)

# 2. Create documents
documents = [
    Document(
        page_content="Python is used for machine learning and automation.",
        metadata={"category": "programming"}
    ),
    Document(
        page_content="FastAPI is used to create APIs with Python.",
        metadata={"category": "framework"}
    ),
    Document(
        page_content="LangChain is used to build applications with LLMs.",
        metadata={"category": "ai"}
    ),
    Document(
        page_content="Chroma and FAISS can store and search embeddings.",
        metadata={"category": "vector-database"}
    )
]

# 3. Create vector index
vector_store = FAISS.from_documents(
    documents,
    embeddings
)

# 4. Get user query
query = "How can I create an API using Python?"

# 5. Search similar documents
results = vector_store.similarity_search(
    query,
    k=2
)

# 6. Display results
print("User question:", query)
print("\nRelevant documents:")

for index, document in enumerate(results, start=1):
    print(f"\nResult {index}")
    print("Content:", document.page_content)
    print("Metadata:", document.metadata)
```

The search retrieves documents based on vector similarity rather than requiring an exact keyword match.

## 17. Important best practices

When building a production embedding and retrieval system:

1. Use the same embedding model for document indexing and query embedding.
2. Keep embedding dimensions consistent.
3. Split long documents before embedding.
4. Avoid embedding duplicate or irrelevant content.
5. Cache embeddings when the same content is reused.
6. Batch document embedding where practical.
7. Store metadata alongside vectors.
8. Choose a similarity metric compatible with your vector index.
9. Evaluate retrieval quality with real user questions.
10. Re-index documents when you change the embedding model or dimensions.
11. Monitor token usage and embedding costs.
12. Keep a record of the model and dimensions used to build each index.

### One particularly important production rule

If you change from:

```python
OpenAIEmbeddings(
    model="text-embedding-3-small",
    dimensions=1536
)
```

to:

```python
OpenAIEmbeddings(
    model="text-embedding-3-large",
    dimensions=1024
)
```

you cannot simply use the new query embeddings against the old index.

You must regenerate the document embeddings and rebuild or migrate the index so that all vectors use a compatible embedding space.

## 20. Final summary

The central idea is:

**Embeddings turn text into numbers so that applications can search by meaning.**

The overall process is:

```text
Text
  |
  v
OpenAI Embedding Model
  |
  v
Vector
  |
  v
Vector Index
  |
  v
Similarity Search
  |
  v
Relevant Documents
```

For your LangChain RAG applications, the key code is:

```python
from langchain_openai import OpenAIEmbeddings

embeddings = OpenAIEmbeddings(
    model="text-embedding-3-small"
)

# Embed one query
query_vector = embeddings.embed_query(
    "What is Python?"
)

# Embed multiple documents
document_vectors = embeddings.embed_documents([
    "Python is a programming language.",
    "FastAPI is a Python framework."
])
```

And to create a searchable index:

```python
from langchain_community.vectorstores import FAISS

vector_store = FAISS.from_documents(
    documents,
    embeddings
)

results = vector_store.similarity_search(
    "What is Python?",
    k=2
)
```

**The most important connection:** Embeddings generate vectors, vector indexes store and organize those vectors, retrievers find relevant documents, and chat models use those documents to answer questions.
