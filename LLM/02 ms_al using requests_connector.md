# Complete Enterprise Python Connector Lesson: SharePoint to Amazon S3 Using MSAL, Microsoft Graph REST API, Requests and Boto3

# PART 1 — Understanding the complete architecture

## 1. What are we building?

We are building a Python source connector that:

1. Authenticates with Microsoft Entra ID.
2. Obtains an access token using MSAL.
3. Uses Microsoft Graph REST API to access SharePoint.
4. Retrieves documents and folders.
5. Navigates nested folders.
6. Downloads document contents.
7. Uploads documents directly into Amazon S3.
8. Detects new, modified and deleted documents.
9. Handles pagination, temporary failures and API throttling.
10. Saves synchronisation state so future runs do not need to download everything again.

Our complete architecture is:

```text
              MICROSOFT ENTRA ID
                      |
                      |
              Python MSAL Library
                      |
                      |
              Access Token Generated
                      |
                      |
             MICROSOFT GRAPH API
                      |
                      |
               Python requests
                      |
                      |
                SHAREPOINT
                      |
                      |
             Download Document Bytes
                      |
                      |
                Python boto3
                      |
                      |
                 AMAZON S3
                      |
                      |
            Save Delta Synchronisation
                  State in S3
```

## 2. What does each technology do?

This is important because each library has a different responsibility.

| Technology | Responsibility | Why we need it |
|---|---|---|
| Microsoft Entra ID | Application identity and authentication | Verifies our application |
| MSAL | Token acquisition | Obtains the Microsoft Graph access token |
| Microsoft Graph | SharePoint API | Provides access to SharePoint documents and folders |
| `requests` | HTTP communication | Sends REST API requests to Microsoft Graph |
| `boto3` | AWS communication | Uploads documents and saves connector state in S3 |
| Amazon S3 | Document storage | Stores the downloaded SharePoint documents |

**The key distinction:**

MSAL handles authentication.

Microsoft Graph handles SharePoint access.

Requests handles communication with the Graph API.

Boto3 handles communication with AWS.

# PART 2 — Understanding MSAL authentication

## 3. What is Microsoft Entra ID?

Microsoft Entra ID is Microsoft's identity and access management service.

Previously, it was called Azure Active Directory (Azure AD).

It manages identities for:

- Applications
- Users
- Organisations
- Services
- Authentication
- Permissions

When our Python connector tries to access SharePoint, Microsoft needs to establish whether the application is allowed to access the requested information.

This is where Microsoft Entra ID comes in.

Our application must be registered with Microsoft Entra ID.

## 4. What is MSAL?

MSAL stands for **Microsoft Authentication Library**.

It is a Python library provided by Microsoft for obtaining authentication tokens.

We use MSAL because Microsoft Graph requires authentication before allowing our connector to access protected SharePoint resources.

Think of MSAL as the component responsible for obtaining our access pass.

The access token is then presented to Microsoft Graph.

### How does MSAL connect to Microsoft Graph?

MSAL does not directly retrieve files from SharePoint.

Instead, the process works like this:

```text
Python Connector
       |
       |
       | 1. Send application credentials
       v
Microsoft Entra ID
       |
       |
       | 2. Validate application
       |
       | 3. Check configured permissions
       |
       | 4. Issue access token
       v
Python Connector
       |
       |
       | 5. Send access token in HTTP header
       v
Microsoft Graph REST API
       |
       |
       | 6. Validate access token
       |
       | 7. Check Graph permissions
       v
SharePoint Documents
```

The connection between MSAL and Microsoft Graph is the **access token**.

MSAL obtains the token from Microsoft Entra ID.

Our Python code places that token into the HTTP Authorization header.

Microsoft Graph validates it when we send a request.

For example:

```python
headers = {
    "Authorization": f"Bearer {ACCESS_TOKEN}"
}
```

This is how the token generated by MSAL is passed to Microsoft Graph.

## 5. Why are we using MSAL instead of manually generating a token?

We should not normally implement the token acquisition process ourselves.

MSAL handles important authentication functionality, including:

- Communicating with Microsoft Entra ID.
- Using the appropriate authentication flow.
- Obtaining access tokens.
- Handling token caching.
- Returning authentication errors.

Microsoft recommends using MSAL rather than implementing token acquisition logic manually.

For our unattended connector, we will use the **client credentials flow**.

This allows our Python application to authenticate as itself, without a person signing in each time.

## 6. What is client credentials authentication?

There are different ways applications can authenticate.

For example:

| Authentication flow | Typical use |
|---|---|
| Client credentials | Background services and automated connectors |
| Authorization code | Applications where a user signs in |
| Device code | Applications where a user signs in through another device |
| On-behalf-of | An application calls another API on behalf of an authenticated user |

For our SharePoint-to-S3 connector, client credentials is a suitable choice because the connector is intended to run automatically.

The application authenticates using its own identity.

It does not need an individual employee to sign in every time it runs.

## 7. What information do we need from Microsoft Entra ID?

We need to register an application in the Microsoft Entra admin centre.

Our application registration provides these values:

| Value | Explanation |
|---|---|
| Tenant ID | Identifies our Microsoft organisation |
| Client ID | Identifies our registered application |
| Client Secret | A credential used by the application to authenticate |
| Microsoft Graph permissions | Defines what the application is allowed to access |

Example configuration:

```python

CLIENT_ID = "YOUR_CLIENT_ID"

CLIENT_SECRET = "YOUR_CLIENT_SECRET"
```

These are placeholders.

You must obtain the actual values from your organisation's application registration.

### What permissions do we need?

For example:

- `Sites.Read.All`
- `Files.Read.All`

The appropriate permissions depend on the SharePoint resources and Graph endpoints you need.

For an enterprise connector, consider `Sites.Selected` where appropriate. This allows an application to be granted access to specifically selected SharePoint sites, rather than granting broad access to all sites.

Important:

- These examples are Microsoft Graph **application permissions**.
- An administrator must grant the required consent.
- `Sites.Selected` also needs an explicit site-level permission grant.
- The application must have the appropriate access to the target SharePoint site.

Use the least privilege necessary.

## 11. Generate the Microsoft Graph access token using MSAL

This is our authentication function:

```python
def get_graph_access_token():

    authority = (
        f"https://login.microsoftonline.com/{TENANT_ID}"
    )

    scopes = [
        "https://graph.microsoft.com/.default"
    ]

    app = msal.ConfidentialClientApplication(
        client_id=CLIENT_ID,
        authority=authority,
        client_credential=CLIENT_SECRET
    )

    result = app.acquire_token_for_client(
        scopes=scopes
    )

    if "access_token" not in result:

        raise RuntimeError(
            "Authentication failed: "
            + result.get("error_description", "Unknown error")
        )

    print("Microsoft Graph authentication successful.")

    return result["access_token"]
```

### Understand every part

**A. `authority`**

```python
authority = (
    f"https://login.microsoftonline.com/{TENANT_ID}"
)
```

This identifies the Microsoft Entra ID authentication endpoint for our organisation.

**B. `scopes`**

```python
scopes = [
    "https://graph.microsoft.com/.default"
]
```

This tells Microsoft Entra ID that we want a token for Microsoft Graph.

The `.default` scope requests the application permissions already configured and consented to for our application.

**C. `ConfidentialClientApplication`**

```python
app = msal.ConfidentialClientApplication(
    client_id=CLIENT_ID,
    authority=authority,
    client_credential=CLIENT_SECRET
)
```

This creates an MSAL confidential client application.

A confidential client is an application that can securely hold credentials, such as a secret or certificate.

The parameters are:

| Parameter | Meaning |
|---|---|
| `client_id` | Registered application ID |
| `authority` | Microsoft Entra authentication endpoint |
| `client_credential` | Client secret or another supported credential |

**D. `acquire_token_for_client()`**

```python
result = app.acquire_token_for_client(
    scopes=scopes
)
```

This asks MSAL to acquire an application access token.

MSAL checks its token cache and obtains a new token from Microsoft Entra ID when necessary.

**E. Check the authentication result**

```python
if "access_token" not in result:
```

The result is a Python dictionary.

If authentication succeeds, it contains an `access_token`.

If it fails, the result normally contains error information.

**F. Return the token**

```python
return result["access_token"]
```

This gives the token back to whichever part of our Python connector called the function.

## 12. What is the difference between MSAL and Microsoft Graph SDK?

This is a very important question.

They are two different libraries with different purposes.

| Library | What it does | Do we need it? |
|---|---|---|
| MSAL | Obtains authentication tokens | Yes, for our chosen authentication approach |
| Microsoft Graph SDK | Provides a higher-level Python interface for Graph API operations | No, not for our implementation |
| `requests` | Sends direct HTTP requests to Graph REST endpoints | Yes, we have chosen this approach |
| `boto3` | Communicates with AWS | Yes |

### What does the Microsoft Graph SDK do?

The Microsoft Graph SDK is a library that wraps Microsoft Graph API operations.

For example, instead of writing a REST request yourself, the SDK provides methods for accessing drives, items, users and other Graph resources.

It can reduce the amount of HTTP request code you need to write.

However, it also introduces SDK-specific classes, request builders, authentication-provider configuration and other abstractions.

### Why are we not using it?

Because we have chosen to learn and implement the connector using direct REST API calls.

We can write:

```python
response = requests.get(
    url,
    headers=headers,
    timeout=60
)
```

This directly sends a GET request to Microsoft Graph.

We control:

- The API URL.
- The HTTP method.
- The headers.
- The parameters.
- The response.
- The error handling.

We do not need the Graph SDK to do this.

### Do we still need MSAL?

Yes, in our selected implementation.

We are using MSAL for authentication and `requests` for API communication.

We are not using the Graph SDK.

**Our chosen combination is:**

```text
MSAL
  |
  | Generate access token
  v
Microsoft Graph REST API
  |
  | Access through requests
  v
SharePoint
```

There is no requirement to install `msgraph-sdk` just because we use Microsoft Graph.

The SDK is optional.

You can use MSAL with direct REST requests, exactly as we are doing.

# PART 5 — Recursive folder traversal

## 22. What is recursive folder traversal?

Imagine the document library looks like this:

```text
Documents
│
├── Finance
│   ├── invoices.pdf
│   └── budget.xlsx
│
├── HR
│   ├── policies.docx
│   └── employees.xlsx
│
└── IT
    ├── Systems
    │   └── architecture.pdf
    │
    └── security.docx
```

The endpoint:

```text
/drives/{drive_id}/root/children
```

only retrieves the immediate contents of the root folder.

It does not automatically enter each subfolder.

Recursive traversal means our Python function calls itself when it discovers a folder.

The process:

1. Open the root folder.
2. Retrieve its contents.
3. If the item is a folder, enter it.
4. If the item is a file, download it.
5. Repeat until all folders have been examined.

## 23. Recursive folder endpoint

To retrieve the contents of a particular folder:

```text
/drives/{drive_id}/items/{folder_id}/children
```

Python:

```python
url = (
    f"{GRAPH_BASE_URL}/drives/"
    f"{DRIVE_ID}/items/{folder_id}/children"
)
```

The `folder_id` identifies the folder we want to examine.

## 24. Recursive traversal function

```python
def traverse_folder(folder_id):

    url = (
        f"{GRAPH_BASE_URL}/drives/"
        f"{DRIVE_ID}/items/{folder_id}/children"
    )

    while url:

        response = get_with_retry(
            url,
            headers=graph_headers
        )

        data = response.json()

        for item in data.get("value", []):

            if "folder" in item:

                print("Entering folder:", item.get("name"))

                traverse_folder(item["id"])

            elif "file" in item:

                upload_to_s3(item)

        url = data.get("@odata.nextLink")
```

The important instruction is:

```python
traverse_folder(item["id"])
```

The function calls itself when it finds another folder.

This is recursion.

**Note:** We will include this as a separate full-scan option. Our main incremental synchronisation process will use Graph delta query, which can enumerate the drive hierarchy, including nested items, without manually walking each folder.

# PART 6 — Downloading SharePoint documents

## 25. Why do we need a separate download request?

Retrieving a document's metadata is not the same as downloading the document.

For example:

```python
item["name"]
```

only gives us the document name.

It does not give us the PDF, Excel or Word file content.

To download the actual file, we use:

```text
/drives/{drive_id}/items/{item_id}/content
```

Example:

```python
download_url = (
    f"{GRAPH_BASE_URL}/drives/"
    f"{DRIVE_ID}/items/{item_id}/content"
)
```

## 26. Understanding the download response

Microsoft Graph commonly returns an HTTP redirect to a temporary, preauthenticated download URL.

This means our code must:

1. Request the Graph `/content` endpoint using the Graph token.
2. Read the redirect's `Location` header.
3. Request the temporary download URL without sending the Graph token.
4. Receive the actual document bytes.

The temporary URL is already authorised and has a limited lifetime, so use it immediately.

Example:

```python
response = requests.get(
    download_url,
    headers=graph_headers,
    allow_redirects=False,
    timeout=60
)
```

The redirect can be:

```text
302 Found
```

The download address is in:

```python
response.headers["Location"]
```

Then:

```python
file_response = requests.get(
    response.headers["Location"],
    timeout=60
)
```

We do not send the Microsoft Graph Authorization header to that temporary download address.

Finally:

```python
file_content = file_response.content
```

This contains the actual file bytes.

# PART 8 — Incremental synchronisation

## 31. What is incremental synchronisation?

Imagine our SharePoint library contains 10,000 documents.

On the first run, we upload all 10,000 documents.

On the next run, only three changes occur:

- A new document is created.
- An existing document is modified.
- Another document is deleted.

We do not want to download all 10,000 documents again.

Incremental synchronisation retrieves only the changes since the previous synchronisation.

| SharePoint change | Connector action |
|---|---|
| New file | Upload to S3 |
| Modified file | Upload updated content to S3 |
| Deleted file | Delete corresponding S3 object |
| Unchanged file | Do nothing |

## 32. What is Microsoft Graph delta query?

Microsoft Graph provides a feature called delta query.

It tracks changes in a drive over time.

Our initial endpoint is:

```text
/drives/{drive_id}/root/delta
```

Python:

```python
initial_delta_url = (
    f"{GRAPH_BASE_URL}/drives/"
    f"{DRIVE_ID}/root/delta"
)
```

The first call begins enumerating the drive hierarchy.

Graph returns pages of items.

When all pages have been processed, the final response provides a URL called:

```text
@odata.deltaLink
```

We save this URL.

The next time the connector runs, we use the saved delta URL to retrieve changes.

## 33. Understanding nextLink and deltaLink

| Property | Meaning |
|---|---|
| `@odata.nextLink` | More pages remain in the current operation |
| `@odata.deltaLink` | Current operation is complete; use this URL for the next synchronisation |

Example:

```text
First run
   |
   v
Initial delta endpoint
   |
   v
Retrieve page 1
   |
   v
Retrieve page 2 using nextLink
   |
   v
Retrieve final page
   |
   v
Receive deltaLink
   |
   v
Save deltaLink in S3
```

Next run:

```text
Load saved deltaLink
   |
   v
Retrieve changes
   |
   v
Process changed items
   |
   v
Receive updated deltaLink
   |
   v
Save updated deltaLink
```

## 34. Where do we save the deltaLink?

We will save it in Amazon S3.

Example:

```text
connector-state/
    sharepoint/
        DRIVE123/
            delta.json
```

This is connector state, not a SharePoint document.

Example JSON:

```json
{
    "delta_link": "MICROSOFT_GRAPH_DELTA_URL",
    "updated_at": "2026-11-11T10:00:00+00:00"
}
```

This means we can restart the Python program without losing our synchronisation position.

# PART 9 — Retry and throttling handling

## 35. What is throttling?

Microsoft Graph can limit the number of requests our application makes.

If we send too many requests, Graph may return:

```text
429 Too Many Requests
```

This is called throttling.

It does not necessarily mean our code is incorrect.

It means we need to slow down.

## 36. What is Retry-After?

Microsoft Graph can return a response header:

```text
Retry-After: 10
```

This tells us to wait 10 seconds before trying again.

We should respect that instruction.

## 37. What is exponential backoff?

If a temporary error occurs and no `Retry-After` value is provided, we can increase the waiting time between retries.

For example:

```text
Attempt 1: Wait approximately 1 second
Attempt 2: Wait approximately 2 seconds
Attempt 3: Wait approximately 4 seconds
Attempt 4: Wait approximately 8 seconds
```

We can also add random delay, known as jitter.

This helps avoid multiple applications retrying at exactly the same time.

## 39. Complete code — copy the entire script

```python
import os
import json
import time
import random
import msal
import requests
import boto3

from datetime import datetime, timezone
from email.utils import parsedate_to_datetime
from botocore.exceptions import ClientError


# =====================================================
# 1. CONFIGURATION
# =====================================================

TENANT_ID = os.environ["MS_TENANT_ID"]

CLIENT_ID = os.environ["MS_CLIENT_ID"]

CLIENT_SECRET = os.environ["MS_CLIENT_SECRET"]

DRIVE_ID = "YOUR_DRIVE_ID"

S3_BUCKET = "your-company-document-bucket"

AWS_REGION = "eu-west-1"

MAX_ATTEMPTS = 6

GRAPH_BASE_URL = "https://graph.microsoft.com/v1.0"

DOCUMENT_PREFIX = (
    f"documents/sharepoint/{DRIVE_ID}/"
)

STATE_KEY = (
    f"connector-state/sharepoint/{DRIVE_ID}/delta.json"
)


# =====================================================
# 2. MSAL AUTHENTICATION
# =====================================================

def get_graph_access_token():

    authority = (
        f"https://login.microsoftonline.com/{TENANT_ID}"
    )

    scopes = [
        "https://graph.microsoft.com/.default"
    ]

    app = msal.ConfidentialClientApplication(
        client_id=CLIENT_ID,
        authority=authority,
        client_credential=CLIENT_SECRET
    )

    result = app.acquire_token_for_client(
        scopes=scopes
    )

    if "access_token" not in result:

        raise RuntimeError(
            "Authentication failed: "
            + result.get("error_description", "Unknown error")
        )

    print("Microsoft Graph authentication successful.")

    return result["access_token"]


# =====================================================
# 3. GENERATE ACCESS TOKEN AND HEADERS
# =====================================================

ACCESS_TOKEN = get_graph_access_token()

graph_headers = {
    "Authorization": f"Bearer {ACCESS_TOKEN}",
    "Accept": "application/json"
}


# =====================================================
# 4. CREATE CONNECTIONS
# =====================================================

session = requests.Session()

s3_client = boto3.client(
    "s3",
    region_name=AWS_REGION
)


# =====================================================
# 5. RETRY AND THROTTLING HANDLING
# =====================================================

def get_with_retry(
    url,
    headers=None,
    allow_redirects=True
):

    retryable_status_codes = [
        408, 429, 500, 502, 503, 504
    ]

    for attempt in range(1, MAX_ATTEMPTS + 1):

        try:

            response = session.get(
                url,
                headers=headers,
                timeout=60,
                allow_redirects=allow_redirects
            )

        except requests.RequestException:

            if attempt == MAX_ATTEMPTS:
                raise

            wait_seconds = min(
                60,
                (2 ** (attempt - 1)) + random.random()
            )

            print(
                f"Request failed. "
                f"Retrying in {wait_seconds:.1f} seconds."
            )

            time.sleep(wait_seconds)

            continue

        if response.status_code in retryable_status_codes:

            if attempt == MAX_ATTEMPTS:

                response.raise_for_status()

            retry_after = response.headers.get(
                "Retry-After"
            )

            if retry_after:

                try:

                    wait_seconds = float(retry_after)

                except ValueError:

                    retry_date = parsedate_to_datetime(
                        retry_after
                    )

                    if retry_date.tzinfo is None:

                        retry_date = retry_date.replace(
                            tzinfo=timezone.utc
                        )

                    wait_seconds = max(
                        0,
                        (
                            retry_date -
                            datetime.now(timezone.utc)
                        ).total_seconds()
                    )

            else:

                wait_seconds = min(
                    60,
                    (2 ** (attempt - 1)) + random.random()
                )

            print(
                f"Temporary HTTP error "
                f"{response.status_code}. "
                f"Retrying in {wait_seconds:.1f} seconds."
            )

            time.sleep(wait_seconds)

            continue

        response.raise_for_status()

        return response

    raise RuntimeError(
        "Maximum request attempts reached."
    )


# =====================================================
# 6. DOWNLOAD A SHAREPOINT FILE
# =====================================================

def download_file(item_id):

    download_url = (
        f"{GRAPH_BASE_URL}/drives/"
        f"{DRIVE_ID}/items/{item_id}/content"
    )

    # Request the Graph content endpoint.
    # Do not automatically follow its redirect.

    response = get_with_retry(
        download_url,
        headers=graph_headers,
        allow_redirects=False
    )

    # Graph commonly returns a 302 redirect.

    if response.status_code in [
        301, 302, 303, 307, 308
    ]:

        download_location = response.headers.get(
            "Location"
        )

        if not download_location:

            raise RuntimeError(
                "Graph returned a redirect without a Location header."
            )

        # This URL is preauthenticated.
        # Do not send the Graph access token to it.

        file_response = get_with_retry(
            download_location,
            headers=None
        )

    else:

        file_response = response

    return file_response.content


# =====================================================
# 7. UPLOAD A FILE TO AMAZON S3
# =====================================================

def upload_to_s3(item):

    item_id = item["id"]

    filename = item.get(
        "name",
        "unnamed_file"
    )

    mime_type = item.get(
        "file", {}
    ).get(
        "mimeType",
        "application/octet-stream"
    )

    print(f"Downloading: {filename}")

    file_content = download_file(item_id)

    # Stable key based on SharePoint item ID.

    s3_key = (
        f"{DOCUMENT_PREFIX}{item_id}"
    )

    s3_client.put_object(
        Bucket=S3_BUCKET,
        Key=s3_key,
        Body=file_content,
        ContentType=mime_type,
        Metadata={
            "sharepoint-item-id": item_id,
            "sharepoint-drive-id": DRIVE_ID,
            "sharepoint-name": filename
        }
    )

    print(f"Uploaded to S3: {s3_key}")


# =====================================================
# 8. RECURSIVE FOLDER TRAVERSAL
# =====================================================

def traverse_folder(folder_id):

    url = (
        f"{GRAPH_BASE_URL}/drives/"
        f"{DRIVE_ID}/items/{folder_id}/children"
    )

    while url:

        response = get_with_retry(
            url,
            headers=graph_headers
        )

        data = response.json()

        for item in data.get("value", []):

            if "folder" in item:

                folder_name = item.get("name")

                print(
                    f"Entering folder: {folder_name}"
                )

                # Function calls itself
                # to enter nested folders.

                traverse_folder(item["id"])

            elif "file" in item:

                upload_to_s3(item)

        # Process additional pages.

        url = data.get("@odata.nextLink")


# =====================================================
# 9. OPTIONAL FULL RECURSIVE SCAN
# =====================================================

def full_recursive_sync():

    print("Starting full recursive scan.")

    traverse_folder("root")

    print("Full recursive scan completed.")


# =====================================================
# 10. LOAD DELTA LINK FROM S3
# =====================================================

def load_delta_link():

    try:

        response = s3_client.get_object(
            Bucket=S3_BUCKET,
            Key=STATE_KEY
        )

        state_data = json.loads(
            response["Body"].read().decode("utf-8")
        )

        return state_data.get("delta_link")

    except ClientError as error:

        error_code = error.response.get(
            "Error", {}
        ).get("Code")

        if error_code in [
            "NoSuchKey",
            "404",
            "NotFound"
        ]:

            print(
                "No previous delta state found."
            )

            return None

        raise


# =====================================================
# 11. SAVE DELTA LINK TO S3
# =====================================================

def save_delta_link(delta_link):

    state_data = {
        "delta_link": delta_link,
        "updated_at": datetime.now(
            timezone.utc
        ).isoformat()
    }

    s3_client.put_object(
        Bucket=S3_BUCKET,
        Key=STATE_KEY,
        Body=json.dumps(
            state_data
        ).encode("utf-8"),
        ContentType="application/json"
    )

    print(
        "Delta tracking state saved to S3."
    )


# =====================================================
# 12. PROCESS EACH DELTA ITEM
# =====================================================

def process_delta_item(item):

    item_id = item.get("id")

    if not item_id:
        return

    s3_key = (
        f"{DOCUMENT_PREFIX}{item_id}"
    )

    # Check for deleted items.

    if "deleted" in item:

        if "folder" in item:

            print(
                f"Deleted folder detected: "
                f"{item.get('name', item_id)}"
            )

            print(
                "Folder descendants need separate "
                "cleanup tracking."
            )

            return

        print(
            f"Deleting S3 object: "
            f"{item.get('name', item_id)}"
        )

        s3_client.delete_object(
            Bucket=S3_BUCKET,
            Key=s3_key
        )

        return

    # Folder metadata is not uploaded as a document.

    if "folder" in item:
        return

    # Upload new or modified documents.

    if "file" in item:

        upload_to_s3(item)


# =====================================================
# 13. INCREMENTAL SYNCHRONISATION
# =====================================================

def run_delta_sync(start_url):

    url = start_url

    latest_delta_link = None

    while url:

        print(
            "Checking SharePoint changes..."
        )

        response = get_with_retry(
            url,
            headers=graph_headers
        )

        data = response.json()

        for item in data.get("value", []):

            process_delta_item(item)

        if "@odata.nextLink" in data:

            url = data["@odata.nextLink"]

        else:

            latest_delta_link = data.get(
                "@odata.deltaLink"
            )

            url = None

    if not latest_delta_link:

        raise RuntimeError(
            "Microsoft Graph did not return a deltaLink."
        )

    # Save only after all pages have been processed.

    save_delta_link(latest_delta_link)

    print(
        "Incremental synchronisation completed."
    )


# =====================================================
# 14. MAIN CONNECTOR
# =====================================================

def main():

    print(
        "SharePoint-to-S3 connector started."
    )

    initial_delta_url = (
        f"{GRAPH_BASE_URL}/drives/"
        f"{DRIVE_ID}/root/delta"
    )

    delta_link = load_delta_link()

    if delta_link:

        print(
            "Previous synchronisation found."
        )

        try:

            run_delta_sync(delta_link)

        except requests.HTTPError as error:

            if (
                error.response is not None
                and error.response.status_code == 410
            ):

                print(
                    "Delta token expired. "
                    "Starting a fresh initial synchronisation."
                )

                run_delta_sync(
                    initial_delta_url
                )

            else:

                raise

    else:

        print(
            "First synchronisation detected."
        )

        run_delta_sync(
            initial_delta_url
        )

    print(
        "Connector finished successfully."
    )


# =====================================================
# 15. RUN CONNECTOR
# =====================================================

if __name__ == "__main__":

    main()
```

Purpose: Control the entire connector.

It checks whether a previous delta URL exists.

If it exists, it performs incremental synchronisation.

It also detects an expired delta token returned as HTTP 410 and starts a fresh initial enumeration.

# PART 14 — Important enterprise considerations

## 46. What is not yet fully production-ready?

The script demonstrates the complete architecture, but there are additional improvements required before using it as a high-volume enterprise service.

| Area | Further improvement |
|---|---|
| Authentication | Prefer certificate or managed credential solutions over long-lived client secrets |
| Token lifecycle | Handle token renewal if a long-running job receives HTTP 401 |
| Large documents | Stream data and use managed multipart uploads rather than loading entire files into memory |
| Deleted folders | Maintain a folder-to-file manifest to clean up descendants reliably |
| Delta recovery | Handle expired delta tokens and recover safely |
| Concurrent runs | Prevent multiple instances from changing the same delta state simultaneously |
| Monitoring | Record file counts, failures, retries and run durations |
| Security | Preserve or separately implement SharePoint access-control requirements |
| Recovery | Use durable processing records for stronger failure recovery |

### Important: SharePoint permissions

Uploading a document to S3 does not automatically preserve its SharePoint permissions.

If a document is restricted to the Finance team in SharePoint, it does not automatically become restricted to that team in S3.

You need a separate permission and access-control design if the documents must retain their original security rules.

### Important: Large files

Our example uses:

```python
file_content = file_response.content
```

This loads the entire document into Python memory.

That is suitable for learning and smaller documents.

For very large files, use streaming and a managed multipart upload approach.

### Important: Deleted folders

Our example handles deleted file records.

Deleted folders require extra care because S3 does not have real directory objects in the same way as a filesystem.

Maintain a mapping between SharePoint folders and their document IDs so that you can reliably remove all affected S3 objects.

# Final understanding

The most important distinction in this whole project is:

**MSAL is not Microsoft Graph. Microsoft Graph is not the Graph SDK.**

Our implementation uses:

- MSAL to obtain an access token.
- Microsoft Graph REST API to access SharePoint.
- Requests to send the Graph API calls.
- Boto3 to upload the files to Amazon S3.

We do not need `msgraph-sdk` for this implementation.

We are deliberately using direct REST API requests because they let us understand and control exactly how our connector communicates with SharePoint.

This gives us the complete source connector architecture:

**Microsoft Entra ID → MSAL → Microsoft Graph REST API → Python requests → SharePoint → Python boto3 → Amazon S3.**
