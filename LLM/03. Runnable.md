# LangChain LCEL and Runnable Components — Complete Practical Guide

## 1. What is LCEL?

### What is LCEL?

**LCEL stands for LangChain Expression Language.**

It is a declarative way to connect different LangChain components into a single pipeline.

For example, you might want to:

1. Receive a user's question.
2. Format the question into a prompt.
3. Send the prompt to an OpenAI model.
4. Parse the model's response.
5. Return the final answer.

Without LCEL, you would manually call each component and pass the output to the next component.

With LCEL, you can write:

```python
chain = prompt | model | parser
```

This is an LCEL pipeline.

### Why do we need LCEL?

Imagine building an application that uses an LLM.

You may need to combine:

- Prompt templates
- Chat models
- Output parsers
- Python functions
- Conditional logic
- Parallel processing
- External APIs
- Retrieval systems

LCEL gives these components a common interface so that they can be combined consistently.

### Benefits of LCEL

| Benefit | Explanation |
|---|---|
| Reusability | Build a pipeline once and invoke it multiple times |
| Readability | Express workflows using simple composition |
| Streaming | Stream intermediate or final output where supported |
| Async support | Run chains asynchronously |
| Batch processing | Process multiple inputs efficiently |
| Parallel execution | Execute independent tasks concurrently |
| Configuration | Pass metadata, tags, callbacks, and execution settings |
| Composition | Combine simple components into complex pipelines |

**Important:** LCEL is not an LLM or a model. It is a way of composing components that implement the Runnable interface.

## 2. What is the Runnable interface?

### What is a Runnable?

A `Runnable` is a standard LangChain interface representing one unit of work.

A Runnable accepts an input, performs an operation, and produces an output.

For example:

```text
Input
  |
  v
Runnable
  |
  v
Output
```

A prompt template, ChatOpenAI model, output parser, or custom Python function can be used as a Runnable.

### Why do we need the Runnable interface?

Consider these different components:

```python
prompt = ChatPromptTemplate.from_template(
    "Explain {topic}"
)

model = ChatOpenAI()

parser = StrOutputParser()
```

Each component performs a different job.

The Runnable interface gives them a consistent way to execute and compose their work.

### Important Runnable methods

| Method | What it does | Example |
|---|---|---|
| `invoke()` | Executes one input synchronously | `chain.invoke(input)` |
| `ainvoke()` | Executes one input asynchronously | `await chain.ainvoke(input)` |
| `batch()` | Processes multiple inputs | `chain.batch(inputs)` |
| `abatch()` | Processes multiple inputs asynchronously | `await chain.abatch(inputs)` |
| `stream()` | Streams output chunks | `chain.stream(input)` |
| `astream()` | Streams asynchronously | `async for x in chain.astream(input)` |
| `astream_log()` | Streams execution logs and intermediate information | `chain.astream_log(input)` |
| `with_config()` | Returns a Runnable with configuration applied | `chain.with_config(...)` |
| `with_retry()` | Adds retry behavior | `chain.with_retry(...)` |
| `with_fallbacks()` | Adds fallback Runnables | `chain.with_fallbacks(...)` |
| `get_input_schema()` | Gets the input schema | `chain.get_input_schema()` |
| `get_output_schema()` | Gets the output schema | `chain.get_output_schema()` |
| `get_graph()` | Gets the execution graph | `chain.get_graph()` |

The exact behavior of streaming and batching depends on the individual components.

### Example: Basic Runnable

```python
from langchain_core.runnables import RunnableLambda

def add_ten(number):
    return number + 10

runnable = RunnableLambda(add_ten)

result = runnable.invoke(5)

print(result)
```

**Output:**

```text
15
```

Here:

- Input: `5`
- Function: `add_ten()`
- Output: `15`

The Python function has been wrapped inside a Runnable.

## 3. Pipe operator `|`

### What is the pipe operator?

The pipe operator `|` connects two Runnables.

The output of the first Runnable becomes the input of the second Runnable.

```python
runnable1 | runnable2
```

### Why do we use it?

It makes pipelines readable and avoids manually passing outputs between components.

Without LCEL:

```python
formatted_prompt = prompt.invoke(
    {"topic": "Artificial Intelligence"}
)

model_response = model.invoke(formatted_prompt)

final_answer = parser.invoke(model_response)
```

With LCEL:

```python
chain = prompt | model | parser

final_answer = chain.invoke(
    {"topic": "Artificial Intelligence"}
)
```

### Complete example without an API call

```python
from langchain_core.runnables import RunnableLambda

def multiply_by_two(number):
    return number * 2

def add_five(number):
    return number + 5

chain = (
    RunnableLambda(multiply_by_two)
    | RunnableLambda(add_five)
)

result = chain.invoke(10)

print(result)
```

**Output:**

```text
25
```

Execution:

```text
Input: 10
   |
   v
multiply_by_two(10)
   |
   v
20
   |
   v
add_five(20)
   |
   v
25
```

### Important point

The pipe operator generally creates a `RunnableSequence`.

Therefore:

```python
chain = runnable1 | runnable2 | runnable3
```

is equivalent to composing the three Runnables sequentially.

## 4. RunnableSequence

### What is RunnableSequence?

`RunnableSequence` executes multiple Runnables one after another.

The output of one step becomes the input of the next step.

```text
Runnable 1
    |
    v
Runnable 2
    |
    v
Runnable 3
    |
    v
Final output
```

### Why do we need it?

Use `RunnableSequence` when your application has multiple dependent steps.

For example:

1. Convert text to lowercase.
2. Remove unnecessary spaces.
3. Count the words.
4. Generate a result.

### Example

```python
from langchain_core.runnables import (
    RunnableLambda,
    RunnableSequence
)

def convert_to_lowercase(text):
    return text.lower()

def remove_spaces(text):
    return text.strip()

def count_words(text):
    return len(text.split())

step1 = RunnableLambda(convert_to_lowercase)
step2 = RunnableLambda(remove_spaces)
step3 = RunnableLambda(count_words)

chain = RunnableSequence(
    first=step1,
    middle=[step2],
    last=step3
)

result = chain.invoke("  HELLO LANGCHAIN WORLD  ")

print(result)
```

**Output:**

```text
3
```

### RunnableSequence parameters

| Parameter | Explanation |
|---|---|
| `first` | First Runnable in the sequence |
| `middle` | List of intermediate Runnables |
| `last` | Final Runnable |

You can also create the same sequence using the pipe operator:

```python
chain = step1 | step2 | step3
```

This is generally the simpler and more readable approach.

### Important attributes

| Attribute | Explanation |
|---|---|
| `first` | First Runnable |
| `middle` | Intermediate Runnables |
| `last` | Final Runnable |
| `steps` | Ordered collection of all steps |

## 5. RunnableParallel

### What is RunnableParallel?

`RunnableParallel` executes multiple Runnables concurrently using the same input.

It returns a dictionary containing the output of each Runnable.

### Why do we need it?

Suppose a user submits a product description.

You want to:

- Summarize the description.
- Extract keywords.
- Count the words.

These operations are independent. They do not need to wait for one another.

Instead of executing them sequentially, you can execute them in parallel.

### Example

```python
from langchain_core.runnables import (
    RunnableLambda,
    RunnableParallel
)

def summarize(text):
    return text[:30]

def count_words(text):
    return len(text.split())

def extract_keywords(text):
    return [
        word.strip(".,!?")
        for word in text.split()
        if len(word.strip(".,!?")) > 4
    ]

parallel_chain = RunnableParallel(
    summary=RunnableLambda(summarize),
    word_count=RunnableLambda(count_words),
    keywords=RunnableLambda(extract_keywords)
)

result = parallel_chain.invoke(
    "LangChain makes it easier to build applications using large language models."
)

print(result)
```

**Output:**

```python
{
    'summary': 'LangChain makes it easier to',
    'word_count': 12,
    'keywords': [
        'LangChain',
        'easier',
        'applications',
        'using',
        'large',
        'language',
        'models'
    ]
}
```

### How does it work?

```text
                  Input
                    |
                    v
             RunnableParallel
              /      |      \
             /       |       \
            v        v        v
        Summary   Word Count  Keywords
            \       |       /
             \      |      /
                    v
             Combined Dictionary
```

### Parameters

The constructor accepts a mapping of names to Runnables.

```python
RunnableParallel(
    summary=summary_chain,
    keywords=keyword_chain
)
```

You can also pass a dictionary:

```python
RunnableParallel({
    "summary": summary_chain,
    "keywords": keyword_chain
})
```

### Important point

`RunnableParallel` sends the same input to each branch.

It is different from `RunnableSequence`:

| RunnableSequence | RunnableParallel |
|---|---|
| Runs steps sequentially | Runs branches concurrently |
| Output of one step feeds the next | Same input goes to every branch |
| Useful for dependent tasks | Useful for independent tasks |
| Produces the last step's output | Produces a dictionary of outputs |

## 6. RunnablePassthrough

### What is RunnablePassthrough?

`RunnablePassthrough` passes the input through unchanged.

In simple terms, it returns whatever it receives.

```python
from langchain_core.runnables import RunnablePassthrough

chain = RunnablePassthrough()

result = chain.invoke("Hello LangChain")

print(result)
```

**Output:**

```text
Hello LangChain
```

### Why do we need it?

Suppose you are building an LLM pipeline.

You want to:

1. Preserve the original user question.
2. Generate an answer using an LLM.
3. Return both the original question and the answer.

`RunnablePassthrough` helps preserve the original input.

### Example

```python
from langchain_core.runnables import (
    RunnableLambda,
    RunnableParallel,
    RunnablePassthrough
)

def generate_answer(question):
    return f"Answer generated for: {question}"

chain = RunnableParallel(
    original_question=RunnablePassthrough(),
    answer=RunnableLambda(generate_answer)
)

result = chain.invoke("What is Python?")

print(result)
```

**Output:**

```python
{
    'original_question': 'What is Python?',
    'answer': 'Answer generated for: What is Python?'
}
```

### RunnablePassthrough.assign()

One of its most useful features is `assign()`.

It allows you to preserve an existing dictionary and add new fields.

Example:

```python
from langchain_core.runnables import (
    RunnableLambda,
    RunnablePassthrough
)

chain = RunnablePassthrough.assign(
    word_count=RunnableLambda(
        lambda data: len(data["text"].split())
    )
)

result = chain.invoke({
    "text": "LangChain is useful for LLM applications",
    "language": "English"
})

print(result)
```

**Output:**

```python
{
    'text': 'LangChain is useful for LLM applications',
    'language': 'English',
    'word_count': 7
}
```

Notice that the original dictionary fields are preserved.

The new `word_count` field is added.

## 7. RunnableLambda

### What is RunnableLambda?

`RunnableLambda` converts an ordinary Python function into a Runnable.

This allows you to use your own Python logic inside an LCEL pipeline.

### Why do we need it?

Not every task requires an LLM.

You might need to:

- Clean text.
- Validate input.
- Calculate a value.
- Transform JSON.
- Call a Python utility function.
- Prepare information before sending it to an LLM.

`RunnableLambda` makes these functions composable with other LangChain components.

### Example

```python
from langchain_core.runnables import RunnableLambda

def clean_text(text):
    return text.strip().lower()

cleaning_runnable = RunnableLambda(clean_text)

result = cleaning_runnable.invoke(
    "  HELLO LANGCHAIN  "
)

print(result)
```

**Output:**

```text
hello langchain
```

### Example: RunnableLambda inside a pipeline

```python
from langchain_core.runnables import RunnableLambda

def convert_to_uppercase(text):
    return text.upper()

def add_prefix(text):
    return "RESULT: " + text

chain = (
    RunnableLambda(convert_to_uppercase)
    | RunnableLambda(add_prefix)
)

result = chain.invoke("langchain")

print(result)
```

**Output:**

```text
RESULT: LANGCHAIN
```

### RunnableLambda parameters

| Parameter | Explanation |
|---|---|
| `func` | Synchronous Python function |
| `afunc` | Optional asynchronous Python function |
| `name` | Optional Runnable name, depending on the installed version |
| `input_type` | Optional input type information |

The most common usage is:

```python
RunnableLambda(my_function)
```

### Using an asynchronous function

```python
from langchain_core.runnables import RunnableLambda

async def async_greeting(name):
    return f"Hello {name}"

runnable = RunnableLambda(async_greeting)

result = await runnable.ainvoke("John")

print(result)
```

**Output:**

```text
Hello John
```

### Important point

Use `RunnableLambda` for ordinary transformations.

If you need to write custom logic that itself streams chunks, look at `RunnableGenerator` instead.

## 8. RunnableBranch

### What is RunnableBranch?

`RunnableBranch` provides conditional execution.

It checks conditions and executes the first matching branch.

If none of the conditions match, it executes the default branch.

Think of it as an `if / elif / else` statement inside an LCEL pipeline.

### Why do we need it?

Suppose you are building a customer support chatbot.

You want:

- Billing questions to go to billing logic.
- Technical questions to go to technical support.
- Other questions to go to general support.

`RunnableBranch` lets you route inputs based on conditions.

### Example

```python
from langchain_core.runnables import (
    RunnableBranch,
    RunnableLambda
)

def billing_response(question):
    return "Please contact the billing department."

def technical_response(question):
    return "Please contact technical support."

def general_response(question):
    return "How can I help you?"

branch = RunnableBranch(
    (
        lambda x: "payment" in x.lower(),
        RunnableLambda(billing_response)
    ),
    (
        lambda x: "error" in x.lower(),
        RunnableLambda(technical_response)
    ),
    RunnableLambda(general_response)
)

print(branch.invoke("I have a payment problem"))
print(branch.invoke("I am getting an error"))
print(branch.invoke("I have a question"))
```

**Output:**

```text
Please contact the billing department.
Please contact technical support.
How can I help you?
```

### RunnableBranch structure

```python
RunnableBranch(
    (condition_1, runnable_1),
    (condition_2, runnable_2),
    default_runnable
)
```

### Parameters

| Parameter | Explanation |
|---|---|
| Branch conditions | Functions that return `True` or `False` |
| Branch Runnables | Runnables executed when their conditions match |
| Default Runnable | Executed when no condition matches |

### Important point

Conditions are evaluated in order.

The first matching branch is selected. Later branches are not evaluated.

## 9. RunnableAssign

### What is RunnableAssign?

`RunnableAssign` adds new fields to an input dictionary.

It uses a `RunnableParallel` mapper to calculate additional values and combines those values with the original dictionary.

### Why do we need it?

Suppose you receive:

```python
{
    "name": "John",
    "age": 25
}
```

You want to add:

- A greeting.
- Whether the person is an adult.
- A category based on age.

Instead of manually rebuilding the dictionary, you can use `RunnableAssign`.

### Example

```python
from langchain_core.runnables import (
    RunnableLambda,
    RunnableParallel
)

from langchain_core.runnables.passthrough import RunnableAssign

mapper = RunnableParallel(
    greeting=RunnableLambda(
        lambda data: f"Hello {data['name']}"
    ),
    is_adult=RunnableLambda(
        lambda data: data["age"] >= 18
    )
)

assign_chain = RunnableAssign(mapper)

result = assign_chain.invoke({
    "name": "John",
    "age": 25
})

print(result)
```

**Output:**

```python
{
    'name': 'John',
    'age': 25,
    'greeting': 'Hello John',
    'is_adult': True
}
```

### Easier alternative: RunnablePassthrough.assign()

In normal application development, you will frequently see:

```python
RunnablePassthrough.assign(...)
```

Example:

```python
from langchain_core.runnables import (
    RunnableLambda,
    RunnablePassthrough
)

chain = RunnablePassthrough.assign(
    greeting=lambda data: f"Hello {data['name']}"
)

result = chain.invoke({
    "name": "John"
})

print(result)
```

**Output:**

```python
{
    'name': 'John',
    'greeting': 'Hello John'
}
```

### RunnableAssign vs RunnablePassthrough.assign()

| RunnableAssign | RunnablePassthrough.assign() |
|---|---|
| Explicit class | Convenient class method |
| Accepts a `RunnableParallel` mapper | Accepts keyword Runnables |
| Adds calculated fields | Adds calculated fields |
| Useful when you need to construct the mapper explicitly | Usually simpler for everyday use |

**Important:** The input to `RunnableAssign` must be a dictionary-like mapping.

## 10. RunnableBinding

### What is RunnableBinding?

`RunnableBinding` wraps another Runnable and binds additional arguments or configuration to it.

You can think of it as a configured version of an existing Runnable.

### Why do we need it?

Suppose you have a ChatOpenAI model.

You want to attach specific model arguments, such as:

- Stop sequences.
- Tool definitions.
- Other invocation-specific model options.

You can bind these arguments to the model so they are used whenever the bound Runnable executes.

### Example using ChatOpenAI

```python
from langchain_openai import ChatOpenAI

model = ChatOpenAI(
    model="gpt-4.1-mini",
    temperature=0
)

bound_model = model.bind(
    stop=["END"]
)

response = bound_model.invoke(
    "Write a short sentence about Python. Then write END and nothing else."
)

print(response.content)
```

**Illustrative output:**

```text
Python is a versatile programming language.
```

The stop sequence tells the model integration to stop generation when the specified sequence is encountered, where supported by the model/API.

### What is happening internally?

```text
Original Model
      |
      v
model.bind(...)
      |
      v
Bound Runnable
      |
      v
invoke(...)
```

### Important methods

| Method | Explanation |
|---|---|
| `bind()` | Binds additional invocation arguments |
| `bind_tools()` | Binds tools to a compatible chat model |
| `with_config()` | Applies Runnable configuration |
| `with_retry()` | Adds retry behavior |
| `with_fallbacks()` | Adds fallback Runnables |

### Important point

In everyday code, you normally use:

```python
bound_model = model.bind(...)
```

You rarely need to instantiate `RunnableBinding` directly.

`RunnableBinding` is the underlying wrapper used to represent a Runnable with bound arguments or configuration.

## 11. Runnable configuration

### What is Runnable configuration?

Runnable configuration controls how a Runnable executes.

It is separate from the actual business input.

For example, suppose your chain receives:

```python
{"topic": "Python"}
```

You can additionally provide configuration such as:

- Tags
- Metadata
- Callback handlers
- Maximum concurrency
- Recursion limit
- Run name

### Why do we need configuration?

Configuration is useful for:

- Debugging.
- Monitoring.
- Tracing.
- Organizing LangSmith runs.
- Controlling batch concurrency.
- Setting execution limits.
- Passing execution metadata.

### Common configuration options

| Configuration | Purpose |
|---|---|
| `tags` | Labels attached to a Runnable execution |
| `metadata` | Additional information attached to a run |
| `callbacks` | Callback handlers for observing execution |
| `run_name` | Name used to identify a run |
| `max_concurrency` | Maximum concurrent executions for batch operations |
| `recursion_limit` | Maximum allowed recursive execution depth |
| `configurable` | Runtime values for configurable Runnable fields |
| `run_id` | Identifier for a run, when supplied |

Not every option affects every Runnable in the same way.

### Example: Using tags and metadata

```python
from langchain_core.runnables import RunnableLambda

def greet(name):
    return f"Hello {name}"

chain = RunnableLambda(greet)

result = chain.invoke(
    "John",
    config={
        "run_name": "GreetingChain",
        "tags": ["demo", "greeting"],
        "metadata": {
            "user_id": "123",
            "environment": "development"
        }
    }
)

print(result)
```

**Output:**

```text
Hello John
```

The configuration is execution metadata. It does not automatically change the returned greeting.

### Example: Maximum concurrency

```python
from langchain_core.runnables import RunnableLambda

def double(number):
    return number * 2

chain = RunnableLambda(double)

results = chain.batch(
    [1, 2, 3, 4, 5],
    config={
        "max_concurrency": 2
    }
)

print(results)
```

**Output:**

```python
[2, 4, 6, 8, 10]
```

Here, `max_concurrency=2` limits the number of concurrent batch executions.

### Configuring model values at runtime

LangChain also provides `configurable_fields()` and `configurable_alternatives()` for certain Runnables.

These are different from ordinary execution metadata.

#### configurable_fields()

Use this when you want to expose a particular model field for runtime configuration.

Example:

```python
from langchain_openai import ChatOpenAI
from langchain_core.runnables import ConfigurableField

model = ChatOpenAI(
    model="gpt-4.1-mini",
    temperature=0
).configurable_fields(
    temperature=ConfigurableField(
        id="llm_temperature",
        name="Temperature",
        description="Controls response randomness"
    )
)

response = model.with_config(
    configurable={
        "llm_temperature": 0.7
    }
).invoke("Explain Python in one sentence.")

print(response.content)
```

**Output:** A model-generated explanation of Python. The exact wording can vary.

#### configurable_alternatives()

Use this when you want to switch between alternative Runnables at runtime.

Conceptual example:

```python
from langchain_openai import ChatOpenAI
from langchain_core.runnables import ConfigurableField

model = ChatOpenAI(
    model="gpt-4.1-mini"
).configurable_alternatives(
    ConfigurableField(id="model"),
    default_key="mini",
    standard=ChatOpenAI(model="gpt-4.1")
)

response = model.with_config(
    configurable={
        "model": "standard"
    }
).invoke("Explain LCEL.")
```

The selected alternative is used for that invocation.

**Note:** Model availability and supported parameters depend on the model and integration version. Some models do not support every parameter, such as temperature.

## 12. Composing complex pipelines

Now let's combine the Runnable components into a more realistic application.

### Scenario: Product review analyzer

Imagine that a user provides a product review.

You want your application to:

1. Receive the review.
2. Clean the text.
3. Count the words.
4. Extract a short preview.
5. Classify the review as positive or negative.
6. Route it to the appropriate response.
7. Return the original review and all calculated results.

We can build this using:

- `RunnableLambda`
- `RunnablePassthrough`
- `RunnableParallel`
- `RunnableAssign`
- `RunnableBranch`
- `RunnableSequence`

### Complete code

This example uses deterministic Python functions, so you can run it without an OpenAI API key.

```python
from langchain_core.runnables import (
    RunnableLambda,
    RunnableParallel,
    RunnablePassthrough,
    RunnableBranch
)

# ---------------------------------
# STEP 1: Clean the review
# ---------------------------------

def clean_review(data):
    return {
        **data,
        "cleaned_review": data["review"].strip().lower()
    }


cleaning_chain = RunnableLambda(clean_review)


# ---------------------------------
# STEP 2: Analyze the review
# ---------------------------------

def count_words(data):
    return len(data["cleaned_review"].split())


def create_preview(data):
    return data["cleaned_review"][:40]


def classify_review(data):
    positive_words = [
        "good", "great", "excellent", "amazing",
        "love", "helpful"
    ]

    negative_words = [
        "bad", "poor", "terrible", "slow",
        "broken", "hate"
    ]

    text = data["cleaned_review"]

    positive_count = sum(
        word in text for word in positive_words
    )

    negative_count = sum(
        word in text for word in negative_words
    )

    if positive_count > negative_count:
        return "positive"

    if negative_count > positive_count:
        return "negative"

    return "neutral"


analysis_chain = RunnableParallel(
    word_count=RunnableLambda(count_words),
    preview=RunnableLambda(create_preview),
    sentiment=RunnableLambda(classify_review)
)


# ---------------------------------
# STEP 3: Combine original and analysis
# ---------------------------------

full_analysis_chain = (
    cleaning_chain
    | RunnablePassthrough.assign(
        analysis=analysis_chain
    )
)


# ---------------------------------
# STEP 4: Route based on sentiment
# ---------------------------------

def positive_response(data):
    return "Thank you! We are glad you enjoyed the product."


def negative_response(data):
    return "We are sorry about your experience. Please contact support."


def neutral_response(data):
    return "Thank you for sharing your feedback."


routing_chain = RunnableBranch(
    (
        lambda data: (
            data["analysis"]["sentiment"] == "positive"
        ),
        RunnableLambda(positive_response)
    ),
    (
        lambda data: (
            data["analysis"]["sentiment"] == "negative"
        ),
        RunnableLambda(negative_response)
    ),
    RunnableLambda(neutral_response)
)


# ---------------------------------
# STEP 5: Build the complete pipeline
# ---------------------------------

final_chain = (
    full_analysis_chain
    | RunnablePassthrough.assign(
        response=routing_chain
    )
)


# ---------------------------------
# STEP 6: Execute the pipeline
# ---------------------------------

result = final_chain.invoke({
    "review": "  This product is excellent and amazing. I love it!  ",
    "product": "Laptop"
})


# ---------------------------------
# STEP 7: Display the result
# ---------------------------------

print(result)
```

### Expected output

```python
{
    'review': '  This product is excellent and amazing. I love it!  ',
    'product': 'Laptop',

    'cleaned_review': 'this product is excellent and amazing. i love it!',

    'analysis': {
        'word_count': 9,
        'preview': 'this product is excellent and amazing.',
        'sentiment': 'positive'
    },

    'response': 'Thank you! We are glad you enjoyed the product.'
}
```

### Understand the execution flow

```text
              User Review
                   |
                   v
            RunnableLambda
              Clean Text
                   |
                   v
         RunnablePassthrough
                assign
                   |
                   v
           RunnableParallel
            /      |      \
           /       |       \
          v        v        v
      Word Count Preview Sentiment
           \       |       /
            \      |      /
                   v
            Analysis Dictionary
                   |
                   v
            RunnableBranch
             /     |      \
            /      |       \
        Positive Negative Neutral
            \      |       /
             \     |      /
                   v
            Response Message
                   |
                   v
           Final Dictionary
```

This example demonstrates how individual Runnables can be composed into a larger workflow.

In a real application, you could replace `classify_review()` with an LLM call and replace the response functions with model-generated customer support responses.

## 13. Real-world LCEL pipeline using ChatOpenAI

Now let's connect LCEL with the `ChatOpenAI` integration you studied earlier.

### What are we building?

A simple text-analysis application that:

1. Accepts a topic.
2. Formats a prompt.
3. Sends the prompt to OpenAI.
4. Parses the model response into a string.

### Installation

```bash
pip install -U langchain langchain-openai
```

Set your API key:

```bash
export OPENAI_API_KEY="your-api-key"
```

For Windows PowerShell:

```powershell
$env:OPENAI_API_KEY="your-api-key"
```

### Complete code

```python
from langchain_openai import ChatOpenAI

from langchain_core.prompts import (
    ChatPromptTemplate
)

from langchain_core.output_parsers import (
    StrOutputParser
)

from langchain_core.runnables import (
    RunnableLambda,
    RunnableParallel,
    RunnablePassthrough
)


# STEP 1: Create the prompt

prompt = ChatPromptTemplate.from_template(
    """
    Explain the following topic in simple language.

    Topic: {topic}

    Include:
    1. What it is
    2. Why it is used
    3. One example
    """
)


# STEP 2: Create the model

model = ChatOpenAI(
    model="gpt-4.1-mini",
    temperature=0
)


# STEP 3: Create the output parser

parser = StrOutputParser()


# STEP 4: Create additional input information

prepare_input = RunnableLambda(
    lambda data: {
        "topic": data["topic"].strip()
    }
)


# STEP 5: Create the main LCEL pipeline

main_chain = (
    prepare_input
    | prompt
    | model
    | parser
)


# STEP 6: Add original input to the final result

final_chain = RunnablePassthrough.assign(
    answer=main_chain
)


# STEP 7: Invoke the pipeline

result = final_chain.invoke({
    "topic": "LangChain Expression Language"
})


# STEP 8: Display the output

print("Original topic:")
print(result["topic"])

print("\nGenerated answer:")
print(result["answer"])
```

### Example output

```text
Original topic:
LangChain Expression Language

Generated answer:

LangChain Expression Language (LCEL) is a way to
connect different components in LangChain to create
AI applications.

It is used to build workflows by connecting prompts,
language models, output parsers, and custom functions.

For example, you can connect a prompt template to
ChatOpenAI and then to an output parser using the
pipe operator.
```

The exact answer will vary because the model generates the response.

### What happens internally?

| Step | Component | Responsibility |
|---|---|---|
| 1 | `RunnableLambda` | Cleans the topic |
| 2 | `ChatPromptTemplate` | Creates the model prompt |
| 3 | `ChatOpenAI` | Generates the response |
| 4 | `StrOutputParser` | Converts the model message into a string |
| 5 | `RunnablePassthrough.assign()` | Preserves the original topic and adds the answer |

The final result is a dictionary containing both the original topic and the generated answer.

## 14. Important differences between Runnable components

This table is useful when deciding which component to use.

| Component | Main purpose | When to use |
|---|---|---|
| `Runnable` | Common execution interface | Foundation for composable components |
| `RunnableSequence` | Sequential execution | When steps depend on previous outputs |
| `RunnableParallel` | Concurrent execution | When tasks are independent |
| `RunnablePassthrough` | Preserve input | When original input is needed later |
| `RunnableLambda` | Wrap Python functions | When custom Python logic is required |
| `RunnableBranch` | Conditional routing | When execution depends on a condition |
| `RunnableAssign` | Add fields to dictionaries | When enriching existing data |
| `RunnableBinding` | Bind arguments to a Runnable | When configuring model invocation arguments |

### A simple way to remember them

- **Sequence:** Do A, then B, then C.
- **Parallel:** Do A, B, and C at the same time.
- **Passthrough:** Keep the original input.
- **Lambda:** Run my Python function.
- **Branch:** Choose a path based on a condition.
- **Assign:** Add more information to the existing dictionary.
- **Binding:** Attach arguments to a Runnable.

## 15. Common mistakes to avoid

### Mistake 1: Passing incompatible input types

For example, a prompt might expect:

```python
{"topic": "Python"}
```

But the previous Runnable might return a string.

The output of each step must match the input expected by the next step.

### Mistake 2: Confusing sequence with parallel

Use `RunnableSequence` for dependent tasks and `RunnableParallel` for independent tasks.

### Mistake 3: Forgetting that parallel branches receive the same input

In:

```python
RunnableParallel(
    first=chain1,
    second=chain2
)
```

Both `chain1` and `chain2` receive the same input.

### Mistake 4: Using RunnableAssign with a non-dictionary

`RunnableAssign` is intended for dictionary inputs.

### Mistake 5: Using RunnableLambda for streaming transformations

`RunnableLambda` is useful for ordinary transformations, but it does not automatically provide incremental streaming of its own output.

For custom streaming transformations, consider `RunnableGenerator`.

### Mistake 6: Assuming every component streams automatically

LCEL pipelines support streaming, but the actual streaming behavior depends on the components in the pipeline. A component that buffers its entire result can prevent incremental output from reaching the final consumer.

### Mistake 7: Mixing Runnable configuration with business input

Use:

```python
chain.invoke(
    {"topic": "Python"},
    config={
        "tags": ["tutorial"]
    }
)
```

The topic is the business input. The tags are execution configuration.

## 16. Quick summary

### LCEL concepts

| Topic | Quick explanation |
|---|---|
| LCEL | LangChain's way of composing Runnables |
| Runnable interface | Standard interface for executing components |
| `invoke()` | Execute one input |
| `ainvoke()` | Execute asynchronously |
| `batch()` | Process multiple inputs |
| `stream()` | Stream output |
| `\|` | Connect Runnables |
| `RunnableSequence` | Execute steps one after another |
| `RunnableParallel` | Execute independent steps concurrently |
| `RunnablePassthrough` | Pass input through unchanged |
| `RunnableLambda` | Convert a Python function into a Runnable |
| `RunnableBranch` | Execute a conditional branch |
| `RunnableAssign` | Add new fields to a dictionary |
| `RunnableBinding` | Wrap a Runnable with bound arguments |
| Runnable configuration | Control execution metadata and behavior |

### Most important code patterns

**1. Sequential pipeline**

```python
chain = runnable1 | runnable2 | runnable3
```

**2. Parallel execution**

```python
chain = RunnableParallel(
    first=runnable1,
    second=runnable2
)
```

**3. Preserve original input**

```python
chain = RunnablePassthrough()
```

**4. Add new fields**

```python
chain = RunnablePassthrough.assign(
    new_field=lambda data: "value"
)
```

**5. Wrap a Python function**

```python
chain = RunnableLambda(my_function)
```

**6. Conditional execution**

```python
chain = RunnableBranch(
    (condition, runnable1),
    runnable2
)
```

**7. Bind model arguments**

```python
bound_model = model.bind(
    stop=["END"]
)
```

**8. Add execution configuration**

```python
result = chain.invoke(
    input_data,
    config={
        "tags": ["production"],
        "metadata": {"source": "api"}
    }
)
```

### Final takeaway

LCEL is the foundation for building modular LangChain applications.

Instead of writing one large Python function that performs everything, you divide your application into small Runnables and connect them.

```text
Prompt
  |
  v
ChatOpenAI
  |
  v
Output Parser
  |
  v
Final Answer
```

As your application becomes more complex, you can add parallel execution, conditional routing, custom functions, and data transformations without abandoning the same Runnable interface.
