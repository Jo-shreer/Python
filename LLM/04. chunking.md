### What is chunking?

Chunking means dividing a document into smaller pieces of content.

For example, imagine a 100-page PDF containing an employee handbook.

Instead of passing the entire 100-page document to an embedding model as one piece of text, we divide it into smaller sections.

For example:

```text
Document: employee_handbook.pdf

Chunk 1:
Introduction and purpose of the handbook.

Chunk 2:
Employee responsibilities.

Chunk 3:
Annual leave policy.

Chunk 4:
Sick leave policy.

Chunk 5:
Working hours and attendance.
```

Each chunk becomes an independent record that can later be sent to an embedding model.

However, we must preserve the information that tells us where each chunk came from.

For example:

- Original document name.
- SharePoint drive ID.
- SharePoint item ID.
- Original S3 location.
- Page number, slide number or worksheet name.
- Document heading.
- Chunk number.
- Chunking method.

This information is called **chunk metadata**.

Without it, we might have the text but lose the context needed to identify its original document and location.

---

## 2. Why format-aware chunking matters

Different file formats represent information differently.

Applying one generic text-splitting method to every file can damage the meaning of the content.

Consider these examples.

### PDF documents

A PDF often contains pages, headings, paragraphs and tables.

A useful approach is to:

- Preserve page numbers.
- Keep related paragraphs together.
- Avoid splitting sentences unnecessarily.
- Preserve table content where possible.
- Split unusually long pages into smaller sections.

Example:

```text
employee_handbook.pdf

Page 1:
Introduction
Purpose of the handbook...

Page 2:
Employee responsibilities
Employees are expected to...

Page 3:
Annual leave
Employees are entitled to...
```

The chunk metadata should retain the page numbers covered by each chunk.

### Word documents

A Word document commonly contains:

- Headings.
- Subheadings.
- Paragraphs.
- Tables.
- Lists.

A useful approach is to use headings as semantic boundaries.

Example:

```text
Company Policy.docx

Heading 1: Employee Benefits

Heading 2: Health Insurance
Paragraph: Employees are eligible...

Heading 2: Pension
Paragraph: The company contributes...
```

The heading should be included in the chunk text or metadata.

Otherwise, a paragraph about pension contributions might lose the context that it belongs to the Employee Benefits section.

### Excel workbooks

Excel requires a different approach.

An Excel workbook can contain multiple worksheets, column headings and thousands of rows.

Consider:

| Employee ID | Department | Salary |
|---|---|---:|
| E001 | Finance | 45000 |
| E002 | IT | 52000 |
| E003 | HR | 48000 |

We should not simply extract all the cell values and concatenate them.

Instead, we should preserve:

- Worksheet name.
- Column headers.
- Row values.
- Row numbers, where available.

For example, a chunk could contain:

```text
Worksheet: Employees

Columns:
Employee ID | Department | Salary

Records:
E001 | Finance | 45000
E002 | IT | 52000
E003 | HR | 48000
```

The column headers are repeated in each chunk so that the records remain understandable independently.

### CSV files

CSV files are similar to Excel worksheets, but usually contain one table.

We should:

- Preserve the CSV headers.
- Group related rows together.
- Repeat headers in each chunk.
- Retain row numbers or record positions.

### PowerPoint presentations

PowerPoint presentations are organised into slides.

A useful approach is to:

- Preserve slide numbers.
- Preserve slide titles.
- Keep related text from the same slide together.
- Avoid combining unrelated slide content.
- Split a particularly large slide into smaller pieces.

Example:

```text
Presentation: Sales_Strategy.pptx

Slide 1: Business Overview
Slide 2: Market Analysis
Slide 3: Revenue Forecast
Slide 4: Sales Strategy
```

The slide number and title should be retained as chunk metadata.

## 3. The normalised document structure expected by our chunker

Our previous normalisation stage produced a common document structure.

For this chunking implementation, we will use the following structure:

```json
{
    "document_id": "file-001",
    "source": {
        "system": "sharepoint",
        "drive_id": "drive-123",
        "item_id": "file-001"
    },
    "file": {
        "name": "employee_handbook.pdf",
        "extension": "pdf",
        "mime_type": "application/pdf",
        "size_bytes": 250000
    },
    "storage": {
        "bucket": "company-documents",
        "key": "documents/sharepoint/drive-123/file-001"
    },
    "content": {
        "text": "Full extracted document text",
        "sections": [
            {
                "type": "pdf_page",
                "page_number": 1,
                "text": "Introduction and purpose of the handbook."
            },
            {
                "type": "pdf_page",
                "page_number": 2,
                "text": "Employee responsibilities..."
            }
        ]
    },
    "metadata": {},
    "processing": {
        "status": "extracted",
        "extraction_method": "pypdf",
        "content_characters": 12000,
        "section_count": 2
    }
}
```

The important part is:

```python
document["content"]["sections"]
```

This is where we expect the format-specific sections to be stored.

For this lesson, we will use section types such as:

| File format | Section type | Important fields |
|---|---|---|
| PDF | `pdf_page` | `page_number`, `text` |
| Word | `docx_heading`, `docx_paragraph`, `docx_table` | `heading`, `level`, `text` |
| Excel | `xlsx_rows` | `sheet_name`, `headers`, `rows` |
| CSV | `csv_rows` | `headers`, `rows` |
| PowerPoint | `pptx_slide` | `slide_number`, `title`, `text` |
| General text | `text` | `text` |

**Important:** The normaliser must actually produce these fields for the chunker to use them. If your current normaliser stores only one large `content.text` value, it will need to be updated to preserve page, heading, worksheet, row and slide boundaries. The chunker below also has a fallback for documents containing only `content.text`, but that fallback cannot recover structure that was discarded during extraction.

## 4. Choosing chunk sizes

A chunk should be large enough to preserve meaning but small enough to be processed efficiently.

For example:

```text
MAX_CHARS = 6000
OVERLAP_CHARS = 500
```

These are character limits, not exact token limits.

As a rough planning estimate, 6,000 characters might represent around 1,500 tokens, but the actual token count depends on the language, content and tokenizer.

Why use a maximum size?

Because documents can contain very long sections. A single section might contain 20,000 characters, which would be too large for our chosen chunk size.

Why use overlap?

Imagine one chunk ends with:

```text
The company provides employees with 25 days of annual
```

And the next chunk starts with:

```text
leave, excluding public holidays.
```

The second chunk does not contain the complete sentence.

A small overlap can preserve some of the preceding context.

For ordinary prose, we can use an overlap of approximately 500 characters.

For tables, we should generally repeat the table headers rather than blindly copying the end of the previous chunk.

The values are configurable. The correct production settings should eventually be tested against the embedding model and the documents being processed.

## 5. How our chunking implementation will work

We will create a Python program called:

```text
document_chunker.py
```

It will perform these steps:

1. Download a normalised JSON document from S3 to a temporary local file.
2. Read the document metadata and its extracted sections.
3. Identify the file format.
4. Convert each format-specific section into meaningful content units.
5. Group related units together without exceeding the configured chunk size.
6. Split oversized content using paragraph and sentence boundaries where possible.
7. Preserve document, page, heading, worksheet, row and slide information.
8. Generate a stable identifier for each chunk.
9. Write each chunk as an individual JSON record in a JSONL file.
10. Upload the JSONL file to a separate S3 prefix.

We use JSONL because each line is an independent JSON record.

For example:

```text
{"chunk_id":"...","text":"...","metadata":{...}}
{"chunk_id":"...","text":"...","metadata":{...}}
{"chunk_id":"...","text":"...","metadata":{...}}
```

This is useful for downstream processing because we can read and process one chunk record at a time.

import boto3
import json
import hashlib
import re
import tempfile

from pathlib import Path
from typing import Iterator

# 1. CONFIGURATION
# ============================================================

S3_BUCKET = "company-documents"

# Location of normalised JSON documents
NORMALISED_PREFIX = "processed/sharepoint/"

# Location where chunked JSONL documents will be stored
CHUNKED_PREFIX = "processed/chunks/sharepoint/"

# Maximum size of a chunk, measured in characters
MAX_CHARS = 6000

# Overlap between consecutive prose chunks
OVERLAP_CHARS = 500

# Example input document
INPUT_NORMALISED_KEY = (
    "processed/sharepoint/drive-123/file-001.json"
)


# ============================================================
# 2. INITIALISE S3 CLIENT
# ============================================================

s3_client = boto3.client("s3")

# 3. DOWNLOAD NORMALISED DOCUMENT FROM S3
# ============================================================

def download_normalised_document(bucket, s3_key, local_path):

    s3_client.download_file(
        Bucket=bucket,
        Key=s3_key,
        Filename=str(local_path)
    )

    print(f"Downloaded normalised document: {s3_key}")

# 4. LOAD NORMALISED DOCUMENT
# ============================================================

def load_normalised_document(local_path):

    with open(local_path, "r", encoding="utf-8") as file:

        document = json.load(file)

    required_fields = [
        "document_id",
        "source",
        "file",
        "content"
    ]

    for field in required_fields:

        if field not in document:

            raise ValueError(
                f"Missing required document field: {field}"
            )

    if not isinstance(document["content"], dict):

        raise ValueError(
            "Document content must be a dictionary"
        )

    return document


# ============================================================
# 5. TEXT SPLITTING
# ============================================================

def split_long_text(text, max_chars):

    """
    Split long text while attempting to preserve:

    1. Paragraph boundaries
    2. Sentence boundaries
    3. Word boundaries

    A hard character split is used only when necessary.
    """

    if not text:

        return []

    if len(text) <= max_chars:

        return [text]

    paragraphs = re.split(r"\n\s*\n", text)

    pieces = []
    current = ""

    for paragraph in paragraphs:

        paragraph = paragraph.strip()

        if not paragraph:

            continue

        # A single paragraph may itself be too large.
        if len(paragraph) > max_chars:

            if current:

                pieces.append(current)
                current = ""

            sentences = re.split(
                r"(?<=[.!?])\s+",
                paragraph
            )

            sentence_buffer = ""

            for sentence in sentences:

                if len(sentence) > max_chars:

                    if sentence_buffer:

                        pieces.append(sentence_buffer)
                        sentence_buffer = ""

                    # Last resort: split an unusually long
                    # sentence at word boundaries.
                    words = sentence.split()
                    word_buffer = ""

                    for word in words:

                        candidate = (
                            word_buffer + " " + word
                        ).strip()

                        if len(candidate) > max_chars:

                            if word_buffer:

                                pieces.append(word_buffer)

                            word_buffer = word

                        else:

                            word_buffer = candidate

                    if word_buffer:

                        pieces.append(word_buffer)

                    continue

                candidate = (
                    sentence_buffer + " " + sentence
                ).strip()

                if len(candidate) > max_chars:

                    if sentence_buffer:

                        pieces.append(sentence_buffer)

                    sentence_buffer = sentence

                else:

                    sentence_buffer = candidate

            if sentence_buffer:

                pieces.append(sentence_buffer)

            continue

        candidate = (
            current + "\n\n" + paragraph
        ).strip()

        if len(candidate) > max_chars:

            if current:

                pieces.append(current)

            current = paragraph

        else:

            current = candidate

    if current:

        pieces.append(current)

    return pieces


# ============================================================
# 6. CONVERT FORMAT-SPECIFIC SECTIONS INTO CONTENT UNITS
# ============================================================

def iter_content_units(document):

    """
    Convert the normalised document into a sequence of
    smaller, format-aware content units.

    Each unit contains:

    - text
    - section type
    - grouping information
    - source location information
    """

    sections = document.get("content", {}).get("sections", [])

    file_extension = (
        document.get("file", {})
        .get("extension", "")
        .lower()
        .lstrip(".")
    )

    current_heading = None
    current_heading_level = None

    if not sections:

        full_text = document.get(
            "content", {}
        ).get("text", "")

        if not full_text:

            raise ValueError(
                "No sections or extracted text found"
            )

        for part_number, text_part in enumerate(
            split_long_text(full_text, MAX_CHARS),
            start=1
        ):

            yield {
                "text": text_part,
                "section_type": "generic_text",
                "group_key": "generic",
                "context": {
                    "part_number": part_number
                }
            }

        return

    for section_index, section in enumerate(sections):

        section_type = section.get(
            "type",
            "text"
        ).lower()

        # ----------------------------------------------------
        # PDF
        # ----------------------------------------------------

        if section_type in {
            "pdf_page",
            "page"
        }:

            page_number = section.get(
                "page_number",
                section_index + 1
            )

            text = section.get("text", "")

            for part_number, part in enumerate(
                split_long_text(text, MAX_CHARS),
                start=1
            ):

                yield {
                    "text": part,
                    "section_type": "pdf_page",
                    "group_key": "pdf",
                    "context": {
                        "page_number": page_number,
                        "part_number": part_number
                    }
                }

        # ----------------------------------------------------
        # WORD DOCUMENT
        # ----------------------------------------------------

        elif section_type in {
            "docx_heading",
            "heading"
        }:

            current_heading = section.get(
                "heading",
                section.get("text", "")
            )

            current_heading_level = section.get(
                "level"
            )

            # Preserve the heading as its own content unit.
            if current_heading:

                yield {
                    "text": current_heading,
                    "section_type": "docx_heading",
                    "group_key": "docx",
                    "context": {
                        "heading": current_heading,
                        "heading_level": current_heading_level
                    }
                }

        elif section_type in {
            "docx_paragraph",
            "paragraph"
        }:

            text = section.get("text", "")

            for part_number, part in enumerate(
                split_long_text(text, MAX_CHARS),
                start=1
            ):

                yield {
                    "text": part,
                    "section_type": "docx_paragraph",
                    "group_key": (
                        "docx",
                        current_heading
                    ),
                    "context": {
                        "heading": current_heading,
                        "heading_level": current_heading_level,
                        "part_number": part_number
                    }
                }

        elif section_type in {
            "docx_table",
            "table"
        }:

            table_text = section.get("text", "")

            if table_text:

                yield {
                    "text": table_text,
                    "section_type": "docx_table",
                    "group_key": (
                        "docx_table",
                        current_heading
                    ),
                    "context": {
                        "heading": current_heading
                    }
                }

        # ----------------------------------------------------
        # EXCEL WORKBOOK
        # ----------------------------------------------------

        elif section_type in {
            "xlsx_rows",
            "excel_rows"
        }:

            sheet_name = section.get(
                "sheet_name",
                "Unknown worksheet"
            )

            headers = section.get(
                "headers",
                []
            )

            rows = section.get(
                "rows",
                []
            )

            header_text = " | ".join(
                str(value) if value is not None else ""
                for value in headers
            )

            for row_index, row in enumerate(
                rows,
                start=1
            ):

                values = [
                    str(value) if value is not None else ""
                    for value in row
                ]

                row_text = " | ".join(values)

                text = (
                    f"Worksheet: {sheet_name}\n"
                    f"Columns: {header_text}\n"
                    f"Record: {row_text}"
                )

                yield {
                    "text": text,
                    "section_type": "xlsx_rows",
                    "group_key": (
                        "xlsx",
                        sheet_name
                    ),
                    "context": {
                        "sheet_name": sheet_name,
                        "headers": headers,
                        "row_number": row_index
                    }
                }

        # ----------------------------------------------------
        # CSV
        # ----------------------------------------------------

        elif section_type in {
            "csv_rows",
            "csv"
        }:

            headers = section.get(
                "headers",
                []
            )

            rows = section.get(
                "rows",
                []
            )

            header_text = " | ".join(
                str(value) if value is not None else ""
                for value in headers
            )

            for row_index, row in enumerate(
                rows,
                start=1
            ):

                values = [
                    str(value) if value is not None else ""
                    for value in row
                ]

                row_text = " | ".join(values)

                text = (
                    f"CSV columns: {header_text}\n"
                    f"Record: {row_text}"
                )

                yield {
                    "text": text,
                    "section_type": "csv_rows",
                    "group_key": "csv",
                    "context": {
                        "headers": headers,
                        "row_number": row_index
                    }
                }

        # ----------------------------------------------------
        # POWERPOINT
        # ----------------------------------------------------

        elif section_type in {
            "pptx_slide",
            "slide"
        }:

            slide_number = section.get(
                "slide_number",
                section_index + 1
            )

            slide_title = section.get(
                "title",
                ""
            )

            text = section.get("text", "")

            combined_text = (
                f"Slide title: {slide_title}\n"
                f"{text}"
            ).strip()

            for part_number, part in enumerate(
                split_long_text(
                    combined_text,
                    MAX_CHARS
                ),
                start=1
            ):

                yield {
                    "text": part,
                    "section_type": "pptx_slide",
                    "group_key": "pptx",
                    "context": {
                        "slide_number": slide_number,
                        "slide_title": slide_title,
                        "part_number": part_number
                    }
                }

        # ----------------------------------------------------
        # GENERAL TEXT / MARKDOWN / OTHER EXTRACTED SECTIONS
        # ----------------------------------------------------

        else:

            text = section.get("text", "")

            for part_number, part in enumerate(
                split_long_text(text, MAX_CHARS),
                start=1
            ):

                yield {
                    "text": part,
                    "section_type": section_type,
                    "group_key": (
                        "general",
                        section_type
                    ),
                    "context": {
                        "section_index": section_index,
                        "part_number": part_number
                    }
                }

# 7. CREATE CHUNKS FROM CONTENT UNITS
# ============================================================

def create_chunks(document):

    """
    Group related content units into chunks.

    The algorithm:

    - Keeps related units together.
    - Avoids mixing unrelated worksheets.
    - Keeps PDF and PowerPoint source locations.
    - Preserves Word headings.
    - Repeats table headers through each row unit.
    - Applies overlap to prose, not structured tables.
    """

    document_id = document["document_id"]

    source = document.get("source", {})

    file_info = document.get("file", {})

    storage = document.get("storage", {})

    units = iter_content_units(document)

    current_units = []

    current_size = 0

    current_group = None

    previous_text = ""

    chunk_number = 0

    def build_chunk(units_to_pack, number):

        texts = [
            unit["text"]
            for unit in units_to_pack
            if unit["text"]
        ]

        combined_text = "\n\n".join(texts)

        section_types = sorted({
            unit["section_type"]
            for unit in units_to_pack
        })

        pages = sorted({
            unit["context"]["page_number"]
            for unit in units_to_pack
            if "page_number" in unit["context"]
        })

        slides = sorted({
            unit["context"]["slide_number"]
            for unit in units_to_pack
            if "slide_number" in unit["context"]
        })

        row_numbers = [
            unit["context"]["row_number"]
            for unit in units_to_pack
            if "row_number" in unit["context"]
        ]

        sheet_names = sorted({
            unit["context"]["sheet_name"]
            for unit in units_to_pack
            if "sheet_name" in unit["context"]
        })

        headings = list(dict.fromkeys(
            unit["context"]["heading"]
            for unit in units_to_pack
            if unit["context"].get("heading")
        ))

        slide_titles = list(dict.fromkeys(
            unit["context"]["slide_title"]
            for unit in units_to_pack
            if unit["context"].get("slide_title")
        ))

        context = {}

        if pages:
            context["page_numbers"] = pages

        if slides:
            context["slide_numbers"] = slides

        if slide_titles:
            context["slide_titles"] = slide_titles

        if headings:
            context["headings"] = headings

        if sheet_names:
            context["sheet_names"] = sheet_names

        if row_numbers:
            context["row_start"] = min(row_numbers)
            context["row_end"] = max(row_numbers)

        # Generate a repeatable identifier from the document,
        # chunk position and chunk content.
        content_hash = hashlib.sha256(
            combined_text.encode("utf-8")
        ).hexdigest()

        chunk_identity = (
            f"{document_id}:"
            f"{number}:"
            f"{content_hash}"
        )

        chunk_id = hashlib.sha256(
            chunk_identity.encode("utf-8")
        ).hexdigest()

        chunk = {
            "chunk_id": chunk_id,
            "document_id": document_id,
            "chunk_number": number,
            "text": combined_text,
            "metadata": {
                "source": source,
                "file": file_info,
                "original_storage": storage,
                "section_types": section_types,
                "context": context,
                "character_count": len(combined_text)
            }
        }

        return chunk

    for unit in units:

        unit_text = unit["text"]

        if not unit_text.strip():

            continue

        unit_group = unit["group_key"]

        unit_size = len(unit_text)

        # A new group means a different semantic context,
        # such as a different Excel worksheet.
        if (
            current_units
            and unit_group != current_group
        ):

            chunk_number += 1

            yield build_chunk(
                current_units,
                chunk_number
            )

            previous_text = "\n\n".join(
                item["text"]
                for item in current_units
            )

            current_units = []
            current_size = 0

        current_group = unit_group

        # If a unit is too large, split it before packing.
        if unit_size > MAX_CHARS:

            if current_units:

                chunk_number += 1

                yield build_chunk(
                    current_units,
                    chunk_number
                )

                previous_text = "\n\n".join(
                    item["text"]
                    for item in current_units
                )

                current_units = []
                current_size = 0

            split_parts = split_long_text(
                unit_text,
                MAX_CHARS
            )

            for part_number, part in enumerate(
                split_parts
            ):

                split_unit = dict(unit)

                split_unit["text"] = part

                split_unit["context"] = {
                    **unit["context"],
                    "split_part": part_number + 1
                }

                chunk_number += 1

                yield build_chunk(
                    [split_unit],
                    chunk_number
                )

            previous_text = unit_text

            continue

        # If the next unit exceeds the limit, flush the
        # current chunk first.
        if (
            current_units
            and current_size + unit_size > MAX_CHARS
        ):

            chunk_number += 1

            yield build_chunk(
                current_units,
                chunk_number
            )

            previous_text = "\n\n".join(
                item["text"]
                for item in current_units
            )

            # Apply overlap only to prose-based content.
            if not unit["section_type"] in {
                "xlsx_rows",
                "csv_rows",
                "docx_table"
            }:

                overlap = previous_text[-OVERLAP_CHARS:]

                current_units = []

                if overlap:

                    overlap_unit = {
                        "text": overlap,
                        "section_type": "overlap_context",
                        "group_key": unit_group,
                        "context": {
                            "overlap": True
                        }
                    }

                    current_units.append(overlap_unit)

                    current_size = len(overlap)

                else:

                    current_size = 0

            else:

                current_units = []
                current_size = 0

        current_units.append(unit)

        current_size += unit_size

    # Write the final chunk.
    if current_units:

        chunk_number += 1

        yield build_chunk(
            current_units,
            chunk_number
        )

# 8. WRITE CHUNKS TO JSONL
# ============================================================

def write_chunks_to_jsonl(document, output_path):

    chunk_count = 0

    with open(
        output_path,
        "w",
        encoding="utf-8"
    ) as output_file:

        for chunk in create_chunks(document):

            output_file.write(
                json.dumps(
                    chunk,
                    ensure_ascii=False
                )
                + "\n"
            )

            chunk_count += 1

            print(
                f"Created chunk {chunk_count}: "
                f"{chunk['chunk_id']}"
            )

    return chunk_count


# ============================================================
# 9. UPLOAD CHUNKS TO S3
# ============================================================

def upload_chunks_to_s3(
    local_path,
    bucket,
    output_key
):

    s3_client.upload_file(
        Filename=str(local_path),
        Bucket=bucket,
        Key=output_key,
        ExtraArgs={
            "ContentType": "application/x-ndjson"
        }
    )

    print(
        f"Uploaded chunks to "
        f"s3://{bucket}/{output_key}"
    )


# ============================================================
# 10. BUILD OUTPUT S3 KEY
# ============================================================

def build_output_key(document):

    source = document.get("source", {})

    drive_id = source.get(
        "drive_id",
        "unknown-drive"
    )

    item_id = source.get(
        "item_id",
        document["document_id"]
    )

    return (
        f"{CHUNKED_PREFIX}"
        f"{drive_id}/"
        f"{item_id}.jsonl"
    )


# ============================================================
# 11. MAIN PIPELINE
# ============================================================

def main():

    with tempfile.TemporaryDirectory() as temp_dir:

        temp_path = Path(temp_dir)

        local_input_path = (
            temp_path / "normalised_document.json"
        )

        local_output_path = (
            temp_path / "document_chunks.jsonl"
        )

        # Step 1: Download normalised JSON from S3.
        download_normalised_document(
            S3_BUCKET,
            INPUT_NORMALISED_KEY,
            local_input_path
        )

        # Step 2: Load normalised document.
        document = load_normalised_document(
            local_input_path
        )

        print(
            "Processing document:",
            document["file"].get("name")
        )

        # Step 3: Create chunks and write JSONL locally.
        chunk_count = write_chunks_to_jsonl(
            document,
            local_output_path
        )

        if chunk_count == 0:

            raise ValueError(
                "No chunks were generated"
            )

        # Step 4: Build the output S3 key.
        output_key = build_output_key(
            document
        )

        # Step 5: Upload JSONL file to S3.
        upload_chunks_to_s3(
            local_output_path,
            S3_BUCKET,
            output_key
        )

        print("--------------------------------")
        print("CHUNKING COMPLETED")
        print("--------------------------------")

        print(
            f"Document: "
            f"{document['file'].get('name')}"
        )

        print(
            f"Total chunks: {chunk_count}"
        )

        print(
            f"Output location: "
            f"s3://{S3_BUCKET}/{output_key}"
        )


# ============================================================
# 12. EXECUTE
# ============================================================

if __name__ == "__main__":

    main()

## 7. Understanding the important functions

### `iter_content_units(document)`

This is the format-aware part of the implementation.

It looks at the section type and handles the content differently.

For example:

```python
if section_type == "pdf_page":
```

This identifies a PDF page.

```python
elif section_type == "xlsx_rows":
```

This identifies structured Excel records.

```python
elif section_type == "pptx_slide":
```

This identifies a PowerPoint slide.

The function uses `yield` rather than building another complete list of content units.

`yield` produces one unit at a time, which allows the chunking process to consume the units incrementally.

### `split_long_text(text, max_chars)`

This function splits oversized text.

It tries to preserve paragraph boundaries first.

If a paragraph is still too large, it attempts sentence boundaries.

If a sentence is exceptionally long, it falls back to word boundaries.

This is better than simply cutting the text at an arbitrary character position.

However, it is still a rule-based splitter. It does not understand the meaning of a sentence or paragraph in the way a human does.

### `create_chunks(document)`

This function groups content units into chunks.

For example, it avoids mixing two different Excel worksheets into the same chunk.

It also carries page numbers, slide numbers, headings and row information into the chunk metadata.

It uses a generator, so the chunks are yielded individually rather than collected into a single large list.

### `build_chunk(...)`

This function creates the final chunk record.

Every chunk contains:

```json
{
    "chunk_id": "generated-id",
    "document_id": "file-001",
    "chunk_number": 1,
    "text": "The actual chunk text",
    "metadata": {
        "source": {},
        "file": {},
        "original_storage": {},
        "section_types": [],
        "context": {},
        "character_count": 5000
    }
}
```

The `chunk_id` is generated using SHA-256.

The ID is repeatable when the document ID, chunk position and chunk content remain unchanged. If the content or chunk ordering changes, the ID can change.

### `write_chunks_to_jsonl(...)`

This function writes one chunk per line.

It does not first build a list containing every chunk.

That is useful because a document may produce hundreds or thousands of chunks.

### `upload_chunks_to_s3(...)`

This uploads the generated JSONL file to Amazon S3.

We use `upload_file()` because the output is written to a local file first.

This avoids building the entire JSONL output as one large Python string.

## 8. Where the files will be stored in S3

We now have three distinct storage locations.

Assume:

```text
Bucket: company-documents

Drive ID: drive-123

Item ID: file-001
```

### Raw documents

The original SharePoint file:

```text
s3://company-documents/documents/sharepoint/drive-123/file-001
```

### Normalised documents

The extracted and standardised document:

```text
s3://company-documents/processed/sharepoint/drive-123/file-001.json
```

### Chunked documents

The format-aware chunk records:

```text
s3://company-documents/processed/chunks/sharepoint/drive-123/file-001.jsonl
```

This separation is useful because we can independently reprocess a document without having to download it again from SharePoint.

For example:

- If the extraction logic changes, regenerate the normalised document.
- If the chunking strategy changes, regenerate the chunks.
- If the embedding model changes, regenerate embeddings from the chunks.
- If the vector database changes, reuse the chunk records.

The original document remains available in the raw S3 location.

## 10. Important enterprise considerations

The implementation above demonstrates the architecture, but there are several points to address before using it for a large enterprise document collection.

### A. Memory management

We have improved memory usage by:

- Downloading the normalised JSON to a temporary file.
- Generating content units with `yield`.
- Generating chunks with `yield`.
- Writing chunks incrementally to JSONL.
- Uploading the output from disk.

However, there is an important limitation:

```python
document = json.load(file)
```

This loads the entire normalised JSON document into memory.

Also, the earlier normalisation implementation stored the full extracted text and section collection in memory.

Therefore, this chunker is incremental when producing chunks, but it is not yet a fully streaming end-to-end pipeline.

For very large documents, the next improvement should be to store normalised sections as JSONL and read them one at a time, rather than storing the entire document as one JSON object.

### B. Preserve permissions

SharePoint permissions do not automatically transfer to S3 or to the chunk records.

If users have different permissions to SharePoint documents, we need an access-control strategy that ensures a user cannot retrieve chunks from documents they are not authorised to access.

### C. Preserve source provenance

Every chunk should be traceable to its original SharePoint item.

This is why we retain:

- `drive_id`
- `item_id`
- Original document name
- Original S3 location
- Page, slide, worksheet or heading context

This becomes especially important when a user needs to trace a retrieved chunk back to the original document.

### D. Reprocessing and versioning

Documents change.

A production connector should track the source document version or ETag and its checksum.

When a document changes, the processing pipeline should identify its existing chunks and replace or supersede them.

Do not rely only on the chunk number to identify a chunk across document versions.

### E. Tables need additional care

The example preserves table rows and repeats headers.

For complex tables, this may not be sufficient.

For example, a table might contain merged cells, multi-level headers, footnotes or relationships between multiple columns.

Those structures may need specialised extraction and serialisation before chunking.

### F. Chunk size must be tested

The `MAX_CHARS` setting is a starting point, not an industry-wide fixed standard.

The eventual chunk size should be tested against:

- The embedding model's token limit.
- The vector database's metadata and record limits.
- The typical length of your documents.
- The quality of retrieval results.
- The cost of embedding and storage.

Character counts are only an approximation of token counts.

### G. Format-specific extraction must be correct

Chunking cannot recover information lost during normalisation.

For example, if the normaliser extracts a Word document as one large text string without headings, the chunker cannot reliably reconstruct the original heading hierarchy.

The extraction and normalisation stages must preserve the structures that the chunker needs.

## 11. What we have achieved

At this point, our pipeline can take a normalised document from S3 and produce a separate collection of structured chunks.

Our output is not just a list of text fragments.

Each chunk has:

- A unique chunk identifier.
- An associated document identifier.
- The original source information.
- The original file information.
- The text content.
- Its source location within the document.
- Its character count.

We have also introduced format-specific processing for PDF, Word, Excel, CSV and PowerPoint.

**The next stage is embedding generation.**

That stage will take each chunk, send its text to an embedding model, receive a numerical vector and associate that vector with the chunk's metadata.

Only after that do we need to decide how to store and index the vectors in a vector database.

The important distinction is:

```text
Normalisation:
Convert different file formats into a common structure.

Chunking:
Divide the normalised content into meaningful pieces.

Embedding:
Convert each chunk's text into a numerical vector.

Vector database:
Store and index the vectors alongside their associated metadata.
```
